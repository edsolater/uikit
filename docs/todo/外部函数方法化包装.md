本文记录一种独立的调用形态转换：把原本以目标值作为第一个参数的外部函数，绑定成包装对象上的方法。它与递归对象路径无关；内部是否使用 JavaScript `Proxy` 尚未裁决。

# 目标调用形态

现有外部函数调用形态：

```ts
derive(x, doSomething)
```

包装后的调用形态：

```ts
wrappedX.derive(doSomething)
```

两种写法应表达同一操作：包装对象保存 `x`，调用方法时自动把 `x` 作为对应外部函数的第一个参数。

```ts
wrappedX.derive(doSomething)
// 等价于
derive(x, doSomething)
```

`derive` 只是示例。包装器不内置具体方法名称，也不决定外部函数接受什么材料。允许包装的值、注册的操作、参数和返回结果均由使用包装器的外部应用定义。

---

# UIKit Source 应用

UIKit 的 `Source<V>` 同时允许裸值和可以按状态方式处理的来源。两类材料需要分别进入对应规则，但业务调用方不应每次重复选择外部函数和传参位置。

外部应用可以声明某项方法如何处理当前被包装值：

```ts
const wrappedX = wrapOperations(x, {
  derive: (source, mapper) => derive(source, mapper),
})

wrappedX.derive(doSomething)
```

若裸值和状态来源需要不同处理，则分派规则属于 UIKit Source 应用，不属于通用包装器：

```ts
derive: (source, mapper) =>
  isStateViewable(source)
    ? deriveStateViewable(source, mapper)
    : deriveValue(source, mapper)
```

# 与递归路径代理的边界

这个需求不要求支持以下调用：

```ts
wrappedX.sub.children
```

它只要求把：

```ts
operation(x, input)
```

变成：

```ts
wrappedX.operation(input)
```

包装对象可以由普通对象、class、闭包或 JavaScript `Proxy` 实现。是否采用 Proxy 是实现选择，不能据此把该需求归入递归路径代理。

# 待裁决

- 这个包装对象和创建入口叫什么；`OperationAdapter`、`BoundOperations`、`MethodAdapter` 均只是候选。
- 外部操作使用对象表、插件、类型参数还是其他方式声明。
- 操作返回值是否保持原样，还是在满足某些条件时再次包装以支持链式调用。
- 裸值和 `StateViewable` 的识别、分派与错误边界。
- 包装对象是否需要公开原始值，以及如何避免公开字段与方法名称冲突。
- 是否使用 JavaScript `Proxy`；当前需求既不要求使用，也不排除使用。
