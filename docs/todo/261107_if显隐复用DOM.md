# 目标：显隐改变接入关系，保留对象身份

不再把“代理追踪不断更换的 DOM”作为目标；此前提出的对象／成员 State 更新方案已退出。本篇要实现的是让 `if` 的显隐复用原 DOM：

```ts
const el = 首次实际创建的元素

条件为 true  → 将 el 接入 document
条件为 false → 将 el 脱离 document，但 el 对象仍然存在
条件再为 true → 将同一个 el 接回原定位置

再次接入的元素 === el // true，而不是新建一个外形相同的元素。
```

这样，持有首次元素的代码不必为了 `if` 显隐持续更换引用。这里固定的是对象身份，不是承诺元素永远连接在文档中，也不是承诺脱离文档后所有 DOM 操作仍然有效。

其他插件或浏览器改变元素属性、移动元素位置，只要仍是同一个对象，就不属于目标替换；不因此增加对整个 DOM 的全面监控。

# 后续需要核实的边界

- 首次条件为 false 时何时创建元素，仍需结合当前延迟创建语义决定，不能预先要求所有隐藏节点立即创建。
- 脱离与接回怎样保留位置、子树及响应式更新；子内容是否需要持续运行，须按其真实职责判断。
- 隐藏、重新接入与最终退出各自触发哪些绑定、监听和清理。保留 DOM 对象不等于所有资源永生，也不等于永久跳过作用域清理。
- DOM 获取与操作就绪的时机继续由 [Task／TaskResult 异步操作](261107_Task与TaskResult异步操作.md) 单独记录，不把本篇的对象复用当成该问题已经解决。
