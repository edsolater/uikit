# 原问题：相同工厂仍会创建不同元素

原 [Dode](../../src/components/Piv/Dode.tsx) 缓存首次选定的元素工厂，每次进入 `Show` 分支时重新创建元素和绑定。相同工厂不代表相同 DOM；而 [domProxy](../../src/components/plugins/tools/createInactivePlugin.ts) 保存首次节点 Promise，不能因此自动改指向新元素。

此前提出的对象／成员 State 更新方案已退出。本篇解决元素本身的稳定身份，不尝试监控浏览器或其他插件的一切 DOM 改动。

# 当前行为：显隐只改变文档接入关系

```ts
首次 if 为 false → 不创建元素、不执行 domRef、不创建 children
首次 if 为 true  → 创建并绑定 el
之后 if 为 false → el 脱离 document，仍保留原对象和绑定
再次 if 为 true  → 将同一个 el 接回原位置
父作用域退出    → 释放字段、事件、domRef 与 children 资源
```

隐藏期间 Source 继续更新脱离文档的元素，重新显示不重建子组件或重置用户输入。首次元素类型保持固定，未变化的 domRef 不重复接入。

Dode 将首次初始化归入调用它的存活作用域，之后直接向原生渲染器输出该元素或空值，不再使用 `Show`。渲染器统一负责移除、接回与父列表重排；沿用其占位与提交机制，没有额外 Element，不增加 flex/grid 布局项，也不另建位置同步或暂停管理器。

这里固定的是对象身份，不承诺元素永远连接在文档中；焦点等浏览器状态在脱离文档后是否保留，仍由浏览器决定。

# 职责边界

移除宿主也会移除其后代；`createPivStructure` 在宿主外插入的兄弟节点或 wrapper，由其原有结构作用域管理，不因为宿主的 `if` 自动成为同一个条件范围。本轮不增加跨节点范围登记、遍历或同步设施。

其他插件或浏览器改变元素属性、移动元素位置，不因此增加全面 DOM 监控。DOM 异步获取和操作取消的时序，继续由 [Task／TaskResult](../../../fnkit/docs/plans/261108_Task与Result执行.md) 的职责处理，不由对象复用替代。
