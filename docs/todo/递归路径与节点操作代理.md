本文记录一种尚未命名的通用代理结构。它同时支持沿对象属性递归进入子节点，以及在任意节点调用预先声明的操作。本文只确定需求，不确定公开名称和实现方案。

# 目标调用形态

假设 `x` 是这种结构产生的代理，则根节点和任意子节点始终是同一种代理：

```ts
x
x.sub
x.sub.children
```

属性访问有两种解释：

- 若属性名属于当前应用声明的操作，则在当前节点调用对应操作。
- 若属性名不属于已声明操作，则把属性名作为下一层对象路径，并返回新的同类代理。

```ts
x.operation(input)
x.sub.operation(input)
x.sub.children.operation(input)
```

代理结构不内置 `map`、`read`、`set`、`value` 等具体操作。操作名称、参数、返回结果和实际执行函数均由使用该结构的外部应用声明。

---

# 结构边界

这个需求负责：

- 让普通属性读取递归进入子节点。
- 让每个节点公开同一组外部声明的操作。
- 区分“节点操作名称”和“业务对象属性名称”。
- 保持根节点和子节点的调用形态一致。

这个需求不负责：

- 定义 UIKit 的 `Source`、`State` 或 `StateView` 语义。
- 定义 Promise 的等待、完成或失败语义。
- 把独立的函数方法化包装限定为路径树的一部分。节点操作可以复用该包装能力，也可以由递归代理自己建立；两项需求互不依赖。

“三维树”目前只是帮助讨论的临时说法。更准确的图景是一棵对象路径树，每个路径节点同时拥有一组可调用操作。

---

# 待裁决

- 公开对象和创建函数叫什么；`ObjectProxy`、`PathProxy`、`RecursiveProxy` 均只是候选。
- 代理节点保存当前值、根对象与路径，还是外部提供的节点描述。
- 已声明操作与业务对象同名属性发生冲突时，在哪个阶段报错。
- symbol、数组、函数调用、getter、循环引用和原型属性如何进入递归路径。
- 操作结果是否自动返回同类代理，还是完全服从外部操作的返回类型。
- 是否直接使用 JavaScript `Proxy`，以及是否存在不使用 `Proxy` 仍能满足契约的实现。
