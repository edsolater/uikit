# 样式文件写法

.style.ts 描述组件自己的选择条件与差异，通用材料和 Mixin 来自 Style System。定义放在首次使用前，不集中堆在文件开头。

## 先定义，再立即使用

```ts
const buttonSurfaceColor = variableFrom(surfaceColor, {
  name: 'button-surface-color',
  states: {
    active: source => colorMix([source, 0.48], neutralColor(2)),
  },
})

rules(button, [
  color({ background: buttonSurfaceColor }),
])
```

variable(source, { name, states }) 创建 Variable；variableFrom(source, { name, states }) 接上已有 Variable 的引用链。states 可省略，回调收到首参数本身。Variable 是黑盒，直接使用 source，不读取内部状态。

Value 只包装稳定内容，不接受 hover、active 等状态。需要状态的颜色、数值、尺寸均由 Variable 定义承担。

## 选择同组材料

```ts
color({
  background: accentColor('soft'),
  foreground: accentColor('strong'),
})
```

Cluster 通过对象配置声明 default、soft、strong 等成员。直接使用 Cluster 代表 default，调用返回对应成员 Variable。成员自己的状态继续有效，不另设 softAccent、strongAccent 等平行入口。

基础色阶可以使用 neutralColor(2)。数字不是所有 Cluster 的统一参数模型；成员名由材料的实际含义决定。

## 声明目标用对象

```ts
rules(button, [
  [$alignSelf, 'center'],
  [surfaceColor, buttonSurfaceColor],
  contentLayout({ mode: 'center', gap: normalSpace }),
])
```

直接声明使用 [Key, 内容] 或 [Variable, 内容]；规则可以组合 Mixin 返回值、数组及其他对象 Iterable。rules 不接受普通声明对象、裸字符串属性目标或字符串声明序列。

Mixin 的配置对象仍然保留。例如 color({ background: material }) 由 color 解释，不能与 rules(button, { background: material }) 混淆。Key 对象直接携带 CSS 属性名，不需要先注册字符串再查找。

声明只交给浏览器解释，不修改 Variable 对象。undefined 内容不登记，重复声明和书写顺序保持，浏览器决定原生级联。

## 材料和效果放在哪里

整个 Style System 是抽象层。通用定义按描述目标与领域判断，不按消费者数量判断。surfaceColor 可以被很多组件使用；buttonSurfaceColor 只描述 Button，就留在 Button.style.ts。

组件选择器及 variant、tone、size、status 协议由组件拥有。Mixin 拥有效果到 CSS Key 的映射；Theme 材料拥有通用配方和状态。必要的定义重复可以保留，不为减少重复增加调用者必须理解的新分类。

focusVisible 是 State Condition。现有 clickable 消费通用焦点材料，组件通过 focusColor 声明颜色差异，不协调线宽、线型、偏移或另写焦点规则。

## 命名与顺序

Variable 名字的最后一个单词说明存在形式：Color、Size、Width、Duration、Shadow 等。前面的词说明用途。例如 buttonSurfaceColor、focusStrokeWidth。

所有定义都在首次使用前，随后复用。通用定义也不例外；真正属于抽象层的内容放回其负责模块，在那个模块内遵循同一阅读顺序。

## 登记与挂载

组件静态导入自己的 .style.ts。模块顶层 rules 登记配置；应用在所有静态样式导入后、render 前调用 cssRoot.mount()。组件渲染不触发编译。compileCSS() 仅返回字符串。

rule 的句柄可替换或删除自己的条目，rules 的句柄删除本批条目；需要刷新时由应用再次挂载。测试结束清理自身句柄。

## 修改后检查

检查完整样式文件：选择条件是否清楚、定义是否紧邻消费、通用状态是否仍由定义端拥有。类型测试拒绝旧声明入口；浏览器测试覆盖组件各配方、状态及其交集。不能只凭文件变短或测试通过判断归属正确。
