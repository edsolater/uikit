# 样式文件写法

.style.ts 描述组件自己的选择条件与差异，可复用 Pieces 和 Mixin 来自 Style System。定义放在首次使用前，不集中堆在文件开头。

内容表达采用 [Token 设计](../../src/style-system/doc/Token设计.md) 的目标模型。源码已完成迁移，下文 token() 使用现役接口，核心行为已通过单元和真实浏览器验证。

## 文件边界

组件的基础外观、状态、伪元素与定位框等配套显示，都写在自己的 .style.ts，通过 Style System 登记。不能另写组件 .css，也不能在 .style.ts 中注入整段 CSS 绕过登记。

.css 只用于 App 背景、reset 等根级样式。职责由选择器服务的对象决定，不由文件所在目录决定；历史组件 CSS 不是新增或继续扩写的例外。

## 先定义，再立即使用

```ts
const button = ['@layer uikit', '.Button']
const buttonContentColor = token(globalContentColor, {
  name: 'button-content-color',
  address: button,
})
rules(button, [
  color({ content: buttonContentColor }),
])
```

globalContentColor 是可坍缩的输入内容。把它放入 token() 自然形成引用，不触发另一套复制定义判断。颜色、尺寸、阴影、计算表达式都使用统一 Token 模型。

有 name、state、address、registration 或被 modify 的 Token 输出 CSS variable，缺名自动生成。没有这些要求的 Token 直接输出 CSS value。内部 _kind 由系统决定，外界不能配置。

## 状态与定义组合

```ts
const feedback = {
  hover: base => multiply(base, 2),
  active: 4,
}
const strength = token(2, { address: button, state: feedback })
```

State 可独立定义，也可直接写进 token({ default, ...state })。state 描述主体条件下的取值，address 决定定义所在位置。直接条件与快捷状态的语义见 [主体状态条件](../../src/style-system/doc/主体状态条件.md)。

新用途由普通函数读取来源的 default、state 等规范化字段并组合，返回新 Token。Token 不内置用途变体；定义加工不需要独立操作。一次颜色变化可以直接组合 oklch、colorMix 等工具，数值变化使用 add、multiply 等表达式。

## 组件决定哪些信息

组件自己的颜色来源、布局、外观分类、状态差异、作用地址与公开控制点都属于组件 .style.ts。共享能力承担可复用的取值、状态条件、计算和效果映射，不替 Button 决定视觉策略。

surface、content、line 等用途分别表达。多个独立目标需要在同一条件改变时，在同一 rules 中并列声明；只改一个就只声明一个。控制点需要公开时导出实际对象，内部参数不因使用 Token 就必须公开。

组件 appearance、tone、size、status 等分类协议由组件拥有。组件分类仍可叫 Variant Props，这与 Token 内置用途变体是不同概念。

## 声明与 modify

```ts
rules(button, [
  [$alignSelf, 'center'],
  declare(surfaceColor, accentColor),
  contentLayout({ mode: 'center', gap: normalSpace }),
])
```

rules 接收 Declaration、声明序列、Mixin 结果及嵌套 Iterable。Mixin 配置由 Mixin 解释，不等于 rules 接受任意样式对象。声明目标使用对象，避免裸字符串别名歧义。

modify 在明确位置或条件修改同一个 Token，使它取得 CSS variable 身份；定义组合由返回新 Token 的普通函数完成。onFirstScan 可以返回新的 modify，坍缩必须等相关修改读取完成，不以第一次引用或某个固定波次作为完成条件。

Token 不携带声明优先级或附带声明列表。address 表达位置，同址顺序交给声明系统，跨地址使用浏览器原生层叠。CSS 引用不会因为后代改变输入，就让祖先计算公式在后代重算。

## 命名与归属

Token 用稳定服务对象命名，例如 surfaceColor、boundaryWidth、motionDuration。转换函数如 lineColor(base) 说明输入与用途；Mixin 直接使用效果名，如 color、contentLayout、clickable。统一名称原则见 [样式系统命名](../../src/style-system/doc/样式系统命名.md)。

Pieces 按领域职责组织，通用定义不按调用者数量判断归属。通用工具不感知 Button 的分类；Button 的具体材料与差异保持在 Button.style.ts。

## 登记与挂载

从独立入口 @edsolater/uikit/style-system 引入样式能力。组件静态导入自己的 .style.ts，模块顶层 rules 登记规则；应用提供 style#css-root，在静态样式导入后、渲染前统一调用 cssRoot.mount()。组件渲染不触发编译，compileCSS() 只返回文本。

根级 reset 与 tokens CSS 由应用显式引入 @edsolater/uikit/css/all-base.css。样式入口 clickable 提供视觉效果，包根同名入口提供组件插件，二者按职责使用。

rule 句柄可替换或删除自己的条目，rules 句柄可删除本批条目；需要刷新时由应用再次挂载。直接改普通 JavaScript 对象不等于页面已更新。

## 修改后检查

检查选择条件是否清楚、定义是否紧邻消费、组件策略是否仍在组件层，以及状态是否在正确地址表达。验证针对可观察行为，包括分类与状态交集、作用域覆盖和实际浏览器输出，不能只凭文件变短或通过静态检查判断设计完成。
