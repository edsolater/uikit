# 样式文件写法

.style.ts 描述组件自己的选择条件与差异，可复用 Pieces 和 Mixin 来自 Style System。定义放在首次使用前，不集中堆在文件开头。

## 先定义，再立即使用

```ts
const surfaceStrength = variable(0.18, {
  name: 'surface-strength',
  states: { hover: 0.28, active: 0.38 },
})

rules(button, [
  surfaceColor.declare(colorMix([toneColor('soft'), surfaceStrength], surfaceColorInteractive)),
  foregroundColor.declare(textColor),
  color({ background: surfaceColor, foreground: foregroundColor }),
])
```

颜色角色使用 ColorVariable：`declare(source)` 只声明基础色，`setLightness(value)` 等方法声明绝对通道，`deltaLightness(value)` 等方法声明独立增量，四通道都按“绝对值（未设置时取基础色通道）＋增量（未设置时为零）”组合。重新声明基础色不会清空这些调整；同一字段的重复设置采用最后有效值，条件退出按 CSS 层叠恢复。无需整色提取、JS 解析或额外颜色转接变量。

`variable(source, { name, states, modification })` 创建 Variable；首参数可以引用另一 Variable，`states` 和 `modification` 可省略。状态内容遇到来源 Variable 时读取其同名状态，缺失则取创建默认内容。需要局部语气覆盖时，把状态变化的参数交给 Variable，颜色来源留在普通组合中，如上例的 `toneColor('soft')`。Mixin 普通消费，编译器展开状态声明，组件不逐状态登记消费 Rule。需要基于前序结果继续变化，用 `declare()` 建立局部基础值，再用 `modify()` 表达相对变化，由 `modification.apply` 收到前序内容。组件不手写 CSS `var()` 或调用 `toCSSString()` 拼接引用，不读取 Variable 内部状态。多成员状态继承由 `clusterFrom(sourceCluster, changes)` 负责。

source 可以是直接 ValueInput，也可以是 `() => ValueInput`。函数 source 在定义时只保存，编译实际消费该 Variable 时才执行；返回的 Variable、Value 或其他 JSSContent 继续按统一内容协议解析。可调用的 Variable Cluster 仍是内容对象，不作为普通 source 函数执行。

Value 只包装内容，不持有 hover、active 等状态。Variable 创建时展开 `states` 中匹配到的快捷名称，未匹配的输入直接作为条件，业务保证条件约束自身。例如 `states: { hover: 1, '&[data-tone="danger"]': 2 }` 可以混用快捷名称和直接条件，编译消费已解析结果。Rules 中的字符串都是普通 CSS 条件，例如 `'&:hover'`；它不会自动使用快捷 hover 的 disabled 抑制或中央顺序。组件分类条件负责选择材料和相对贡献，状态配方由 Variable 持有。

## 选择同组 Atom

```ts
color({
  background: accentColor('soft'),
  foreground: accentColor('strong'),
})
```

Cluster 通过对象配置声明 default、soft、strong 等成员。普通值消费 Cluster 代表 default，调用返回对应成员 Variable；`[toneColor, accentColor]` 这样的双 Cluster 声明按目标同名成员整组赋值，无需在组件中逐成员配对。只声明双方已有的同名成员，未匹配目标保留原有取值，来源额外成员不参与；不深度合并或修改共享对象。成员自己的状态继续有效，不另设 softAccent、strongAccent 等平行入口。

基础色阶可以使用 neutralColor(2)。数字不是所有 Cluster 的统一参数模型；成员名由该组 Atom 的实际含义决定。

## 声明目标用对象

```ts
rules(button, [
  [$alignSelf, 'center'],
  surfaceColor.declare(accentColor),
  contentLayout({ mode: 'center', gap: normalSpace }),
])
```

颜色角色通过 `surfaceColor.declare(source)` 等操作返回 Declaration。rules 接受单个 Declaration、声明序列、Mixin 返回值、数组及其他对象 Iterable；其他 Key／Variable 的二元声明协议仍保留。rules 不接受普通声明对象、裸字符串属性目标或字符串声明序列。

Mixin 的配置对象仍然保留。例如 color({ background: surfaceColor }) 由 color 解释，不能与 rules(button, { background: surfaceColor }) 混淆。JSSKey 对象直接携带 CSS 属性名，不需要先注册字符串再查找。

声明只交给浏览器解释，不修改 Variable 对象。undefined 内容不登记，重复声明和书写顺序保持，浏览器决定原生级联。

## 内容碎片和效果放在哪里

整个 Style System 是抽象层。通用定义按描述目标与领域判断，不按消费者数量判断。surfaceColor 描述组件承载面，组件只选择基础色与调整。functions 中的 CSS 函数构造内容，ColorVariable 负责基础色、通道及增量声明与消费。

组件选择器及 variant、tone、size、status 协议由组件拥有。Mixin 拥有效果到 JSSKey 的映射；通用 Variable 拥有配方和状态。必要的定义重复可以保留，不为减少重复增加调用者必须理解的新分类。

组件样式区分业务规则与公开控制点，这两项职责都属于 `.style.ts`，不要求分成文件。业务规则决定分类、材料和状态怎样组合；公开 Variable 提供可由外界操作的同一内容身份，属于组件自己的契约。Button 的色源、画布和背景强度在 `Button.style.ts` 中以 export 定义，并从组件入口导出；分类贡献保持私有。内部参数不因使用 Variable 就必须公开，未来控制能力也不要求现在增加另一层 Controller。

`variable`、`colorMix`、`calcAdd` 提供创建、混色与计算的通用语义，不决定 Button 的视觉策略。通用 `clickable()` 已提供禁用淡化，Button 不再创建专属 opacity 控制点。业务无需重复建立通用默认策略，也不把组件控制定义搬进底层工具。

焦点由定义端状态能力与通用 Mixin 承担。focusOutline 在 focus 状态下消费 toneColor 的 line 成员，clickable 将轮廓和偏移交给 CSS；Button 用整组声明选择配色，不逐项绑定焦点颜色。Focus 属于 State Condition，优先级低于 hover／active；focus 内置匹配 `:focus-visible`，不与 `:focus` 混同。line 是轮廓颜色用途，不是另一种焦点状态，普通背景和前景不会随它改色。

## 命名与顺序

Variable 名字的最后一个单词说明存在形式：Color、Size、Width、Duration、Shadow 等。前面的词说明用途。例如 surfaceColor、focusStrokeWidth。

所有定义都在首次使用前，随后复用。通用定义也不例外；真正属于抽象层的内容放回其负责模块，在那个模块内遵循同一阅读顺序。

## 登记与挂载

组件静态导入自己的 .style.ts。模块顶层 rules 登记配置；应用在所有静态样式导入后、render 前调用 cssRoot.mount()。组件渲染不触发编译。compileCSS() 仅返回字符串。

rule 的句柄可替换或删除自己的条目，rules 的句柄删除本批条目；需要刷新时由应用再次挂载。测试结束清理自身句柄。

## 修改后检查

检查完整样式文件：选择条件是否清楚、定义是否紧邻消费、通用状态是否仍由定义端拥有。类型测试拒绝旧声明入口；浏览器测试覆盖组件各配方、状态及其交集。不能只凭文件变短或测试通过判断归属正确。
