# 样式文件写法

.style.ts 描述组件自己的选择条件与差异，可复用 Pieces 和 Mixin 来自 Style System。定义放在首次使用前，不集中堆在文件开头。

内容表达采用 [Token 设计](../../src/style-system/doc/Token设计.md) 的目标模型。源码已完成迁移，下文 token() 使用现役接口，核心行为已通过单元和真实浏览器验证。

## 文件边界

组件的基础外观、状态、伪元素与定位框等配套显示，都写在自己的 .style.ts，通过 Style System 登记。不能另写组件 .css，也不能在 .style.ts 中注入整段 CSS 绕过登记。

.css 只用于 App 背景、reset 等根级样式。职责由选择器服务的对象决定，不由文件所在目录决定；历史组件 CSS 不是新增或继续扩写的例外。

## 先定义，再立即使用

```ts
const button = ['@layer uikit', '.Button']
export const buttonContentColor = token(contentColor, {
  name: 'button-content-color',
  address: button,
})
rules(button, [color({ content: buttonContentColor })])
```

第一个参数是基础内容，第二个参数是 name、state、address 等配置。已有 Token 直接传入，继承来源配置并以来源当前值为默认内容；追加 state 软合并组件差异。显式 address 固定定义位置，未指定时，需要 CSS variable 的 Token 在实际 AST 消费地址建立 default 与 state，不必额外注入组件地址。函数仅用于延迟生产或消费时读取数据等明确目的。

有 name、state、address、registration 或被 modify 的 Token 输出 CSS variable，缺名自动生成。没有这些要求的 Token 直接输出 CSS value。内部 _kind 由系统决定，外界不能配置。

## 按对外职责决定外置或内联

公开控制点服务于使用方常见、独立且语义稳定的视觉需求，确定后再独立命名并导出。读取和组合也属于控制，但能读取、结果完整或只消费一次，都不能单独决定是否公开。颜色、尺度与内部空间配方的默认倾向和例外见[样式书写的一些权衡建议](../../src/style-system/doc/样式书写的一些权衡建议.md)。

内部小配方和纯计算可以内联或在计算函数内部命名，不能仅把中间变量搬进 rules，变成更深的嵌套。rules 应直接看出属性消费什么，配方应看出材料和差异。

## 状态与定义组合

```ts
const feedback: TokenStateInput = {
  hover: (base) => multiply(base, 2),
  active: 4,
}
const strength = token(2, { address: button, state: feedback })
```

State 可独立定义，也可直接写入配置的 state。对象、Map、单个条件 entry 及其嵌套数组或 Iterable 可以混合，入口按顺序展开且保留 entry 配对。hover、active 等稳定条件使用现成快捷名；组件临时定义的 whenComponentState = stateCondition(...) 可直接作为条件，无须也不应登记全局简写。快捷名映射只由 Style System 所属 Pieces 条件模块维护，未知字符串立即报错。原始 CSS 通过对象 entry 或 Map 输入，不作对象键字符串化。解析后的 Token.state 统一为 Map，可直接参与新组合；rules 的字符串地址仍表示 CSS，不查状态快捷名表。

提供 State 的辅助函数优先返回对象或条件 entry，不必为了匹配解析结果提前构造 Map。调用方直接组合各份定义：

```ts
const buttonColorSource = buttonToken(brandColor, {
  name: 'button-color-source',
  state: [interactiveColorStates({ chromaResponse: 1 }), { danger: badColor }],
})
```

同条件后值覆盖前值并保留首次位置。已有 Token.state 也可直接参与组合，定义输入与解析结果的区别见[Token 设计](../../src/style-system/doc/Token设计.md#state-可以独立复用)。

组件级 Token.state 优先使用静态预置快捷名，稳定的名称便于直接阅读；没有快捷名时使用 StateCondition 对象。Style System 内部优先引用由 stateCondition 定义的条件变量，集中定义并复用，修改条件时不必逐处改写。这是书写优先级，两种合法输入仍可使用。rules 地址不查状态快捷名表，需要共享状态条件时可直接传 stateConditionRegistry.outlined、stateConditionRegistry.loading 等对象，不能把 'hover' 当作悬停快捷名。

快捷名在参数入口换成静态表中的条件对象，归一后的 state 直接编译。映射不修改选择器权重或添加排序；同时命中的状态按原 CSS 特异度和定义顺序层叠。

共享分类和交互条件直接进入 state，局部条件用 stateCondition(input) 定义；不读取 header，也不手动拼 CSS。hover、active、enabled、disabled 等条件各自匹配，不常规添加排除条件或枚举交集。条件与快捷名的边界见 [主体状态条件](../../src/style-system/doc/主体状态条件.md)。

新用途由普通函数读取来源的 default、state 等规范化字段并组合，返回新 Token。Token 不内置用途变体；定义加工不需要独立操作。一次颜色变化可以直接组合 oklch、colorMix 等工具，数值变化使用 add、multiply 等表达式。

## 组件决定哪些信息

组件自己的颜色来源、布局、外观分类、状态差异、作用地址与公开控制点都属于组件 .style.ts。共享能力承担可复用的取值、状态条件、计算和效果映射，不替 Button 决定视觉策略。

公共 Token 描述样式自身，不按 Button、Dialog 等组件类型选择材料。组件选择阴影档位、布局比例和交互变化；例如 Button 的两向 padding 比例由 Button.style.ts 定义，公共间距材料只提供共享基准与状态。

surface、content、line 等用途分别表达。Token 的基础与条件变化在自身 default、state、address 中定义，rules 只把它接入具体属性。公开控制点的选择取决于它表达什么角色，而不是配方长短或使用次数。

组件 appearance、tone、size、status 等分类协议由组件拥有。组件分类仍可叫 Variant Props，这与 Token 内置用途变体是不同概念。

## 自动声明与 modify

```ts
rules(button, [
  [$alignSelf, 'center'],
  { 'background-color': surfaceColor },
  contentLayout({ mode: 'center', gap: normalSpace }),
])
```

rules 接收对象、单个属性 entry、Mixin 结果及嵌套 Iterable，自动完成属性声明。字符串键使用 CSS 原名，例如 'background-color'；Key 对象用二元组保留身份。Token 的 CSS variable 定义由架构在显式 address 或当前消费地址建立，不写回地址；普通 CSS value 仍直接输出。

手动 declare 和 [existingToken, value] 仍可执行，但属于 dangerous 操作，不做运行时或类型拦截。正常组件不靠它们补默认值、切换状态或覆盖已有 Token；局部独立配置创建新 Token，并在对应属性消费它。

modify 在明确位置或条件修改同一个 Token，使它取得 CSS variable 身份；定义组合由返回新 Token 的普通函数完成。onFirstScan 可以返回新的 modify，坍缩必须等相关修改读取完成，不以第一次引用或某个固定波次作为完成条件。

Token 不携带声明优先级或附带声明列表。显式 address 固定位置，缺省时按消费位置发布；全局材料明确指定 root。同址顺序交给声明系统，跨地址使用浏览器原生层叠，显式固定在祖先的公式不会因后代改变输入而搬到后代重算。

## 命名与归属

Token 名称在同一逻辑链中保留相同抓手，例如 buttonColorSource → buttonSurfaceColor、buttonContentColor、buttonBoundaryColor；业务前缀在前，Source 在最后。公共基础材料使用 baseSpace、baseOpacity、baseRadius、baseShadow 等名称。转换函数如 lineColor(base) 说明输入与用途；Mixin 直接使用效果名，如 color、contentLayout、clickable。统一名称原则见 [样式系统命名](../../src/style-system/doc/样式系统命名.md)。

Pieces 按领域职责组织，通用定义不按调用者数量判断归属。通用工具不感知 Button 的分类；Button 的具体材料与差异保持在 Button.style.ts。

有独立职责的定义分别命名；对外控制点还需 export，使外界可以读取和复用。纯内部计算可以内联，但不以 token(token(...)) 隐藏必要的分阶段关系，也不为拆开表达式增加无职责的中间变量。

## 登记与挂载

从独立入口 @edsolater/uikit/style-system 引入样式能力。组件静态导入自己的 .style.ts，模块顶层 rules 登记规则；应用提供 style#css-root，在静态样式导入后、渲染前统一调用 cssRoot.mount()。组件渲染不触发编译，compileCSS() 只返回文本。

根级 reset 与 tokens CSS 由应用显式引入 @edsolater/uikit/css/all-base.css。样式入口 clickable 提供视觉效果，包根同名入口提供组件插件，二者按职责使用。

rule 句柄可替换或删除自己的条目，rules 句柄可删除本批条目；需要刷新时由应用再次挂载。直接改普通 JavaScript 对象不等于页面已更新。

## 修改后检查

检查选择条件、控制点与消费关系是否清楚，公开 Token 是否可被外界读取，内联是否反而增加了嵌套和跳转；再核对组件策略与状态地址。验证针对可观察行为，包括分类与状态交集、作用域覆盖和实际浏览器输出，不能只凭文件变短或通过静态检查判断设计完成。
