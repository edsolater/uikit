本文规定 UIKit 组件的 `.style.ts` 怎么写：先让维护者扫读配置，再按需查看组装实现。以 [Button](../../src/components/kits/Button/Button.tsx) 和 [Button.style.ts](../../src/components/kits/Button/Button.style.ts) 为当前实例，不要求本轮迁移其他组件。

通用注释要求见 [代码注释](../../../ai-rules/rules/Code-代码注释.md)，对象能力与激活边界见 [Style System 设计](../../src/style-system/design.md)。本文只承载 UIKit 的样式写法。

# 先读组件定义

修改样式前，先读组件的类型、行为和相邻规格，确认分类与 DOM 输出。不能只看样式文件，也不能按当前颜色或效果重新发明组件分类。规格与实现不一致时，先查明相关事实，不把矛盾带进新的写法。

Button 的对应关系如下；其他组件使用自己的定义，不机械照搬这些选项。

| 组件概念 | 候选或条件 | 样式读取位置 |
| --- | --- | --- |
| variant：动作声量 | bare、solid | data-variant |
| tone：动作语气 | accent、danger | data-tone |
| size：尺寸 | small、large、xlarge | data-size |
| 组件状态 | loading、disabled，可同时成立 | data-status；disabled 同时输出原生属性 |
| 浏览器交互状态 | 悬停、按下、焦点提示 | :hover、:active、:focus-visible |

variant、tone、size 是独立分组，不统称为状态；hover 等浏览器条件也不因此成为组件的 Status Props。分区保留 `variant`、`tone`、`size` 及实际候选名，使读者能直接对应组件定义。中文补充含义，不替换协议名称。

# 内容在前，条件在后

配置名称先回答“这是什么内容”，再说明适用条件。同类内容保持对称：

| 内容 | 基础配置 | 条件配置 |
| --- | --- | --- |
| 外观 | appearance | appearanceWhenHover、appearanceWhenFocus、appearanceWhenBare、appearanceWhenBareAndHover |
| 组件变量取值 | variables | variablesWhenAccent、variablesWhenSmall |

内容词概括一类维护目标，不对应某一个 CSS 属性。appearance 包含边界、圆角、轮廓、颜色、背景和阴影，不再把 shape 作为并列内容类别。

沿用已明确的 baseLayout、baseTransition 等名称，区分基础布局与过渡配置。组合条件用必要的限定表达，例如 appearanceWhenSolidAndActive；不能把对象藏在一长串条件之后。

文件已经说明所属组件，内部配置不重复加 button 等组件前缀，也不添加 Declaration 这类实现后缀。短名不表示跨组件通用：组件专用配置仍留在本文件，共享材料从 Style System 的具体文件导入。

## 与属性名称冲突时

内容词的范围较广，但不能假设永远不与 CSS 属性重名。只有当前文件实际发生重名时，才给配置名加 kit 前缀，属性函数保留原名。例如已导入 appearance 属性函数时：

```ts
/** 默认外观 */
const kitAppearance = [appearance('none'), backgroundColor(bgColor)]
```

同一组配置保持对称，使用 kitAppearance、kitAppearanceWhenHover 等名称。没有冲突时仍用 appearance，不预先给所有配置加 kit。

# 注释是内容简述

节点注释使用 `/** ... */`，给定义处和悬浮提示提供同一份中文说明。先说明负责的内容；只要出现条件值，就必须同时写出它所属的 namespace。组合条件逐项标明，不能依赖分区标题补足。条件 namespace 使用 `variant`、`tone`、`size` 和 `state`，条件值使用代码中的英文名称，例如 `hover`、`active` 和 `focus-visible`；不在括号内另译成中文。读者应能据此决定是否进入代码内部。

```ts
/** 外观（state：hover） */
const appearanceWhenHover = [backgroundColor(bgHoverColor), color(foregroundHoverColor), boxShadow(hoverShadow)]

/** 配色变量（tone：danger） */
const variablesWhenDanger = [
  declareVariable(toneColor, dangerColor),
  declareVariable(toneSoftColor, dangerSoftColor),
]
```

“悬停反馈”只交代场景，不能让读者知道内容是外观还是布局；“切换底色、文字色和阴影”又把实现复述了一遍。这里用“外观（state：hover）”概括内容与条件即可。

优先使用自然的中文短语，够用就停。组件范围已由文件说明，不重复强调 Button；取值、计算和拼装留在黑盒内。只有影响正确使用或维护的约束才补充，例如特定组合的文字色优先级、注册前必须存在的宿主节点。

# 正文配置，末尾组装

前面按主题定义具名配置，末尾才创建 styleRule 并调用 of。hoverStyle 与 kitStyle 都属于组装实现，不放进配置正文；职责注释跟随配置，而不是跟随选择器对象。

```ts
// =============================================================================
// variant 外观
// =============================================================================

// --- variant:bare ---

/** 外观（variant：bare） */
const appearanceWhenBare = [
  backgroundColor('transparent'),
  border(thinDistance, 'solid', 'transparent'),
  boxShadow('none'),
]

// =============================================================================
// 样式组装
// =============================================================================

const bareStyle = styleRule('&[data-variant="bare"]')
bareStyle.of(appearanceWhenBare)

const kitStyle = styleRule('.Button')
kitStyle.of(bareStyle)
```

文件是第 0 层级；内部第 1 层区域使用三行长等号标题，第 2 层主题使用单行短横线标题。第 3 层及以下由具名变量、函数等真实代码块及其注释承载。只在有助定位时分区，不为每个变量加标题，不为凑层级制造函数或 namespace。

标题前后留一行空白，节点注释紧贴代码。展开较长配置便于阅读，但不要求每个数组都换行。具名内容可为单条 Declaration 或嵌套集合，of 接收时无需手动展开；末尾只引用配置，不重新内联一整段内容。过渡条目直接列出，不借 map 或额外包装隐藏配置。

组装顺序决定 CSS 输出顺序。按主题调整正文时，不顺手改变选择器、变量接口、注册链或层叠关系。

---

# 内部配置不等于外部接口

配置、分支与 kitStyle 默认不导出。具名是为了内部阅读和组合，不意味着外部 JS 可以任意修改；只有明确的外部调用需求才开放对应入口。Button 当前只导出 registerButtonStyle。

共享 CSS variable 承担样式定制接口：declareVariable 给当前作用域设定取值，把 variable 传给属性则使用该值。它不要求导出组件内部的声明或规则对象，也不允许重写共享变量的兜底材料。

# 修改后检查

- 遮住配置内部，只读分区、名称和注释：能否找到要改的内容，并分清 variant、tone、size 与状态？
- 同类配置是否内容在前、条件在后，是否重复了文件已经提供的组件身份？
- 配置正文是否混入 styleRule 或 of？末尾是否仍按既有顺序组装？
- 导出是否都有实际使用者，而非为测试或未来设想开放？
- 重命名后检查 TypeScript；调整连接与排列时，对比实际 Root 激活输出并运行受影响的现有验证，不给每个配方机械新增测试。
