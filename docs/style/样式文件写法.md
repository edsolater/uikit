# 样式文件写法

.style.ts 描述组件自己的选择条件与差异，可复用 Pieces 和 Mixin 来自 Style System。定义放在首次使用前，不集中堆在文件开头。

## 先定义，再立即使用

```ts
const surfaceStrength = variable(0.18, {
  name: 'surface-strength', address: button,
  states: { hover: 0.28, active: 0.38 },
})

const buttonSurfaceColor = variable(colorMix([buttonSurfaceSource, surfaceStrength], buttonSurfaceCanvas), {
  name: 'button-surface-color', address: button,
})
const buttonContentColor = variable(textColor, { name: 'button-content-color', address: button })

rules(button, [
  color({ background: buttonSurfaceColor, content: buttonContentColor }),
])
```

颜色角色使用普通 Variable；一次颜色变化直接写 `oklch(source, { lightness: current => add(current, -0.04) })`，未指定通道保留来源，无需创建 Modification。需要独立声明或覆盖的变化配方通过 `modification({ name: '--surface-change', type: 'color', detail: { lightness: 0.3, chroma: current => add(current, 0.3) } })` 独立定义。固定通道表示设为该值，回调表示相对变化，未指定通道保持来源值。内置转译在编译时用 l/c/h/alpha 生成与来源无关的配方；`declare(change)` 声明配方，`modify(surfaceColor, change)` 返回条件修改声明。

`variable(content, { name, address, states })` 创建 Variable。address 是根据地，缺省root；消费时AST只查询这个地址，缺声明才补，已有值保留。states随根据地声明；组件状态模板必须给材料指定组件地址；也可在hover/active条件rules中显式modify表达变化，不在每个消费点投影状态。组合中的Variable保留CSS引用，后代同名输入不使祖先已计算公式重新绑定。

`variableFrom(source, value, nameOrOptions)`复用来源states/variants规则及固定值，不修改来源。未提供新名字或地址时沿用来源；独立用途通常给新名字，需要自身交互时明确组件地址。只改变状态/等级可传source.content再提供options。需要累计变化用modify，无需先写一次无值declare或重传创建内容。

`adjust(source, change)`返回新Variable，沿用来源根据地，保留完整定义，对默认/state/variant/变体state的最终结果统一加工一次。modify返回条件声明，在明确范围加工这些结果，其他范围不变。组件直接消费结果，不拆出所有变体重新导出，不手工拼接var()。多个独立目标同条件选新值仍使用并列declare(target, newValue)。

两处参数都有独立简写：`variable(0.18, 'surface-strength')` 把字符串作为名称；`variable({ default: 0.18, hover: 0.28, active: 0.38 }, 'surface-strength')` 把首参数的 default 作为默认值，其余自身可枚举字段作为状态。default 字段存在性沿用 fnkit 的 containKey，default 为 undefined 也有效。第二参数仍可传完整配置对象；其中 states 覆盖简写的同名状态，其他状态保留。入口 parser 将这些写法统一为一份配置，不改变默认生产函数和状态回调的执行时机。

普通创建必须提供name与内容；状态回调的base是所选声明的基础内容。数值变化用add/multiply等CSS表达式表达，固定值原样继承。priority按显式值、来源加一或普通创建0确定；显式0有效。同名同完整地址按等级及书写顺序选择，跨地址仍遵循浏览器原生层叠。名称引用不激活定义，不按名称借入另一对象状态。

source 可以是直接 ValueInput，也可以是 `() => ValueInput`。函数 source 在定义时只保存，编译实际消费该 Variable 时才执行；返回的 Variable、Value 或其他 JSSContent 继续按统一内容协议解析。可调用JSSContent按自身内容协议消费，不作为普通生产函数执行。

Value 只包装内容，不持有 hover、active 等状态。Variable 创建时展开 `states` 中匹配到的快捷名称，未匹配的输入直接作为条件，业务保证条件约束自身。例如 `states: { hover: 1, '&[data-tone="danger"]': 2 }` 可以混用快捷名称和直接条件，编译消费已解析结果。Rules 中的字符串都是普通 CSS 条件，例如 `'&:hover'`；它不会自动使用快捷 hover 的 disabled 抑制或中央顺序。组件分类条件负责选择材料和相对贡献，状态配方由 Variable 持有。

## 同条件声明多个颜色

组件自己的surface/content/line等Variable分别声明。同一危险条件需要协调变化时，在同一rules中并列declare每个具体目标；只改一个颜色就只声明一个，不隐式配对成员。颜色之间是否随动由显式Variable引用决定。

基础材料直接使用paperColor、inkColor、brandColor等Variable。新用途的转换用普通函数接收具体基础并返回Variable；复用已有定义、状态与变体用variableFrom。组件分类决定何时选择哪份材料，不改材料提供者的全局JS配置。

同一对象的主题、强弱与交互用 states 表达，并写明实际条件。variants 表达具体部分或应用场景，如 surface、content、boundary；`source.variant('boundary')` 返回普通 Variable。用途配方可返回 `{ default, ...states }`，覆盖该部分的同名状态，其余状态继承。variableFrom 复用定义，variant 结果消掉父层变体。需要分类只改一次输入时，让用途默认表达式明确引用该输入；实际 Button 写法与颜色效果见[Variable的创建与复用.md](../../src/style-system/doc/behaviors/Variable的创建与复用.md)。

自动声明只保障根据地存在声明。无值declare仅保留为逃生舱，正常业务不能使用，也不能重传创建内容补基础。Button原四条补偿声明已移除；颜色公式与状态的组件位置通过address明确表达。

## 声明目标用对象

```ts
rules(button, [
  [$alignSelf, 'center'],
  declare(surfaceColor, accentColor),
  contentLayout({ mode: 'center', gap: normalSpace }),
])
```

颜色角色通过 `declare(surfaceColor, source)` 等操作返回 Declaration。rules 接受单个 Declaration、声明序列、Mixin 返回值、数组及其他对象 Iterable；其他 Key／Variable 的二元声明协议仍保留。rules 不接受普通声明对象、裸字符串属性目标或字符串声明序列。

Mixin 的配置对象仍然保留。例如 color({ background: surfaceColor }) 由 color 解释，不能与 rules(button, { background: surfaceColor }) 混淆。JSSKey 对象直接携带 CSS 属性名，不需要先注册字符串再查找。

声明不修改 Variable 对象。显式undefined代表此处无输出，但地址已声明，不用创建内容覆盖；同名同完整地址由编译器按声明键等级与书写顺序选择或 join，跨地址原生级联由浏览器决定。

## 内容碎片和效果放在哪里

整个 Style System 是抽象层。通用定义按描述目标与领域判断，不按消费者数量判断。组件自己的buttonSurfaceColor等定义表达具体控制对象，通用转换函数只表达从输入生成颜色的规则。functions 中的 JSS 内容组织工具构造 Expression；Variable 保存内容与自身状态，Modification 独立保存变化配方；declare 读取 key/content 声明材料，modify 的声明在编译消费时应用变化并组织条件步骤。

组件选择器及 variant、tone、size、status 协议由组件拥有。Mixin 拥有效果到 JSSKey 的映射；通用 Variable 拥有配方和状态。必要的定义重复可以保留，不为减少重复增加调用者必须理解的新分类。

组件样式区分业务规则与公开控制点，这两项职责都属于 `.style.ts`，不要求分成文件。业务规则决定分类、材料和状态怎样组合；公开 Variable 提供可由外界操作的同一内容身份，属于组件自己的契约。Button 的色源、画布和背景强度在 `Button.style.ts` 中以 export 定义，并从组件入口导出；分类贡献保持私有。内部参数不因使用 Variable 就必须公开，未来控制能力也不要求现在增加另一层 Controller。

`variable`、`colorMix`、`add` 提供创建、混色与计算的通用语义，不决定 Button 的视觉策略。通用 `clickable()` 提供禁用淡化，也接受 opacity 材料。Button 用私有 Variable 表达强调档位及其禁用状态，没有新增公开 opacity 控制点；禁用状态相对 opacity 基准计算。组件的视觉档位留在组件样式，不搬进底层工具。

焦点由定义端状态与clickable承担，clickable显式接收组件address。Button用focusColor直接提供buttonColor.variant('boundary')，危险条件只选择buttonColorInput。Focus内置匹配:focus-visible，中央优先级低于hover/active，不与原生:focus混同。

## 命名与顺序

Mixin 直接使用效果名称，如 `color`、`contentLayout`、`clickable`。

Variable 名字的最后一个单词说明存在形式：Color、Size、Width、Duration、Shadow 等。前面的词说明用途。例如 surfaceColor、boundaryWidth。

颜色实体使用具体用途名，例如buttonSurfaceColor；普通转换函数如lineColor(base)调用后返回新的Variable。VariableName模板字符串返回逻辑名，CSS地址由正规化负责，不按名称关联定义。

所有定义都在首次使用前，随后复用。通用定义也不例外；真正属于抽象层的内容放回其负责模块，在那个模块内遵循同一阅读顺序。

## 登记与挂载

从独立样式入口引入样式 API：

```ts
import { key, rules } from '@edsolater/uikit/style-system'

rules('.Caption', [[key('font-size'), '14px']])
```

应用入口从同一样式入口取得 `cssRoot`，并显式引入 `@edsolater/uikit/css/all-base.css` 保留生产环境的 reset 与 tokens。样式入口的 `clickable` 提供视觉效果，包根的 `clickable` 提供组件插件。

组件静态导入自己的 .style.ts。模块顶层 rules 登记配置；应用在所有静态样式导入后、render 前调用 cssRoot.mount()。组件渲染不触发编译。compileCSS() 仅返回字符串。

rule 的句柄可替换或删除自己的条目，rules 的句柄删除本批条目；需要刷新时由应用再次挂载。测试结束清理自身句柄。

## 修改后检查

检查完整样式文件：选择条件是否清楚、定义是否紧邻消费、通用状态是否仍由定义端拥有。类型测试拒绝旧声明入口；浏览器测试覆盖组件各配方、状态及其交集。不能只凭文件变短或测试通过判断归属正确。

## 第三方消费共享材料

Style System 从独立子路径导入。旧 CSS 及其消费者仍保留；新材料保存自己的值与条件，导入本身不会登记主题或挂载样式。

```ts
import { colorCanvas, colorAction, shadow, space, variableFrom, key, rules, cssRoot } from '@edsolater/uikit/style-system'

rules('.AccountPanel', [
  [key('background-color'), colorCanvas],
  [key('box-shadow'), shadow.variant('card')],
  [key('padding'), space],
])

// 元素状态在组件自己的根据地展开；根主题来源仍响应 data-theme。
const action = variableFrom(colorAction, colorAction.content, { name: 'panel-action', address: '.PanelAction' })
rules('.PanelAction', [
  [key('background-color'), action.variant('surface')],
  [key('color'), action.variant('content')],
  [key('border-color'), action.variant('boundary')],
])

// 宿主建立 style#css-root 后统一提交；材料依赖随实际消费声明。
cssRoot.mount()
```

具体组件仍在自己的 .style.ts 定义专属 Variable；共享材料不替组件决定分类与状态。

主题来源在根上响应 `data-theme`。动作材料在自身地址响应交互与 `data-emphasis`；soft 与 hover/active 的必要组合已有明确配方，禁用最后生效。states 本身不是自动累计修改。画布直接引用根来源；中性表面、内容与边界各自拥有强调状态。
