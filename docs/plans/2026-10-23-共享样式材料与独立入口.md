# 共享样式材料与独立入口 Plan

> 历史入口说明（2026-10-23）：Storybook 已退出当前项目。本文相关配置路径、命令与验收结果保留为当时事实，不再作为现役执行指引；当前预览由既有 Example 承担。

## 目标与范围

将旧 CSS tokens 的颜色、尺寸、排版、层级与动效定义补入现有 Style System pieces/tokens，采用自足 JS 内容和原生编译能力；旧 CSS、导入与组件配方保持。组件 .style.ts 继续引用共享材料并拥有专属 Variable。新定义不自动挂载主题，不新建引擎或平行 tokens 目录。

用户确定 Style System 从 @edsolater/uikit/style-system 独立导入，包根退出转导出；普通组件、Foundation、Hooks 根出口保持。Mixin 去 jss 前缀由协作者同步定义、调用方与文档，本轮集成实际出口。行动前 index/worktree 与 CSS 指纹保存于 agents/run/shared-style-materials，不执行 Git 回退或暂存。

## 2026-10-23：按对象状态与用途部分重组材料（已完成）

本轮替代前轮“一个旧 CSS 名称对应一个独立 Variable”的组织方式；历史记录保留。独立发布入口与 Mixin 更名已在当前 HEAD，当前 index 为空，本轮不暂存、不提交、不回退。用户所说“暂存想法”落实为本段计划。

### 当前设计与前置事实

用户明确：state 是同一对象的状态，包括 light/dark、soft/strong、hover；variant 是具体应用部分或场景，例如 surface/content/boundary、card/popover/dialog。上一轮候选表不构成机械扩张引擎的要求。

已核现有 Variable：variant 先计算新基础，然后继承状态；各 state 读取同一个基础，不自动累计。直接把 dark 固定色复制到各部分，会使 content/boundary 变成同色；把 soft 与 hover 当作自动累计也不成立。采用真实主题来源 → 用途材料两层，退出 base → dye → role 的无职责转发。主题来源在根承载 light/dark；用途材料引用主题当前值，并在消费者明确的 address 上处理自身状态。部分转换保留各自颜色关系。需要同时成立的状态使用已有明确复合条件，不新增维度引擎或自动组合表。

| 区域                                           | 本轮落点与判断                                                                                                                                                                                                                                                                                          |
| ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| color/seeds、dyes、roles                       | 合并无职责转发；保有真实主题意义的来源，品牌/动作/强调/反馈复用相同配方时使用 variableFrom。surface/content/boundary 用 variants，soft/strong/交互归 states；主题与局部状态不能互相覆盖。现役 palette/brandColor 等的颜色值保持；Button 的 soft/strong 旧变体命名按真实用途同步，保持组件外观和 props。 |
| shadow                                         | 场景选择收为一个材料的 card/popover/dialog variants，层级内容复用现有独立几何；保留真实主题条件与各部分独立覆盖。旧 CSS 桥与现役消费者不动。                                                                                                                                                            |
| space/size/radius/font/boundary/motion/opacity | 逐项核对是否真正状态。没有已成立条件的尺度不制造 data-* 协议；保留必要尺寸内容，删仅因旧 CSS 名字复制的无用途旋钮。减少动效继续复用原生 media 条件。                                                                                                                                                    |
| 出口、文档、材料测试                           | 同步实际对象入口及消费示例；退出锁死旧层级/名称数量的断言，保留独立 CSS、主题、局部覆盖、状态组合及卸载行为。                                                                                                                                                                                           |

### 部分状态的最小协议核查

先前“variants 引用各部分 Variable”候选退出：对用途主体 variableFrom 到局部 address，并不会把被引用部分的根据地一起移动，hover 会留在根，不能以引用包装掩盖。现有 variant 执行已经把规则返回值直接交给 variableFrom，parseVariableArgs 本来支持 `{ default, ...states }`；只需将 VariableVariantRule 的公开返回类型补齐这个既有输入，不改执行链或解析器。具体部分可覆盖自身 state，继承局部 address，旧普通内容和固定 Variable 引用语义保持。

最小验证先证明选取 content/boundary 后，各自状态在局部元素生效，并且与根主题同时成立；通过后再批量材料。不是引入自动多状态累积：soft+hover 的必要组合仍显式声明，且只编写实际需要的组合。

Button 原 soft 变体实际用于常态淡底，原 strong 用于非 filled 文字，它们并不是 emphasis 状态。分别改为 surface/text；line 改 boundary；原 content 继续表示实底上的 paperColor 内容色。真实 data-emphasis 状态仍保持原行为，不把名称修正偷换为颜色或透明度变化。

### 本轮实施结果与逐项取舍

- 颜色从三个文件的 base → dye → role 转发，收为根主题来源 → 用途对象；删除 dyes 文件。根主题来源有真实可覆盖身份，保留旧亮暗基本颜色与反馈混色；用途对象无需重新复制主题表。colorBrand、colorAccent 与各反馈颜色只拥有强调状态，colorAction 承担交互。colorLink 复用动作配方，visited 只在非交互、非禁用时采用，不用测试强读浏览器隐私历史。
- 表面、内容、边界各有真实不同配方；variants 使用原已有的 `{default,...states}` 解析，只补齐 VariableVariantRule 类型，运行链零新增。soft/strong 与 hover/active 的实际组合显式定义；复用 whenHover/whenActive/whenDisabled，原生 disabled 和 UIKit 标识都覆盖交互。没有自动笛卡尔展开或新 factory。
- 中性 surface/content/boundary 分别持有强调状态，引用根主题来源；canvas 本身就是根主题来源，直接复用对象，不制造无状态转发。组件只将用途对象迁到自己的 address，根主题保持根地址。
- shadow 退出未消费的数字层级公开表和多个用途转发，保留 card/popover/dialog 三份私有主题几何及一个公开用途主体。根负责主题，选取场景所得 Variable 可独立局部覆盖；原 Button CSS 桥保持。
- controlSize 使用现有 data-size 三档状态，Button 用 variableFrom 在组件地址承接，三个尺寸分类退出重复 minHeight 声明。字体和间距仍由组件分类组合，因为同一 small 对 gap、纵向和横向 padding 分别有不同要求，单一通用状态没有接管它们的职责。radius 不随 data-size 变化，保留固定形状与覆盖材料；font 字号/字重与 opacity 固定值同理。space/size/radius/boundary 删除没有消费者、也未参与任何公式的 base/ratio/scale 旋钮，不为它们保留伪控制承诺。
- motion 合并重复的新旧快速时长和两套来源：环境 media 状态 → 应用倍率 → durationFast/Normal/Slow。删除手动 onActive 自声明，沿现有 Variable 自动声明；保留原 --motion-scale-ratio 覆盖名。标准与强调缓动保留不同控制身份。
- Button 颜色用途为 surface/text/boundary/content；退出旧 soft/strong/line 用途名称，content 原纸色含义保持。这是样式用途命名修正，不能说所有样式 API 均未改变；组件 props、各分类外观与交互保持。相关现役说明同步，未给原错误语义保桥接别名。

## 2026-10-23：同一材料由统一基准派生表现（已完成）

用户进一步明确不需要四个独立尺寸入口，小、大等应相对于同一基准，而且不限于 size。此前以“固定档位仍有值”保留碎入口的取舍被本轮替代；上轮材料已全部暂存，当前工作树为空，本轮只改工作树，index 保持用户原样。

| opacity           | 统一存在感基准，soft/strong/disabled 按真实条件相对它；旧 half/muted 的无消费者入口退出。                                                                                            |
| color             | 色相身份与根主题不是同一标量的大小档，保真实颜色主体。各部分继续引用同一来源；alpha 强弱与禁用改为基准相对倍率，避免换半透明来源后又强置固定透明度。                                 |
| shadow            | card/popover/dialog 的多层几何不是等比楼梯，保具体场景。退出旧公开数字感等级桥，Button 以 control/filledControl 实际场景承接旧外观。模糊半径三入口收为一个长度基准，不造 data-blur。 |

复用现有 multiply、variableFrom、状态简写和条件，不新增档位工厂或自动比例矩阵。状态仍是同对象表现，variants 仍是部分/场景；没有 DOM 条件时，在消费处直接写相对表达，不伪造 selector。

### 本轮实施与修正依据

- 标量各只有当前主体基准：controlSize、space、textSize、fontWeight、radius、boundaryWidth、opacity、motionDuration、motionEasing。space 的三个 variant 是 gap/paddingBlock/paddingInline 部分；没有把 small 等档位偷搬到 variant。Button 局部定义引用公共对象，不复制 `.content`，尺寸/间距/文字三类分支收为状态模板；透明度和交互强度也从当前基准相对计算。
- 字重有独立的字体职责，Button 的 700 由 400 基准乘 7/4；胶囊是 Button 外形字面量 999px。focus 的宽度与间隔消费 boundaryWidth 与 space，不再各造长度入口。快交互时长直接为 motionDuration 的 2/3，减少动效仍由媒体条件驱动。
- 主题明暗回调读取当前主体 base，避免 variableFrom 替换基础后暗态又跳回旧来源。反馈身份仍各有色相；强调/禁用 alpha 相对输入计算，半透明输入不被固定 alpha 覆盖。Accent 暗态只降低当前基础的彩度；反馈暗态从带品牌混色的基础调整，这修正了旧配方绕过主体的关系，不承诺旧未接入材料每个色值逐字相同。
- 阴影场景仍表达多层真实几何，所有层共用 shadowDistance 长度与 shadowColor 颜色，分别按本层比例计算；不是乘整段 shadow 字符串。control/filledControl 替代旧 CSS 桥，亮暗默认几何及颜色由浏览器与原 CSS 对照。blurRadius 是单一模糊长度基准。按层展开源码，未添加工厂来压缩代码。

### 本轮失败尝试

1. 独立尺度探针最初以 Bun 执行 Vitest 浏览器入口，连接超时；按项目正式 Node runner 运行即通过。没有调整超时或生产逻辑，临时进程已停。
2. 阴影对照最初将交互场景留在根地址，根 hover 导致探针展示升起态；改为 probe 自己的局部 address，保真实组件初始化契约。
3. RGB 旧阴影的 alpha 经 8 位量化，与新 OKLCH 的精确 0.03 存在约 0.00137 差异。测试仍逐层精确比较几何，颜色转同一空间后采用最多 1/255 容差；没有改生产颜色凑字符串。
4. 审查发现部分暗态虽使用相对公式却引用旧上游，仍会绕过新 base；已改当前主体回调，并增加真实替换主体后明暗都跟随的浏览器边界。
