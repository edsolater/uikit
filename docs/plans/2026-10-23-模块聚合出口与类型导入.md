# 模块聚合出口与类型导入（已完成）

## 目标与边界

用户要求聚合 index 仅使用本地 `export *`，纯类型来源使用 `import type` / `export type`；同来源同时使用值和类型时，合并为具名项内的 `type`；`export type X = ...` 仍是正常类型声明。Solid 接入属于具体 Foundation 文件，index 不直接接第三方。应用装配 index.tsx 不作为聚合入口处理。

首轮入口调整前 HEAD 69d43f3，工作树与暂存为空。本轮不改 Git index，不提交或回退；保持状态异步、mergeProps、Effect 运行契约及样式独立发布入口。

## 职责与步骤

1. Foundation 聚合自身模块；原生 Context 归具体 context 文件。render 内部 owner 与计算工具接入移至内部 reactivity，渲染与 props 仍归 render。不造 public 包装过滤名单。
2. 各领域 index 直接聚合完整主体；同一来源只列一次。原选择性名单不是 API 冻结依据，完整能力及 predicate 可自然公开，但内部运行时、编译会话与账本不得因 star 意外泄漏。
3. 样式编译的公开节点与控制协议归真实契约模块，编译实现依赖该模块；仅必要职责分离，不按每个符号拆文件。项目维护的 TS/TSX 按实际值与类型关系组织导入，不改变类型声明和运行表达式。
4. 首轮类型检查定位真正重名来源；从模块职责处理冲突，不恢复选择性出口或新增筛选壳。
