# Variable 依赖链与弱声明 Plan

状态：生产功能、统一声明发布及 CSS 名称声明入口补漏已完成；本轮维护净减要求未通过。更新日期：2026-10-16；文件名保留最初日期 20261015。当前证据见 [名称声明验证](../../agents/run/variable-name-declarations/verification.md)，之前的实施和精简报告保留历史身份。

## 修改目标与用户已经确定的要求

父位置的 CSS 属性消费 line 后，子位置只要重新声明同 CSS 名称的 surface，编译器就在该位置联动声明 line，使最终 CSS 保留当地的 `line → surface` 关系。全部协调属于一次编译会话的 AST；交给 CSS 引擎的只有结果，没有观察者或运行时联动代码。

以下用户要求作为验收依据；上轮将 extend 默认等级写成0属于 Agent 误解，现予纠正：

1. 真正的 CSS 属性消费才“激活 Variable 依赖链”，与 Active 资源链分开。仅创建对象、保存配方、declare 或激活资源不是实际属性消费。默认生产函数、Expression 中的结构化依赖也需沿链处理。
2. 观察者表使用 `Map<CSS 自定义属性名, Set<需要联动声明的 Variable 材料>>`。按 CSS 名称查来源，材料保存配方；同名 globalSurface 与 componentSurface 均能触发 line 的观察者，不能按 JS 对象身份隔断。
3. 每次 declare 分别处理两项：沿依赖边联动 declare；直接读取自己的 states 一起 declare。状态归属不记录成依赖边，base 也不是普通同名 Variable 自引用，而是该名称本次声明的基础内容。
   已被本会话真实消费的同名材料也提供状态规则：独立同名对象当地 declare 后，这些规则按当地 base 展开。自身明确提供或继承后覆盖的同名状态优先，不登记状态归属图。这是前期 Plan 漏记的用户原要求，现已补回。
   普通 Key 与原始二元声明同样按 CSS 名称参与，不能因入口不同丢状态。普通 Key 保留999与原 join，生成状态沿用本次声明键等级；当前状态地址的明确值不由借用规则重写。此前 raw tuple 固定 active30 的旧测试把当地7保持到 active，是漏状态造成，已按源30／派生60及退出恢复纠正。
4. Variable 的 name 必选；仅 extend 可以继承名称。有 extend 时 default 可选，无 extend 时 name/default 必须提供。extend 继承默认内容和原始 states 函数规则；新 default 覆盖原 default。原规则保留，base 随新默认或局部 declare 的内容重绑定，不能冻结到创建时默认值。
5. priority 属于声明键。普通 Key 为最高档 999；Variable 的等级为 `specifiedPriority ?? (extend ? extend.priority + 1 : 0)`：直接指定、继承加一、否则0。global 只是 JS 前缀，定义端自己设 0，不按名称自动识别。
6. 联动声明等级为配方所属 Variable 的 priority 减 1；该次声明展开的 states 与该声明同级。传递链各配方分别计算，不能沿图逐边递减，也不能再给状态减级。
7. CSS 名称与完整条件地址相同时，高 priority 覆盖；同 priority 按原书写顺序。覆盖型 Variable 同级后写赢，普通 Key 的既有 join／同级聚合业务保留。
8. 不恢复 dynamic 或通配符默认声明，不引入浏览器 runtime observer，不用 CSS specificity、`!important` 或 cascade layer 实现 priority。

## 调用方式与可观察结果

### 同名跨对象联动

```ts
const globalSurface = variable('red', { name: 'surface-color', priority: 0 })
const componentSurface = variable('green', { name: 'surface-color', priority: 1 })
const line = variable(globalSurface, { name: 'line-color', priority: 1 })
```

父位置的 `border-color` 消费 line 后，子位置只声明 componentSurface，无需再次消费 line：

```css
.Parent {
  --surface-color: red;
  --line-color: var(--surface-color);
  border-color: var(--line-color);
}
.Child {
  --surface-color: green;
  --line-color: var(--surface-color);
}
```

配方保持 CSS 引用，不替换成来源的 JS 默认值。观察者集合可以保存多个同名不同配方的材料，随后按各次声明等级与顺序选择结果；不一律报配方冲突，也不只记录最后创建的对象。

### extend 与自身基础内容

```ts
const source = variable('10px', {
  name: 'size', priority: 0,
  states: { hover: base => multiply(base, 2), active: base => multiply(base, 3) },
})
const inherited = variable({ extend: source })
const larger = variable('20px', { extend: source })
const selected = variable({ extend: source, states: { active: '50px' } })
```

inherited 沿用 size、10px 和原始规则，priority 为 1。larger 使用 20px，继承的 hover 得到 40px；selected 覆盖 active，保留 hover。局部 `declare(larger, '7px')` 的当地 hover 等价于 14px。实现可直接表达值或使用内部基础引用，测试不绑定内部名称或创建时回调次数；base 不能变成 `--size: var(--size)`。同名引用包装不是 extend 的替代写法。

### 同一等级规则处理全部声明

| 声明来源 | 声明等级 | 自身 states 等级 |
| --- | --- | --- |
| 显式声明 priority 为 p 的 Variable | p | p |
| 联动声明配方 priority 为 p 的 Variable | p - 1 | p - 1 |
| 普通 Key | 999 | 保留既有 Key 业务 |

line 配方 priority 为 6，联动就是 5，可以覆盖等级 4 的显式 line。与等级 5 的显式 line 相遇时，后写的那次声明获胜，不存在“直接必胜”或“同级直接先”。

`A → B → C` 中 B 的配方 priority 为 6、C 为 9，则联动 B 为 5，C 为 8；C 不从 B 的 5 再减一次，C 的 states 也用 8。完整地址包含目标、状态及外层条件；别处高等级声明不能淘汰当前地址的声明。

## 实施后的职责

创建、局部声明、名称联动与同址选择分别由以下文件负责。

| 文件 | 职责 | 实施结果 |
| --- | --- | --- |
| `src/style-system/variable-args-parser.ts` | 归一 default/states、名称简写与 extend | 接收 extend-only 与新 default，保留原始状态规则；公开 variable 类型要求普通创建提供 name/default |
| `src/style-system/variable.ts` | 创建、引用、注册资源 | 保存创建事实与原始规则，交付实际消费过的配方；默认与名称图协调已迁出 |
| `src/style-system/variable-declaration.ts` | 公共声明基础、状态、消费者归属及重访 | Variable、Key 与 raw tuple 共用声明材料和状态发布；单个状态贡献保留真实 Key.join |
| `src/style-system/variable-modify.ts` | 相对修改步骤与结果 | 仅实际修改创建步骤状态，组合引用公共声明；改绑释放旧结果，不改变同对象归属 |
| `src/style-system/variable-dependency.ts` | 本会话默认请求与名称联动 | 收集有效消费配方和当地需求，不再回存声明实例或往返 Modify；重建先清旧再进入下一波 |
| `src/style-system/key.ts` | 声明键、CSS 名称与 join | priority 归键所有；复用 `propertyName()`，保留普通 Key 的 999 与同级 join |
| `src/style-system/compiler/ast-controller.ts` | 通用查询、编辑、来源、撤销、稳定核验 | 复用 `search/insert/depend/onRemove/addSettlementCheck`，不加入 Variable 图识别 |
| `src/style-system/compiler/style-nodes-to-content-nodes/` | 角色访问、编译波与同址连接 | 仅补必要的通用键等级选择、消费上下文；Variable 配方和反向图留在领域辅助文件 |

原有默认声明、注册、修改与 Active 撤销的有效职责须唯一接管；不并存两份相互补偿的协调账本。同址旧“存在即返回”不能代替 priority 竞争。

## 实施顺序

1. **已完成：冻结要求与 RED。** 先写正式测试并保留生产 SHA256，证明链和 priority 的实际 CSS 行为失败；接口、类型契约与行为 RED 分别报告。改写与新要求矛盾的匿名名称、原始默认回调绑定等旧断言，保留独立解析和输出验证。
2. **已完成：落实创建与键契约。** 支持两种 extend 形式，继承原始规则并绑定当地 base。匿名生产调用已明确供名；Adjust 和 Cluster 生成器显式使用内部名称分配工具。priority 按上文三分支公式落实。
3. **已完成：接通会话观察者。** 按真实 CSS 属性消费的结构化内容取依赖，按 CSS 名称收集材料；Active 与状态归属不成为依赖边。动画帧内属性属于消费，资源描述符不属于消费。
4. **已完成：统一 declare。** 自身与已消费同名材料的状态共用当地 base 展开；显式与联动声明统一进入 Join 的等级和原顺序选择，没有直接声明让位特判。自动状态声明也是联动来源，默认关系物化不重新种图。
5. **已完成：存活与撤销。** 来源与消费资格同时核对，AST 管理实际产物来源；共享、后到、撤销和会话隔离均有行为验证。消费输入或 revision 改变后，旧用法、旧边及旧派生产物同步更新，不额外执行生产函数建图。
6. **已完成：验证与文档。** 正式需求测试、Style System 全单元、全仓浏览器（含 Button 状态进入与退出恢复）、类型及构建通过；现役架构和 Variable 文档同步。完整命令和结果保存在当前实施证据中。

## 行为验收与本轮运行边界

本轮新增流程测试集中在 `src/style-system/test/变量依赖与声明行为.test.ts`，通过 describe 区分依赖联动与声明优先级，并共用一份 CSS 产物读取函数；静态 CSS 语义验证位于同前缀 `.browser.test.ts`。仅验证 variable 入口的类型契约继续留在相邻 `variable.test.ts`，不重排无关历史测试。

主要通过真实 `variable/declare/compileRules` 输出验证 CSS 名称、完整位置、值、顺序及撤销。公开 `onCompile`／Controller 只用于构造后到与撤销输入；不检查内部 Map、类名或调用步骤。

| 测试组 | 必须识别的错误 |
| --- | --- |
| 真实消费与名称依赖 | 同名跨对象不联动、不同名误连接、仅 Active 误激活、Expression／生产函数与传递观察者遗漏 |
| declare／extend／base | declare 不展开自身 states、状态归属被当图边；base 冻结或自引用；extend 丢 name/default/原始规则，覆盖 state 时丢未覆盖规则 |
| 等级与完整地址 | 普通默认0或 extend 加一被误解、数值反转、同级顺序错误、直接来源特判、联动逐层或状态额外扣级、普通 Key 999／join 破坏、跨地址淘汰 |
| 会话与生命周期 | 后到声明不参与、撤销高等级后不恢复、共享消费者提前清理、最后消费者或新会话残留观察者 |

base 的 7px → 14px 与继承 20px → 40px 使用最少真实浏览器用例：一次编译的静态 CSS 是输入，浏览器只作 `var/calc` 语义判定器。没有监听服务或编译后的功能 JS，测试不自行解释 CSS 变量与算术。

正式测试直接调用实际公共类型与实现，不再保留实施前的未来接口类型视图。name/default 必填用类型用例验收，没有新增运行时防御判断或绑定报错文本。

当前日志和原始证据放 `agents/run/variable-dependency-implementation/`。`variable-priority-extend/` 保留生产实施前的 RED；`variable-priority-default/` 保留 Agent 将 extend 错读为默认0的历史，并非用户改变规则；`variable-dependency-spec/` 保留更早证据。这些历史报告没有改写。没有执行 Git 写操作。

## 尚未裁决的边界

- 手写 `var(--name)` 字符串是否建图尚未指定；本轮用结构化 Variable／Expression，不新增 CSS 文本解析器。普通 Key 声明同名来源应能触发已经激活的观察者。
- 普通配方中的真实依赖环与同名自引用诊断仍待确定；base 的自身基础语义不是这种环。本轮不为想象的错误策略堆测试。
