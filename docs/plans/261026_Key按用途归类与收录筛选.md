## 范围与保留能力

- 旧文件中的每个 Key 必须有唯一接收位置或具名排除依据；不留 `non-standard`、
  `svg`、`basic-user-interface` 等没有统一直接目的的收容文件。
- 具名 `$Key` API 保持；CSS 原名、camelCase 别名及导出变量仍指向同一实例。
  构造保持纯函数，字符串入口直接依赖唯一静态表，自定义显式登记保持首对象及冲突语义。
- `background-image`、`box-shadow` 等同址重复贡献的逗号聚合、Key 自定义 `join`、
  状态/资源与撤销行为保持，不因换目录改写聚合实现。
- 现有 Mixin 中的对象/数组简写继续工作。尚未形成统一能力的 Background、Margin 等对象输入，
  不在本轮顺手新增；不把文件归类当成简写解析已经完成。
- 不重做 Token、业务组件、Mixin 效果、公共函数命名，也不删除自定义属性声明入口。
- 原已完成 Plan 和其 CSV 保留历史；后续迁移不得修改旧事实来迎合新目录。

## 验收与停止

| 检查对象 | 必须得到的结果 |
| --- | --- |
| 文件职责 | 每个目标文件可用一句直接目的解释，成员服务该目的；不靠规范名或“视觉”等总括词成立。 |
| 全量接管 | 原 569 项各有唯一归属或明确排除；旧文件退出无漏项，目标不产生空分类。 |
| 收录状态 | deprecated/前缀/预置自定义属性退出；实验项有可追溯的 Chrome 支持或近期发货依据。 |
| 业务入口 | 仅导入 rules/compileCSS 的真实打包消费者可正常使用字符串属性。 |
| 旧能力 | 聚合、对象/数组已有写法、Key 身份、显式登记、状态资源及撤销继续生效。 |
| 边界 | 没有借归类新增属性解析框架、改业务或重命名公共 API。 |

文档阶段核对职责列表、旧文件去向、数量和链接即可，不把未运行的源码验收写为已通过。
后续施工稳定通过且没有新失败信号后停止；发现用途冲突、证据矛盾或引用无法接管时，
