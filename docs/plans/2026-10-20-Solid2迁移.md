# Solid 2 迁移计划

## 目标与用户约束

将 UIKit 的运行时切换为 Solid 2，除用户明确授权的新 createEffect 契约外保持现有对外 API。真实组件只以 Button 为验收对象；Hooks 单独核查，其他组件不借本轮迁移重写或删除。先固化 Piv 的行为测试，再修改运行时，并通过单元测试、浏览器测试、构建和 `bun run dev` 验证。

修改以 Foundation 为主。Piv 只在既有职责内修正，不大面积重组。不加 readonly，不执行 Git 回退，不手写 dist。此前将整个动作放入 compute、apply 为空的要求已经由下述用户裁决替代，不再作为当前实现目标。

## 当前裁决：计算、执行与清理分开

用户要求顺应 Solid 2 的 compute → effect 与原生清理机制，优先让人直接看清依赖和资源归属。允许修改 `createEffect` 契约及必要消费者；其他公开 API 不因此自动获得修改授权。保留现有暂存和未暂存工作，不回退或改写 index。

`createEffect` 支持三种形式，按下列优先级选用：

1. `createEffect(source, value => ...)`：优先直接表达一个状态来源。
2. `createEffect([first, second], ([firstValue, secondValue]) => ...)`：确需多个独立来源时保留位置关系与准确 tuple 类型。
3. `createEffect(() => compute(), value => ...)`：前两者不能自然表达时才使用计算函数。

不创建无业务意义的派生 State 来凑单源；已有且有明确业务含义的派生能力继续复用。三种入口都只在 compute 中读取并跟踪依赖，动作内额外读取不添加依赖；动作返回 cleanup，在下次动作前或所属作用域释放时由 Solid 清理。不保留旧单回调兼容路线，也不另造调度器或清理体系。

### 接口与调用落点

| 落点 | 本轮职责与处理 |
| --- | --- |
| `foundation/createEffect.ts` | 单 Source、Source tuple、compute 三种类型重载与唯一运行时接入；复用 `val`，不重做来源转换。保留 onMount/onCleanup 其余公开契约。 |
| `foundation/render.ts` | 删除单回调 render Effect 模拟，按原生两阶段建立 DOM 监听；保持其他 props、Context 与 State API。 |
| `Piv/id.ts` | 直接消费合并层保留的稳定 id Source，由 Effect 自动读取，动作只写 DOM。 |
| `Piv/className.ts`、`handleStyle.ts` | 原生 mapArray 分别拥有声明及字段作用域，内层计算实际值，动作提交并返回本轮清理；不能在禁止创建 primitive 的动作阶段新建字段监听。class 多来源共同拥有 token 的计数语义保留。 |
| `Piv/handleHTMLProps.ts`、`handleHTMLPropsValue.ts` | 继续只订阅有效字段来源；计算最终字段值，动作写入并返回恢复绑定前 DOM 的清理。必须删除 restorePrevious、提前恢复与 splice 幂等补偿，采用计算 → 旧 cleanup → 新写入。 |
| `Piv/handleStyle.ts` | 重新按原生动作 cleanup 组织资源，移除不再需要的代际 token；保持同值换源、旧源退出与卸载行为。 |
| `hooks/useDocumentTitle`、`useUIThemeMode` | 已有标题/主题单 Source 直接传入；浏览器写入与监听安装在动作阶段，监听返回 cleanup。 |
| `kits/Loop.tsx`、`Popover/createPopoverController.ts` | 仅为必要调用迁移：Loop 用 compute 调用原有 Solid Accessor 并读取 DOM Source，因为 val 不执行普通函数，不能直接用来源 tuple 得到 items，也不额外造 State 包装。Popover 直接使用元素 Source，监听返回 cleanup，不重写组件。kitContext 文档例子同步。 |
| `foundation/createState/createReactiveRunner.ts` | 单独审查追踪计算与缓存结果职责，保留首次同步运行、getResult、显式释放及独立存活契约，不能借新 Effect 改其公开行为。 |

style 与 HTML 的 memo 只返回当前有效字段声明，mapArray 按 key 保留字段作用域，同 key 换源由同一原生 Effect 完成计算、旧清理和新提交；字段退出时释放该作用域。class 直接使用 mapArray 管理声明列表。没有弃值 memo、手动调度、代际 token 或保存上轮恢复函数。

runner 审查结论：`createReactionFn` 的同步首跑、缓存结果和整个 action 追踪契约继续保留。唯一生产消费者 followState 在 action 中写目标 State，因此不能将其称为纯计算或机械改成弃值 memo。本轮没有把新的 Effect 调用导向 runner；runner 内计算阶段执行 action、空 apply 的特殊适配仍存在，后续若调整需要另行确认其契约。

### 本轮验证顺序

1. 先补齐三入口类型推断、动作额外读不订阅、旧 cleanup 先于新动作、卸载清理的行为边界。
2. 实施 Foundation 与必要调用；Piv 的 DOM、事件、来源切换、同值换源、隐藏/重建和释放断言继续成立，不能为新实现削弱。
3. 运行类型检查、完整单元、Button 浏览器、构建及真实页面验证；Hooks 按实际调用范围核查，其他组件仅作必要语法迁移。
4. 按《代码清洁》的逻辑链短且认知流畅标准独立挑刺，修正补丁叠加、重复事实、无必要包装与职责绕行，再由原审查者复查。
5. 沿用已有 Button DOM/响应式性能入口，对改造前冻结产物、Solid 1 与新实现作一次复查；不新增基准场景，不将性能假设当成正确性依据。

## 迁移后的时序与验收边界

State 自持当前值，`.set()` 后直接读取立即得到新值。派生和 DOM 等待 Solid 2 提交；生产 `.set()` 不强制 `flush()`，避免破坏计算及 action 的事务。测试在状态写入或人工派发事件之后使用测试侧 `flush()`，保留原 DOM、身份、事件和清理断言，不把旧运行时即时更新的事实升级为用户要求。

Piv 在创建真实元素的当前分支捕获 owner，ref 取得 DOM 后恢复该 owner；自身 `if` 的隐藏、重建与整体卸载均已验证。没有在 Piv 顶层捕获父 owner 来代替分支作用域。

## 首轮历史实现与职责（Effect 与 Piv 补偿已由两阶段改造替代）

以下保留首轮事实。旧单回调 Effect、style 代际 token 与 HTML restorePrevious 不再是当前实现；现役职责见本文开头裁决及末尾两阶段执行记录。

- Foundation 继续拥有运行时差异。State 的值与通知分离，映射结果装盒以保留函数/Promise 身份；显式 `equals` 保留相同派生结果不重复通知的行为。runner 使用脱离父 owner 的 root，首次运行与显式释放契约保持。Effect 仍按用户指定方式将动作放在第一个参数；onMount 在 settled 后恢复登记时的 owner，使回调仍可创建监听。Context 保留 Provider、id、defaultValue 协议和结构拷贝能力，不额外引入身份注册表。
- Piv 主体只增加创建元素时捕获分支作用域与 ref 内恢复。`handleStyle.ts` 以每个 CSS 字段的代际 token 阻止旧 cleanup 删除新声明；`handleHTMLProps.ts` 在新一轮绑定前执行旧恢复函数，并使恢复幂等。两处服务不同资源语义，不抽取通用清理引擎。class、事件、plugin、ref 消费机制不重写。
- 配置固定 `solid-js@2.0.0-rc.15`、`@solidjs/web@2.0.0-rc.15` 与 `@solidjs/vite-plugin@3.0.0-next.50`，更新 JSX、DOM 类型扩展及测试渲染入口，移除根级旧 JSX 插件直接依赖。Button 生产代码和公开 props 不变；其他组件和 Hooks 生产代码没有改写。

## Storybook 稳定版接入

用户追加授权：升级最新稳定的 Storybook 10.x 组合，实际构建并检查 Button Story 与 Controls，继续采用最小修改。已有迁移变更由用户暂存，本轮只修改工作区，不改 Git index。

实际安装 `storybook@10.6.3`、`storybook-solidjs-vite@10.7.3`。适配器支持当前 Solid 2，自动选择新 renderer；既有根 Vite 插件已满足 JSX 编译要求，不添加自有 renderer、兼容 adapter 或重复插件。`.storybook/main.ts` 的源码别名保持，Button、Foundation、Piv 生产代码保持。

构建成功后，真实页面仍揭示样式错误：Filled 已有正确 data 属性和蓝色变量，却显示浅底、黑字、font-weight 400 与 8px 圆角。原因是 `preview-head.html` 的宿主先于 Vite 注入的基础 CSS，组件的 uikit layer 先创建，随后创建的 reset layer 覆盖组件属性。仅检查 DOM 属性不足以验收。

修正在 `.storybook/preview.ts`：基础 CSS 导入完成后，将既有空宿主移到 head 末尾，再调用原来的 `cssRoot.mount()`。不复制 layer 顺序、不增加 `!important`，不修改 Button 样式。修正后 Filled 在 Story 与真实 Example 的背景、内容色、字体粗细和圆角计算值一致。

实际 Controls 又发现一个独立问题：Disabled Story 的已声明字段从 true 改为 false 后，按钮仍禁用。`parseStatusProps.tsx` 保存的是外部字段首次读取的值；`parseVariantProps.tsx` 对已声明的 appearance、size 等不定字段同样取了快照。已有 State 测试只改变同一个对象内部的值，没有覆盖响应式 props getter 替换字段值。

在原责任内各改一行，以现有 `derive` 持续读取已声明外部字段，保留初始化时确定的内外归属及分组接管规则，不支持本轮尚未授权的运行期新增字段接管。parser 输出保持同一个稳定的派生 Source；不保证它与调用方传入的原 State 对象引用相同。历史测试中的引用直传断言改为检验映射前值、effect 收到 details 中同一个稳定 Source、effect 只执行一次和后续持续更新。这不增加 State/Getter 检测分支，也不在 Storybook 强制重建组件。
