## 目标与当前方向

精简 Style System 中为规则绑定、成员代理和同名关联增加的机制，保留变量定义与状态复用。使用者应能直接看出：规则是什么、创建了哪个 CSS 变量、它依赖谁、组件通过哪些入口控制颜色。

用户目前明确的方向是：

- 颜色转换由普通 JS 函数表达，调用后返回具体 Variable。函数本身不需要 CSS 实体。
- Variable 承载需要声明、引用和动态控制的 CSS 实体；组件拥有自己的具体变量定义。
- `extend` 改名为 `derive`，保留变量定义和状态复用。颜色转换函数与定义派生承担不同用途，可以组合使用。
- `VariableName` 保留对象形式，支持字符串化以便名称拼接；只去掉按名称关联和激活定义的职责。允许名称重复，但不因此在 JS 中自动替换依赖对象。
- CSS 层面的全局控制由实际 Variable 提供；规则算法和构建参数由普通 JS 变量提供。
- 清理现有机制，尽量缩短逻辑；不新增专门的配方对象。
- 不保留组或整组换色的专门机制。多个独立颜色需要协调变化时，在同一条 `rules()` 中并列多个 `declare()`。

以下计划按最新裁决修正：保留定义与状态复用，将 `extend` 改名为 `derive`；保留可字符串化的 `VariableName` 对象；整组换色改用并列声明。先前删除继承、把名称改成字符串的提案退出。此处记录前一阶段讨论结论；当前已获代码实施授权。

## 从线条颜色开始表达用途

线条颜色是一种转换规则。把某个表面颜色传进去，得到属于这个表面的线条颜色变量。

以下是目标用法伪代码，`derive` 的具体参数签名尚需在实施设计中核对。`Variable.name` 仍返回 `VariableName` 对象，通过 `Symbol.toPrimitive` 或 `toString()` 等字符串化能力支持模板字符串，无需改为字符串字段。

```ts
const lineStrength = variable(0.18, 'line-strength')

const lineColor = (base) =>
  variable(
    { default: colorMix([base, lineStrength], 'transparent') },
    `${base.name}-line`,
  )

const surfaceColor = variable(paperColor, 'surface-color')
const buttonSurfaceColor = surfaceColor.derive(
  buttonDefaultColor,
  (name) => `button-${name}`,
)
const buttonLineColor = lineColor(buttonSurfaceColor)
```

`surfaceColor.derive(...)` 复用表面变量的定义和状态，并表达 Button 的差异；`lineColor(buttonSurfaceColor)` 根据具体表面创建线条变量。前者复用定义，后者表达转换与依赖，互不取代。

`buttonLineColor` 明确依赖 `buttonSurfaceColor` 和 `lineStrength`。控制表面颜色或线条强度时，保留 CSS 动态响应；不依赖另一个同名 JS 对象自动接管引用。

如果改变的是转换算法，用普通 JS 参数或配置控制。配置在函数调用时读取，就影响这次创建；需要在构建消费时读取，则放进默认值的无参延迟函数。修改 JS 配置本身不会自动更新已经提交的 CSS，需要相应的重新构建与提交。

函数是规则的骨骼：它描述怎样产生一个有用途的变量，还没有形成具体 CSS 声明。调用它创建 Variable 后，才有可供样式消费和控制的实体。这个预加工过程有意义，但无需为了表达它再建立一种框架对象。

## 用依赖与并列声明表达颜色变化

### 从一个基础色推导其他颜色

Button 的边线和文字如果都由表面色计算，可以显式建立依赖：

```ts
const buttonLineColor = lineColor(buttonSurfaceColor)
const buttonContentColor = readableContent(buttonSurfaceColor)
```

改变表面色后，相关颜色随之变化。这要求保留变量依赖在使用作用域内的响应能力，不能只改引用对象身份而丢失局部派生声明。

### 同一条件下分别声明独立颜色

危险按钮可能分别指定表面、边线和文字。这些变化属于同一条按钮样式规则，无需再建立目标组、来源组或整组配对协议。

```ts
// 用法示意：dangerCondition 代表 Button 的危险条件。
rules(dangerCondition, [
  declare(buttonSurfaceColor, dangerSurfaceColor),
  declare(buttonContentColor, dangerContentColor),
  declare(buttonLineColor, dangerLineColor),
])
```

消费处继续引用 Button 自己的变量；要单独调整某个颜色，就声明对应变量。声明的条件、顺序和覆盖使用现有规则，不新增组级优先关系。

当前 Button 的 `[toneColors, badColors]` 等整组写法改为明确的并列声明。不新增整组换色 API、通用成员配对函数或组对象协议；也不要求颜色必须组织为普通对象。

## 现有机制的清理提案

| 现有部分               | 计划处理                                                                                                | 用途如何承接                                                               |
| ---------------------- | ------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| `Variable.baseOn()`    | 删除方法、绑定基础参数的逻辑和对应类型                                                                  | 普通函数接收基础，创建 Variable                                            |
| 默认生产函数的绑定参数 | 删除 `baseOn` 专用参数语义，保留无参延迟生产                                                            | 外层函数接收规则参数，闭包保存所需引用                                     |
| `extend`               | 改名为 `derive`，保留现有定义和状态复用能力                                                             | 沿用来源定义与状态，再表达派生变量的差异；不借重命名删除继承语义           |
| Cluster 包装           | 删除 `VariableCluster`、`variableCluster`、默认成员代理、可调用成员选择、登记表和 `clusterFrom`         | 直接引用具体变量，普通函数创建所需变量                                     |
| `resolveVariable()`    | 随 Cluster 代理移除各入口的默认成员解包                                                                 | 操作直接接收具体目标                                                       |
| Cluster 整组配对       | 删除 `clusterDeclarations`、组声明展开和成员配对冲突检查                                                | 同一条 `rules()` 中并列多个 `declare()`                                    |
| Name 的定义关联        | 保留 `VariableName` 对象并支持字符串化；移除同名定义注册、`bindVariableName` 和按名称激活全部定义的路径 | 对象继续表示 CSS 名称，具体 Variable 引用携带实际定义依赖                  |
| 按名称建立依赖关系     | 改为具体 Variable 关系，移除同名自动接管语义                                                            | 保留实际依赖的状态响应、局部声明与失效清理                                 |
| 颜色共享中转实体       | 保留有实际用途的globalSurfaceColor/globalContentColor；删除无用途代理及固定转换实体，组件拥有自己的定义 | 基础材料和有明确用途的控制 Variable 继续提供全局控制；转换函数创建组件变量 |

`derive` 承接 `extend` 的定义与状态复用，不用普通工厂或 `variable(source, name)` 替换这项能力。重命名不改变既有复用时机，也不擅自删除原有名称、等级等配置行为；确有其他语义调整时另行明确。名称不再激活定义，与定义复用能力的保留互不冲突。

重复 CSS 名称仍受浏览器层叠与作用域影响。取消 JS 同名关联不意味着可以消除 CSS 中的同名效果；名称输出和 CSS 声明合并仍需要处理真实 CSS 地址。

保留 Variable、状态规则、`declare`、实际依赖展开、CSS 表达式及必要的资源生命周期。`modify`、`adjust` 等能力本轮只去掉 Cluster 适配，不据此宣布删除它们自身的用途。

## 验收方式

- 两个不同表面传给 `lineColor`，得到分别依赖各自表面的变量；不会因同名 JS 对象出现而自动换绑。
- 全局 `lineStrength` 与组件局部表面控制都有效；局部覆盖时边线在正确位置重新建立表达式，不继承错误的祖先计算结果。
- Button 普通与危险条件通过并列声明切换表面、边线、文字；单独声明一个变量不会意外改动其他独立变量，状态响应和作用域隔离保留。
- `derive` 保留来源定义与状态复用，派生变量可表达自身差异；与 `lineColor(base)` 组合时，hover、active 等所需行为不丢失。
- `Variable.name` 仍为 `VariableName` 对象，模板字符串可用于名称组合；字符串化及纯名称引用不会按名称查找或激活其他定义。
- 默认延迟函数在约定的构建消费时读取配置；不暗示修改 JS 变量即可自动更新已提交 CSS。
- 检查公开类型、编译 CSS、浏览器计算样式，并运行相关回归、类型检查和构建；扫描源码、测试、出口、文档和产物的旧 API 残留。

## 实施确认的调用契约

Name字符串化输出无--逻辑名；CSS引用与声明保持完整正规化地址。derive只有实例入口：derive()沿用默认与状态，derive(value, nameOrOptions)表达差异；仅配置差异写derive(source.content, options)。没有variable({derive:source})入口，也不猜测单参对象是否为配置。完整值对象和显式undefined仍按内容处理。

组身份、成员配对与组级覆盖不再需要设计。来源变化按具体对象关系响应，CSS同名仍由CSS层叠处理，不因此激活其他JS定义。
