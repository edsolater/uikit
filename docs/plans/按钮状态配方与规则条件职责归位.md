# 修改目标

状态：2026-10-01 已按授权实施并通过验证。调查事实记录实施前快照；验证结果见文末。

共同纠正两层责任越界：Button 的状态配方由 Variable 的 `states` 持有，经 Mixin 普通消费后自动展开；公开 Rules 只组合普通 CSS 条件与声明，不把字符串作为 StateCondition 名称查询中央表。

用户明确裁决：可组合优先，维护视觉意图，旧数值与像素一致不作为目标。本轮维护 bare 退场、solid 突出、tone 语义、层次与状态反馈，删除只为复刻旧结果存在的分类交集。

此前的 [第一层状态方案](状态配方由Variable持有并交给StateCondition展开.md) 是 Agent 提案，不是本轮依据。[颜色接口方案](默认颜色派生与声明输入统一.md) 不并入本轮；通用 modify 语义、ColorVariable API 与 AST 结构不重设计。[Button 样式一致性恢复](Button样式一致性恢复.md) 和旧 CSS 保留为历史证据，其逐数值验收不约束本轮。

| [variable-modification.ts](../../src/style-system/variable-modification.ts) | modify 归于同对象的最近语义父声明，基础状态先发布再连接前序步骤 | 保留归属、ID 和次序，不能用 selector 交集替代语义父链 |

调查中的可证伪反例：

- 同一公开字符串在状态登记前是标签 selector，登记后变成中央状态条件；原始 Rules 的未知字符串报未知状态。说明错误位于输入解释。
- tone 创建默认红、局部声明蓝。把混色公式放入 states.hover 后会读取红色默认值；普通公式引用 tone、独立参数持有状态则保留局部蓝色引用。
- modify 可把同根定义的独立贡献连接为步骤，不需要联合 selector；如果分类另建局部定义，另一根路径修改不会自动归入该实例。
- 旧 bare＋tone 配比无法用独立差值完全复刻。用户选择维护意图，故无需保留这些专属数值和交集。

# Button 配方与实施落点

状态改变的量由 Variable 持有，局部色源保持普通 JSS 引用。组件选择材料与贡献，Mixin 消费现有 surfaceColor／foregroundColor，不新增输出转接颜色 Variable。

| 分类 | 独立贡献 | 验收意图 |
| --- | --- | --- |
| 默认 | 低强度语气色与中性交互画布 | 普通动作的层次与反馈 |
| bare | 透明画布与独立强度差值 | 常态透明，hover／active 有轻量反馈 |
| solid | 语气主色、对应前景、强度差值与状态阴影 | 动作突出，交互有层次 |
| tone | 整组语义材料与普通前景选择 | accent／danger 与声量独立组合 |
| disabled | 已有透明度、阴影与光标状态；中央条件抑制 hover／active | 统一淡化、停止交互反馈 |

[Button.style.ts](../../src/components/kits/Button/Button.style.ts) 的 surfaceSource 与 surfaceCanvas 分别选择同一混色公式的色源和画布。solid 切换 soft 为主色，bare 切换中性画布为透明；它们不是输出桥。surfaceStrength 持有状态，bare／solid 通过已有 modify 加入贡献。前景直接声明共享角色：tone 选择 strong，随后 solid 选择 foreground，普通分类顺序表达优先级，无分类交集。

默认前景与中性交互表面复用已有材料。opacity、shadowSolid、cursorLoading 的状态保持定义端职责。disabled 不再叠加旧背景混色和前景透明度衰减；统一淡化与状态抑制满足本轮意图。

CSS `inherit(--name)` 读取父元素属性，不能读取同一元素上一条声明，见 [CSS Values 5](https://www.w3.org/TR/css-values-5/#inherit-function)。本轮不引入新 API 或实验 flag；组合复用既有 Variable 引用与 modify。

# Rules 与内部状态路径

公开 `rule()`／`rules()` 与原始 Rules 编译统一将字符串转为普通 Condition。`'hover'` 是字面标签 selector，`'&:hover'` 是普通伪类条件，不自动使用中央 disabled 抑制。不能按状态名称黑名单拒绝字符串，否则 Rules 仍在解释状态登记。

StateCondition 名称校验、顺序与匹配条件只供 Variable.states 自动展开。内部 ConditionPath 的 stateConditionPath 与 semanticPath 继续保留；未知 states 名称仍报错，通用 modify 的语义父归属不变。

颜色聚合的内部资源通过 [resource-rule.ts](../../src/style-system/compiler/resource-rule.ts) 保存已有完整条件路径，Rule 路径输出实际 Condition。原 ResourceCompilation 提交时恢复内部身份，继续负责替换、共享与撤销。这是私有路径桥接，不是公开状态输入或 AST 重构。

必须统一普通与私有资源的地址编码：无状态同目标、同 Key 仍后激活替换；不同状态名即使映射相同 CSS 条件，也保留各自内部身份。直接用 Controller.insert 重造账本无法保留既有同名接管，因此退出该候选。

# 可证伪验收

| 验收项 | 失败条件 |
| --- | --- |
| 普通条件含义稳定 | 同一字符串随 stateCondition 登记变义，或 raw／onActive 普通字符串仍报未知状态 |
| Variable 状态完整 | 未知 states 不再报错、中央顺序失效、自动 hover／active 不再抑制 disabled |
| 定义端状态与组合 | Button 仍逐状态登记消费 Rule、有 variant×tone 交集、Mixin 解释状态或另建 dispatcher |
| 局部来源 | tone 默认红、局部蓝时交互退回红；局部成员／角色覆盖互相污染或退出不恢复 |
| 视觉意图 | bare 常态不透明、交互无反馈；solid 声量不突出；tone 丢语义；禁用有交互反馈；两主题分类不能独立组合 |
| 资源身份与生命周期 | 普通／私有同址不能接管而出现逗号颜色；同条件不同状态身份被合并；删一个消费者清掉其他消费者资源；最后退出或重新消费错误 |
| 通用边界 | modify 的对象归属、ID 或步骤语义改变，ColorVariable 接口重设计或 AST 扩大重构 |

# 后续裁决：业务规则与公开控制定义

用户随后明确两部分：业务规则决定表现，值得暴露的 Variable 同时作为未来控制器；不是所有内部参数都需要暴露，Button opacity 无需单独定义。本节记录后续实施，不覆盖上节首次验收结果。

该次实施曾将控制定义放入独立的 Button.variables.ts；用户随后纠正“两部分”表示职责而非文件，现已合回 [Button.style.ts](../../src/components/kits/Button/Button.style.ts)。其中公开 buttonSurfaceSource、buttonSurfaceCanvas、buttonSurfaceStrength，同一对象经既有组件出口传到包入口并直接消费。色源与画布支持 declare，强度支持 declare／modify。它们控制混色两端与强度，有可观察的独立作用；不增加 Controller 包装或复制实例。

Button.style.ts 继续负责分类选择与私有贡献，bare／solid 差值、阴影、光标不因使用 Variable 自动公开。Variable、colorMix、calcAdd 提供通用操作，具体视觉策略归 Button；专属 opacity 删除，clickable() 使用通用 disabledFade。未来运行时变值自动插入 CSS 尚未实现，当前控制通过 Rules 声明和挂载执行。

新增浏览器反例分别验证 source 单独生效、canvas 在其基础上独立生效、strength.modify 与 hover 组合，另一作用域 strength.declare 生效，未控制按钮不受影响，逐项移除后恢复。控制能力不是由文件移动或名称推断。
