# 本轮确定的方向

## 目的与当前方式

目的与行为同时由[Variable的创建与复用.md](../../src/style-system/doc/behaviors/Variable的创建与复用.md)与[Variable的创建与复用.md](../../src/style-system/doc/behaviors/Variable的创建与复用.md)记录：业务直接使用变量即可获得有效样式，并通过全局或区域输入调整结果、保留显式控制及状态，无需手工管理依赖或重复重建。Behavior的行为节记录当前约定的默认可用、当前设定保持及当地动态响应。行为是达成目的的一种方式，可经用户裁决演进；这不授权静默改变现有API、状态或生命周期。代码负责具体实现，本计划记录待实施方案。

## 两项独立职责

每次使用先保障默认基础，再按样式Address取得当前定义并处理目标自身state及必要的当地联动。两者分别判断，不能把根默认当作各Address的当地声明。

1. AST提供当前`:root`声明清单，Variable/default逻辑按CSS名称检查：已有则不补，没有才补创建默认基础。根兜底不展开state，不写入Variable声明记录树。即使根声明来自另一个同名Variable或普通Key，也保留已有声明；不扩大为任意选择器等价解析。
2. 从当前Address沿condition path逐级向上取得当前定义，找不到才使用创建默认。保存和复用的必须是原始declare输入：尚未附上state、未被CSS引擎求成具体值；不能把state展开产物或浏览器求值结果再当输入展开。该定义同时供当地基础和目标state使用。

Address指编译中的样式地址，不是实际DOM。不得查DOM或根据页面结构拼猜条件路径。

## 当地基础与state分开处理

当前定义原始内容确有Variable引用，且任一被引用Variable在当前Address已有声明，才输出当地基础重声明。当地声明包括显式和连带自动产物；根兜底不算当地声明。多输入是任一成立，不要求所有输入都当地declare；其他输入可以继承。

无引用或输入未在当地声明时，不重复当地基础，但目标自身state仍在使用Address发布。state依据当前原始定义生成，不在根兜底展开，防止根hover使多个Button同时改变。当前定义是固定20时，即使创建默认引用base，也不得恢复旧公式；自身乘2状态仍为40。

例如`basicSize = 1em`、`cardWidth = multiply(basicSize, 20)`，Card和Inner只使用cardWidth、输入当地没有声明时，不在两处复制basicSize或cardWidth基础。Card声明basicSize后只在Card联动cardWidth；Inner纯消费继续继承。若source声明触发middle当地自动声明，middle又是result的实际引用，则result可在同一Address继续联动。

先登记当前Address输入声明、提交CSS后修改该输入的CSS值，已经发布的表达式仍须动态响应。只有内联`style.setProperty`却没有当前Address声明，不承诺生成当地基础，也不引入DOM观察或JS运行时重建。

## Card与Inner示例

当前API输入，两个样式Address都只消费cardWidth：

```ts
const basicSize = variable('1em', 'card-basic-size')
const cardWidth = variable(multiply(basicSize, 20), 'card-width')
const sourceRules: Rules = [
  [['.Card'], 'width', cardWidth],
  [['.Card', '.Inner'], 'width', cardWidth],
]
const css = compileRules(sourceRules)
```

当前API对应的CSS示意（纯消费及Card输入触发案例已通过，允许等效格式）：

```css
:root {
  --card-basic-size: 1em;
  --card-width: calc(var(--card-basic-size) * 20);
}
.Card {
  width: var(--card-width);
}
.Card .Inner {
  width: var(--card-width);
}
```

然后在Card的同一Address增加输入声明，再编译：

```ts
sourceRules.unshift([['.Card'], ...declare(basicSize, '2em')])
const updatedCSS = compileRules(sourceRules)
```

期望Card联动，Inner继续继承，不重复当地基础：

```css
:root {
  --card-basic-size: 1em;
  --card-width: calc(var(--card-basic-size) * 20);
}
.Card {
  --card-basic-size: 2em;
  --card-width: calc(var(--card-basic-size) * 20);
  width: var(--card-width);
}
.Card .Inner {
  width: var(--card-width);
}
```

## 当前定义记录与AST分工

Variable内部condition声明记录树保留原始输入及条件位置，用于当前定义查找。根兜底不进入该树。当地自动声明的事实可以触发后续依赖，但它保留origin、指回业务原始输入，不成为新的原始定义；state展开产物或浏览器求值结果不能再次作为原始输入展开或自激。这与检查当前Address是否已有声明分别承担不同职责，不要求新增一份平行原始输入。

Variable按根声明清单查CSS名称、识别实际引用并检查当地输入声明门槛。此前“Variable不检查默认是否已有、一律交AST决定”的方案在同范围退出。AST继续拥有贡献覆盖、同址优先关系、条件和来源关系、去重及生命周期；不增加Variable侧另一套覆盖判定。具体字段和查询API须核对现有契约，不预设私有结构。

延迟生产函数与合法JS内容能力保留。实际依赖来自内容契约及真实编译记录，不按传参猜测，也不为探测依赖重复执行业务函数。编译判断发生于CSS提交前，浏览器负责CSS运行时求值；性能仍须实测，不能据JS阶段推断已经更快。

后续审查确认消费重访反复登记撤销回调，以及生成节点先发布、后补角色的时序负担。第三项先做复现：40/80个独立联动同时退出需要43/83轮，80个输入产生21137次顺序比较，证明整批回填确有重复工作。此次只修登记和工作范围，不改变Variable、状态、Modify、Canvas及Button行为；实现和验收由主实例直接完成。

# 验收案例

下表为验收输入与结果示意，不是新增API签名。

| 场景与操作                                                           | 应观察结果                                                                |
| -------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| 默认0.4，兄弟作用域显式0.2                                           | 普通消费0.4、兄弟消费0.2；撤销覆盖后恢复适用默认                          |
| 默认0.4，更窄条件覆盖0.8，进入再退出条件                             | 0.4→0.8→0.4，无关声明不抑制普通默认                                       |
| `base=4`、`amount=2`、`result=base×amount`；A改base为7，B改amount为3 | 普通/A/B为8/14/12，无需补依赖清单；撤销A后为8/8/12                        |
| result普通定义改为20，再改变旧来源base                               | 保留20，旧默认表达式不复活；邻居仍遵循自己的适用定义                      |
| result普通定义换成another×3                                          | 当地读取another，旧base变化不再恢复旧配方；无其他需求时旧依赖资源退出     |
| result有按基础乘2的状态，本次声明基础为20                            | 普通20、命中该状态40，退出恢复20；不以创建默认计算                        |
| basicSize=1em、cardWidth=basicSize×20，Card/Inner纯消费              | 根基础可用，两处均不重复当地基础；Card声明输入后只在Card联动，Inner不克隆 |
| 根同名已有声明；无依赖固定量有hover状态                              | 根基础不被创建默认覆盖，两个实例hover独立，根兜底不展开该状态             |
| 延迟或状态内容实际引用Variable；另有传入但未引用的参数               | 前者维持真实条件依赖，后者不产生关系或资源激活                            |
| 当前Address已declare任一实际输入，提交后修改该输入CSS值              | 已有当地表达式读取新输入，不需要JS重建；其他输入仍可继承                  |
| 显式主题根、媒体条件与区域覆盖共同存在                               | 主题/媒体切换及局部选值正确，自动默认不压过有效设定                       |
| 两个消费者共享依赖，撤销其一，再撤销全部                             | 先保留剩余需求，再清理退出产物；复编无旧关系                              |
