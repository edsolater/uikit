# 不可违背的边界

1. **不实现 `name()`，不增加 Variable 名称反查表或提前字符串化。** Variable 作为目标继续使用 `[variable, content]`；对象键只沿用原有属性解析。既有原生 CSS 字符串入口不因此删除。
2. 声明对象右侧不限制为字符串：原始值按现有 Value 输入协议理解；Value、Variable、subject、condition、依赖都不能被对象展开丢失。不强制将每个原始值新包装成对象。
3. 不调整 `softTone`、`strongTone`、`actionHover`、`actionActive` 等命名或语义，不新增自身值回调，不生成颜色曲线，不改 disabled 混色、透明度、hover、active、focus、尺寸配方。
4. 不把业务无需区分 Flex/Grid 当作缺陷，不改布局 Mixin。共享角色不等于固定颜色，也不引入禁止继承或新的组件隔离机制。
5. 保留输入顺序、重复声明、undefined 跳过、整批失败不登记和内容身份。对象无法表达重复键，需要重复声明时继续使用 Iterable。
6. 不增加材料类、Manager、转换包装、第二套编译系统或旧目录兼容转发。只迁移实际引用与受影响现役文档，不改其他历史 Plan。
7. 不迁移 Input、Card、PopUp，不改基础 CSS token、包发布协议或无关文件。不覆盖用户改动，不提交 Git，不生成截图或临时报告，不引入 readonly 或缩写色名。

# 目标写法

以下为契约示例，不要求把 Button 的 Mixin 改成原始 CSS：

```ts
rules(button, [
  {
    display: 'inline-flex',
    color: foregroundColor,
    opacity: value(1, { disabled: 0.56 }),
  },
  [surfaceColor, action],
])
```

对象和元组共同进入原有有序声明链。`surfaceColor` 表示通用组件角色；`action` 是现有操作色材料的源码名，本轮不顺便重命名为 `actionColor`。
