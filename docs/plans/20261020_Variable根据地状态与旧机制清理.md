# 目标与实施判断

本轮纠正非根据地显式赋值自动发布states的错误，并删除已无消费者的旧机制。依据用户要求“旧机制该删的彻底删掉，states只随根据地展开”，保留已有声明、显式undefined、根别名的原生权重、定义复用和完整加工能力。前轮历史记录保留，通过纠正指针退出失效结论。

`variable/declare.ts`原定位仍成立，但显式赋值基础与状态发布混在同一流程，导致根变量在.Box赋10px后也带上根的8px状态。本轮先写浏览器反例并确认失败，再将状态发布交给`publishHomeStates`：只有AST查询匹配到根据地地址及名称的节点发布states。显式赋值仍建立修改所需的真实基础；消费只保障和绑定根据地。根别名匹配直接复用AST，不新增选择器解析、私有声明树或状态flag。

# 实施顺序与清理去向

1. 浏览器先证明根4px、状态8px、.Box显式10px的错误；保留根状态和组件根据地正例。
2. 分开显式赋值基础与根据地状态发布；地址或名称变化时重建定义并撤回旧状态。
3. 删除下表中的无消费者内容，扫描源码、出口和现役文档；保留实际引用及资源退出链。
4. 改写保护旧语义的测试，按有效目的继续验证优先级、生产基础、注册和完整加工；同步受影响Behavior、教程、架构及历史指针。
5. 全量单元、浏览器、类型检查、构建及产物/API bundle验证；独立审查后按实际结果修正。
