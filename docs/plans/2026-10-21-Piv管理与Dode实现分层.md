# Piv 管理与 Dode 实现分层

## 目标与边界

保留对外组件名 Piv，在 `src/components/Piv/` 内建立内部 Dode。Piv 决定元素身份、显示条件、来源优先级、公共能力与插件生命周期；Dode 创建已经确定的元素并执行基础 DOM 绑定。两者共用原来的一个真实 DOM，不增加包装层，不改变 Card、Button 等业务组件用法，Dode 不进入包根公开 API。

用户明确要求能力已经准备好但未启用时不占用 draggable 资源，启用时直接复用现有插件能力。boolean/options 入口及动态 Source 开关属于讨论中提出并整体承接的方案，不扩展成所有配置字段热更新或通用能力注册中心。页内拖动继续使用 Pointer、原始 DOM 与 translate；外部原生 drop、Scope、Top Layer、占用保护及现有同步 data-interacting 事务策略保留。

先 Plan 后生产修改。保留已有暂存和未暂存内容，不执行 Git 写操作、回退或自动提交，不新增 readonly。调查期间用户在外部提交了前轮改动，开始时看到的 dirty 不再作为必须保留的状态形状；以实际工作区内容为基线，不能自行还原旧状态。本轮当前基线 HEAD 为 `86e6315`，实际操作前继续核对。

## 接线与公共能力契约

Piv 先决定真实元素及分支；Dode 创建该元素，在其 ref 能取得 DOM 时调用 Piv 提供的初始化入口。Piv 将插件和公共能力返回值归入声明账本，Dode 只取得最终 DOM 绑定材料。它不接收原始 PivProps，也不解析或实例化公共能力。

`draggable`、`droppable` 接受 `Source<boolean | Options | undefined>`。true 使用对应插件默认配置，options 使用已有插件配置形状；两者可以在同一元素上启用。不是启用原生 HTML draggable，也不另写拖放事务。options 中的 disabled 沿原插件控制器契约：显式创建能力但禁止操作，不等于快捷 false 的零实例路径。

默认缺省或字面 false 直接跳过能力接入，不实例化插件、不建立该能力状态、事件监听或 Drop Target。显式动态 Source 为了观察开关有必要的控制订阅，但值为关闭时不拥有插件实例、DOM 监听及注册资源；这与默认元素没有能力监听区分。打开时创建原生作用域并消费插件，关闭时释放该作用域，取消正在进行的拖动、解绑事件及注销目标。再次打开复用原 DOM，避免重复监听。

### 来源与独立入口

能力配置按直接 props、shadowProps、plugin 返回声明的现有来源优先关系选择，读取最高优先级非 undefined 值。false 是有效关闭值，覆盖低优先级启用；不把它拼成列表后按 truthy 判断。

快捷字段只控制自己的能力实例，全部快捷来源 undefined 时关闭。原 plugin 展开、顺序和资源归属保持；同一能力在快捷属性与 plugin 两种方式中选择一种，不自动跨入口判重或接管。默认无资源承诺针对未另行显式配置同名 plugin 的快捷路径，false 不撤销显式 plugin 或 usePlugin 的资源。

事件仍使用原 listener 停止函数和原生 Effect 清理，不新建资源回收体系；切换能力声明时应保留未变化 listener 的 once/local/global 生命周期，不能因全量重绑其他事件而误触清理。

## 验证边界

- 默认 Piv、字面 false：一个原 DOM，没有官方拖放实例及对应监听/注册；不能靠事件触发时才返回来冒充零资源。
- 显式开启：已有 Pointer 拖动、原始 DOM、外部 drop、Scope 与占用保护继续成立；同一元素允许两项能力。
- 来源：直接 false 覆盖低优先级 true/options；动态换来源后旧源停止；原显式 plugin 契约及运行顺序不变。
- 生命周期：关闭时取消活跃拖动、恢复 Top Layer/位移/同步标记、移除事件并注销 Drop Target；重开一次生效；if 隐藏、重建与卸载清理正确。

- 最终运行 `bun run test`、`bun run type-check`、`bun run build`、`bun run build-storybook`，各命令单独保留退出码，浏览器不得并发争用。
