# 5. 拒绝已经撤销的依赖来源

**实施结果：** 已完成，独立实际代码复查通过。`ASTSession.own` 统一校验来源存活，公共 `depend` 继续委派；校验在自依赖早退之前执行。回归覆盖已撤销来源明确失败、清理一次、退出输出来源继续持有产物，以及尚未入队的合法产物。旧实现不抛错的反例修正后通过；全量单元测试 242 项（38 个文件）、类型检查、浏览器测试 98 项（16 个文件）通过。

- **实施前问题与证据：** [ASTController 与 ASTSession](../../src/style-system/compiler/ast-controller.ts) 的来源登记没有拒绝已撤销 owner。A 拥有生成产物 P，撤销 B，再执行 `depend(P, { owner: B })`，最后撤销 A；P 因已死的 B 仍在来源集合而残留。
- **修改目标与落点：** 在公共 depend 的登记边界及其委派的会话来源操作中明确拒绝已撤销来源。ASTSession 负责来源存活与级联，不能让 Variable 或编译回调各自补检。退出输出的节点仍是存活来源，不应因此被拒绝。
- **顺序与前置：** 在扫描优化前先固定存活合同，使后续结构改动有行为基准。
- **最小验收：** 通过 Controller 建立 A、B、P，依上述顺序操作，断言对已撤销 B 的 depend 明确失败；移除 A 后 P 被清理且 onRemove 只执行一次。对 `remove(B, { from: 'output' })` 则允许 depend，移除 A 后 P 仍存活，真正撤销 B 后才清理。

- **修改目标与落点：** 在编译器有待生成资源的波末，按记录的当前 Rules 一次线性收集最终 Rule 身份的关联，待生成项携带对应激活记录，生成节点时使用该关联。保留资源生成时读取当前 Rules 的原有时点，不维护首次激活快照或永久逆索引。这里连接 onActive 与按需节点，属于编译器，不迁移成 Controller 的资源专用接口。地址合并时保留最终 Rule 的精确身份关联及全部消费者。
- **顺序与前置：** 第 5、7 项完成后使用统一存活判断。记录关联优化必须保持同址最后替换和多消费者来源，而不能只改循环。
- **最小验收：** 两个激活内容提供同址不同值资源，断言后激活值进入 CSS；多个 owner 消费同一资源时，撤销一个不会清理资源，全部撤销后才清理。再消费已有激活内容，在资源未被替换且仍存活时不会重复生成资源。同一 Rule 身份的多个记录均关联最终产物，不把不同 Rule 的旧记录误认成获胜记录；跨波新增及未再消费记录的新增／删除／替换保持原关联语义。计数证明每批关系收集随当前 Rules 总量线性增长，各产物只使用对应关联，不逐项遍历无关记录；无 pending 的波不收集。

**实施结果：** 已完成，独立实际代码复查通过。Variable 协议所属模块统一生成注册字段，两条消费路径保留各自位置、来源、identity、激活期与撤销处理；旧的第二份 syntax／inherits／initial-value 字段列表退出。普通与修改内部注册在有／无 initialValue 时的基线及修改后字段完全一致，内部 syntax 约束保持；本项是保行为的责任合并，无自然失败反例，不伪造红测。既有 A/B/A 同名注册及归零重激活回归继续通过；全量单元测试 260 项（38 个文件）、类型检查、浏览器测试 98 项（16 个文件）通过。

- **实施前问题与证据：** [Variable](../../src/style-system/variable.ts) 的资源激活与修改模块的内部 Variable 登记都手写 syntax、inherits、initial-value 声明。注册字段增改、默认值或序列化规则改变时必须同步两个字段列表；二者生命周期不同，复制字段并不能表达这种分工。
- **修改目标与落点：** 由拥有 Variable registration 协议的模块提供一处 @property 内容生成，普通 Variable 与内部修改步骤复用它。共享的是内容生成，激活期、同地址替换、owner 与撤销仍由各自消费路径处理；不合并生命周期状态。
- **顺序与前置：** 第 8 项资源关联稳定后实施，并与第 9 项分别提交验证与复查。
- **最小验收：** 同一 registration 配置用于普通 Variable 和 modify 内部步骤，断言两条路径的 syntax、inherits、initial-value 均一致，内部变量的 syntax 类型约束得到保留；未提供 initial-value 时应省略该声明，不能输出 undefined。保留 A/B/A 同名不同对象的激活期用例，以及消费者归零后重新激活用例，防止共享生成代码改动注册先后与撤销语义。
