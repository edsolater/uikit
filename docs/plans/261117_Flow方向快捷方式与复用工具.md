本计划为 Flow 增加 `$row`、`$column`，并把快捷方式的核心选择规则放进可复用 Utils。组件只声明主字段、快捷映射与原样式效果；聚合后的配置仍保留原字段和值。

# 目标与已定规则

```tsx
<Flow $column>纵排内容</Flow>
<Flow $column $direction="row">横排内容</Flow>
<Flow $direction="row" $styleConfig={{ $column: true }}>纵排内容</Flow>
```

用户明确优先级：显式 `$styleConfig` 来源高于直接 `$direction`，直接 `$direction` 高于直接快捷属性。同一来源的 `$row`、`$column` 同时启用时，按出现顺序，后者覆盖前者。快捷方式必须在样式定义中逐项声明，不能从字符串枚举自动推导。

Flow 的声明使用显式映射 `{ $row: 'row', $column: 'column' }`。`$row`、`$column` 类型为布尔；false 或 undefined 不启用该快捷。直接 `$column $row` 选择 row，反向顺序选择 column，不能采用 handler 定义顺序替代输入顺序。

本轮实现选择：每个来源内部，主字段 `$direction` 比同来源的快捷明确，因此优先。显式配置中的 `$direction: undefined` 表示清空该方向组，沿原收集机制恢复默认，零次调用方向解释；直接主字段值为 undefined 表示没有具体方向，可使用快捷。该细节是保持原清空能力的实现选择，不声称用户逐项指定。显式同名 false/undefined 已遮盖的低层快捷不能复活。

# 必要机制与职责

当前平铺对象只保存最终同名字段值，无法从中判断 `$direction` 与 `$column` 的来源优先级；spread 覆盖已存在键时又不移动原键位置，无法用最终 Object.keys 还原显式对象中的两个快捷顺序。绑定层目前按定义表迭代，也不代表使用方出现顺序。

Parser 保留当前字段和值的合并规则，只在新聚合结果上附加非枚举、只读的来源和顺序元信息。不改写原配置对象，不复制 Source 值，不增加状态或缓存；没有直接字段时仍返回原 props。仅显式配置或 Controller 新写入的普通对象按当前对象自身的单一来源处理。

绑定层给解释函数增加第二个只读上下文，含当前字段和当前配置。旧单参数解释函数继续成立。Utils 只读取该次实际消费的配置及元信息，不回读原 props，不绕过 Controller。

独立 `createStyleConfigShortcuts` 接收主字段、原解释函数和逐项写出的快捷映射，交付相应字段解释表。它内部处理来源、具体值和快捷顺序，仅在当前字段是有效胜者时调用原解释一次；不是依次执行全部快捷再撤销。显式清空不调用解释，沿既有收集清除效果。它不含 Flow 名称、Token 或布局规则，也不生成枚举之外的快捷名称。

Flow.style.ts 只声明映射并提供原方向效果。当前 row 依赖默认值而不主动写 Token，所以“先 column 再 row”会残留 column 的换行和对齐；必须先确定唯一方向，再应用原效果。

# 实施与验收

- 先保持合并字段和值的既有行为，验证非枚举元信息正确保留来源与各来源真实顺序，普通回调/Source 身份与无输入原对象仍成立。
- 再接入 Utils 与解释上下文，Flow 只显式声明映射；不把优先级判断留在组件中，也不增加 DSL、State、Effect、registry 或缓存。
- 最后运行真实 Flow、公共绑定及其他组件回归、类型检查和发布构建。新增测试针对实际冲突，不镜像内部数据结构。

必须拒绝的错误结果：

- 直接 `$direction="column"` 与直接 `$row` 同时存在却得到 row。
- 直接 `$direction="column"` 与显式配置 `$row: true` 同时存在却得到 column。
- 直接字段先 `$column` 后 `$row`，显式对象先 `$row` 后 `$column`，却沿最终 spread 键位置得到 row；正确为显式 column。
- 直接快捷被显式同名 false/undefined 遮盖后仍然激活。
- 同层 column 后 row 虽方向恢复，却残留 nowrap 或错误交叉轴对齐。
- Source 更新失效、Controller 替换后被原输入补回，或多次调用方向解释产生中间效果。

还须验证仅显式对象、直接输入、两者组合、快捷 true/false 切换、Controller 清空和对象键顺序反转。有效胜者只应用一次，Token 默认、节点身份及 Marker 清理保持。若需要按组件名分支、回读上游或加同步状态才能通过，停止该方法并回查职责。
