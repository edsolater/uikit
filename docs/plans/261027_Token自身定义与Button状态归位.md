# Token 自身定义与 Button 状态归位

## 目标与边界

依据 [Token 设计](../../src/style-system/doc/Token设计.md) 和用户本轮裁决：
普通属性通过 rules 的对象或 entry 自动声明；Token 通过 default、state、address 建立自身定义。
手动 declare 和外部 Token 赋值保留为 dangerous 操作，靠君子协定限制，不加运行时拒绝、警告或类型禁用。

本轮负责从定义到 Button 消费的整段链路，重写 Button 样式组织，并同步现役使用文档。
不保留用多个 rules 给已有 Token 重新赋值的组件写法，也不新增代理 Token 或公共 Button 配方包装。
底层已有自动声明与状态发布能力，保留其资源、modify、注册和显式逃生行为，不为表示架构变化而重造编译器。

## 全局图与职责

```text
材料与普通表达式
  → Token 定义【default、state、address 共同描述主体】
  → rules 属性消费【对象、Key entry、Mixin】
  → 编译器按实际消费自动建立默认及状态声明
  → CSS 条件与浏览器计算
```

| 载体                            | 本轮职责                                                                   |
| ------------------------------- | -------------------------------------------------------------------------- |
| Token 设计及现役 API/使用文档   | 区分推荐定义链路与允许但危险的外部重声明                                   |
| Button.style.ts                 | 颜色、内容、背景和阴影的变化在所属 Token 的 state 定义；rules 消费属性效果 |
| rules/declare 与 Token 编译准备 | 保持自动展开、按需定义及资源生命周期；公开说明危险操作边界                 |
| 行为测试                        | 证明不手动声明也可消费、状态与分类交集、作用域隔离、撤销及危险入口仍可用   |

Button 的材料选择、三种外观、危险语气、四档尺寸、存在感、禁用、焦点、loading 与主题引用继续有效。
状态不会自动顺序组合：危险色与 hover/active 的交集在定义中明确表达；不能假定 state 回调会读取另一个状态的取值。
组件导出的 Token 用于复用定义或参与表达式，不再推荐作为外部赋值控制句柄。

## 实施与验收

1. 修正“禁止”的含义，统一设计依据；补充不手动声明的浏览器测试。
2. 重写 Button 定义，让分类和交互变化由 Token 自动发布；退出原 Token 赋值 rules。
3. 同步现役接口、组件规格和示例，不改写已完成历史 Plan。
4. 通过全量单元、浏览器、类型检查和构建，审查入口是否仍保留危险操作且没有新增拦截。

验收必须覆盖 normal/plain/filled 与 danger、hover/active、disabled 的交集、主题引用及局部新定义的显式属性消费。
不能只凭文件变短、样式文本出现或测试个数判定完成；不得削弱有效行为断言或增加超时来掩盖失败。
全部必要证据通过且独立复查闭环后停止，不扩展为整套样式引擎的无关重构。
