# 颜色处理公式

材料用 `environmentSensitivities` 表达接受影响的比例，可用 `environmentTargets.lightness` 定义自己的明度适应目标。

## 材料的环境感知

```ts
interface ColorEnvironmentSensitive {
  lightness?: number | ((base: Readonly<OKLCH>, environment: Readonly<ColorEnvironment>) => number)
  chroma?: number | ((base: Readonly<OKLCH>, environment: Readonly<ColorEnvironment>) => number)
  hue?: number | ((base: Readonly<OKLCH>, environment: Readonly<ColorEnvironment>) => number)
}
```

- `base` 是这份材料自身当前的 OKLCH，不是环境色，也不等于业务分类“原色”。
- `environment` 是多份贡献合成后的环境。
- 数值与函数结果都表示受影响的比例：0 不响应，1 完全接受环境作用；省略为 0。
- 各通道独立，但每个感知函数都能读取全部自身色值，包括色相。
- 材料不另存偏移量；没有第二份 `sensitivity` 属性。

例如，仅用于演示根据自身色相变化的感知规则，不是自然界的通用规律：

```ts
environmentSensitivities: {
  lightness: 0.8,
  chroma: base => 0.2 + 0.4 * (
    1 + Math.cos((base.hue - 30) * Math.PI / 180)
  ) / 2,
}
```

自身色相 30° 时彩度感知为 0.6，210° 时为 0.2。改变材料自身色相后，下次环境求值重新计算比例。

## 当前环境作用公式

多环境合成见[环境叠加公式](环境叠加公式.md)。明度默认向环境明度靠近，也可由材料提供固定或动态目标；彩度、色相仍向环境目标靠近：

```text
感知比例 s = environmentSensitivities(base, environment)
目标 t = 材料明度目标（仅明度可选）或环境 tint
环境变化量 Δ = (t - base) × influence
当前值 = base + Δ × s
```

`environmentTargets.lightness` 可以是有限数值，也可以是 `(base, environment) => 数值`，在本次求值时读取当前材料色值与合成环境。省略则使用环境明度。

`influence` 是环境的外部作用强度，缺省为 1；不是第二份材料感知。缺少 `tint` 的通道，或感知为零，不改变自身值，也不求材料目标。色相用最短角差，最后回绕；明度限制在 0～1，彩度不低于 0，结果不舍入。Alpha 独立保留。

```ts
/** 求当前色值；所有通道都读取同一份材料自身 base。 */
function evaluateColor(material, environment) {
  const { base, environmentSensitivities } = material
  const result = { ...base }
  for (const channel of ['lightness', 'chroma', 'hue']) {
    const environmentTarget = environment.tint?.[channel]
    if (environmentTarget === undefined) continue
    const rule = environmentSensitivities?.[channel]
    const response = typeof rule === 'function' ? rule(base, environment) : rule ?? 0
    if (response === 0) continue
    const target = channel === 'lightness'
      ? evaluateLightnessTarget(material.environmentTargets?.lightness, base, environment)
      : environmentTarget
    let difference = target - base[channel]
    if (channel === 'hue') difference = ((difference % 360 + 540) % 360) - 180
    result[channel] = base[channel] + difference * (environment.influence?.[channel] ?? 1) * response
  }
  return { ...material, base: result } // 限制通道范围，保留材料信息，不保存环境。
}
```

applyEnvironment 返回颜色材料：更新 base，保留目标、感知规则、Alpha 与用途，不保存本次环境。再次应用时，当前 base 就是新的计算起点。

## 工具如何保留规则

- 通道工具改变自身 `base`，环境目标与感知函数保留，下次求值读取新值。
- `mix` 按来源权重合成感知规则；动态函数不提前求值，读取混合材料自身 `base` 与合成环境。缺省规则按 0 参与。
- 来源包含明度目标时，`mix` 合成目标 `T = Σ(w × s × t) / Σ(w × s)`；`w` 为材料权重，`s` 为当前明度感知，`t` 为材料目标或环境明度。零感知来源不求目标；总感知为零时不产生环境响应。这不表示材料混合与环境求值满足任意交换律。
- `emphasis` 按下方公式调整材料感知，动态规则先在求值时计算，再调整比例。自身 `base` 同时参与颜色处理，Alpha 与用途保留。
- 正强调保留材料明度目标；负强调按同一推进比例 `p` 将目标褪向本次环境明度：`新目标 = 原目标 + (环境明度 - 原目标) × p`。新目标函数在下次求值时读取当前环境，不保存强调时的旧环境。
- Purpose 的 Level 是用途分类维度，不是上述函数的处理量。

## 强调处理公式

`emphasis(color, environment, level)`：正级越近越清晰，负级越远越褪色，0 原样返回。整数用于色阶；小数沿同一曲线取样，供连续过渡与验证。级数必须有限。

参照环境不追加贡献，不施加 `influence`。Alpha、用途与材料感知保留；环境求值仍由 `applyEnvironment` 负责。

### 连续推进

```text
t = tanh(0.7 × abs(level))³
颜色坐标 = 基底坐标 + (目标坐标 - 基底坐标) × t
```

- `0.7` 是本轮级差参数：±1 推进约 22%，±2 约 69%；不是自然常数。
- 三次方让 0 两侧的速度、加速度都趋于 0；即使两侧目标不同，路径也达到 C² 连续。0 精确经过基底，不取端点平均。
- 曲线平缓起步、加速后再减速，逐渐接近端点；不在有限级数处截断或硬夹紧。平滑不代表视觉已经认可。

连续颜色坐标为 `L、a = C cos(H)、b = C sin(H)`，材料仍以 OKLCH 储存。色相按圆周融合；穿过无彩点时 H 可以换方向，但实际颜色路径连续，不把不可见的 H 当作颜色跳变。

### 两端如何确定

| 方向 | 明度目标 | 彩度、色相目标 |
| --- | --- | --- |
| 正级彩色 | `L目标 = L + 0.15 × L × (1 - L)` | `C目标 = 1.3 × C`；保持自身 H |
| 正级灰色 | 不暗于环境时趋白，否则趋黑；缺少环境 L 时以 0.5 为参照 | 不增加彩度 |
| 负级 | 环境 L，缺省保留自身 L | 环境 C、H；缺省通道保留自身值 |

正级参数是本轮候选：`0.15` 让中间明度最多增加约 0.038，越接近黑白端点越少推；`1.3` 表示清晰端点增加 30% 自身彩度。有限级数只推进其中一部分。参数不超过两位有效数字，计算结果不舍入。

彩色正级增强自身颜色，不按背景亮暗选择压黑，也不寻找显示色域上限。灰色没有彩度可增强，暂以明暗差增加辨识，需单独看图判断。

负级联合融合 L、a、b；自身与环境的颜色差乘以 `1 - t`，最终趋零。环境越接近无彩，色相牵引自然越轻；相反色相的融合可能经过无彩点。

### 环境感知

原感知比例为 `s`，沿相同曲线调整：

```text
正级：s' = s × (1 - t)
负级：s' = s + (1 - s) × t
```

动态规则保留到求值时，先读取处理后的自身 base 与合成环境，再调整比例。任意用户规则本身若不连续，后续环境求值不自动获得连续性；本函数的 C² 保证针对自身颜色路径及固定感知比例的调整。

```text
0 级：原样返回
根据正负方向确定端点
按连续推进量融合颜色坐标，再转回 OKLCH
包裹环境感知规则，保留材料其他信息
```

### 入口与显示边界

入口依次呈现：确定强调目标 → 计算平滑推进量 → 过渡颜色 → 调整环境感知。各步骤的具体计算留在同文件的内部函数中。

`emphasis` 只计算颜色信息，不转换 RGB、不搜索或裁切显示色域；显示范围与映射由显示层负责。可视化直接以 CSS OKLCH 呈现，因此超出屏幕色域的颜色可能被浏览器映射，不能把映射后的效果当作函数计算值。

参数依据、历史试验与视觉反馈见 [Emphasis 探查记录](Emphasis探查记录.md)。
