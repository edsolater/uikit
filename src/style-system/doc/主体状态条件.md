# 怎样使用主体状态

需要同一材料在hover、active等主体状态下反馈时，把状态写在Variable中，再交给效果API消费。本页解释[自身状态](behaviors/样式状态只由变量自身承担.md)和[状态名称](behaviors/状态名称登记必须明确且无歧义.md)的用法；名称、次序、合法输入及错误均由行为篇负责。

## 名称与顺序

内置hover、active、focus等可以直接用于states。多个材料确实需要共用自定义名称时，再用stateCondition(name, condition)登记；只有一次用途也可以直接写条件。名字是否合法、直接条件与普通Rules字符串的区别见[名称登记](behaviors/状态名称登记必须明确且无歧义.md)。

需要焦点提示时，本例使用focus快捷项；它与focusVisible、原生whenFocus各有什么含义，见[确定状态](behaviors/同时成立的状态必须有确定结果.md)。这不是让鼠标取得焦点就必定绘制轮廓。

## Variable自己提供反馈

```ts
const feedbackColor = variable('red', {
  name: 'feedback-color',
  states: { hover: 'pink', active: 'darkred' },
})
rules('.Feedback', [[key('color'), feedbackColor]])
```

本例元素普通为红色、悬停粉红、按下深红。使用处仍消费feedbackColor；实际行为见[自身状态](behaviors/样式状态只由变量自身承担.md)，多个状态同时成立及禁用分别查[次序](behaviors/同时成立的状态必须有确定结果.md)、[禁用反馈](behaviors/禁用主体不接受交互反馈.md)。这里不以声明条数解释效果。

```text
一个新材料需要复用反馈：在它的Variable中选择states
页面只使用现有反馈：直接消费该Variable
需要位置或屏幕条件：在Rules中选择普通Condition
```

## 派生定义复用状态

另一个材料要沿用已有默认与反馈时，用source.derive(value, nameOrOptions)表达差异；完整API及创建时复用见[派生行为](behaviors/延伸样式保留来源且允许覆盖.md)，可照用例子见[Variable教程](变量定义与消费.md#derive的定义与状态复用)。

## 组合普通内容

混色或Value包装可以使用feedbackColor，再由浏览器取得当前颜色。本页不定义另一种状态传播规则，组合的响应见[当地输入行为](behaviors/派生结果跟随当地输入变化.md)；维护状态路径和选择器权重实现时再读[架构](../architecture.md#状态与变量接入)。
