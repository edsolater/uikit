# 怎样使用主体状态

本文按 [Token 设计](Token设计.md) 的目标接口说明用法，源码已完成迁移。状态边界见 [state 与条件选择](behaviors/states与条件选择.md)。

## 共享条件与局部分类

可复用的组件分类条件位于 pieces/conditions/profile.ts：外观 whenFilled、whenOutlined、whenPlain，语气 whenToned、whenDanger，存在感 whenSoft、whenStrong，尺寸 whenSmall、whenLarge、whenXlarge。
它们是 StateCondition，只匹配 data 属性，不持有组件默认值、颜色配方或 Profile 运行时对象。
interaction.ts 提供 whenHover、whenActive、whenDisabled、whenEnabled、whenLoading 等交互与状态条件。
pieces/conditions/environment.ts 提供 whenDarkTheme，匹配 data-theme="dark"，以及 whenReducedMotion，匹配 prefers-reduced-motion: reduce 媒体条件；主题和动效 Token 可直接复用这些环境条件。
whenSoft 只表示 soft 分类，与交互、禁用等条件独立匹配。

共享条件可直接进入 rules 的地址，也可直接作为 Token state 的 entry 条件。
StateCondition 就是单个 { header } 条件对象；各 Pieces 条件文件同时提供预置对象和快捷名表，由根 state-condition-registry.ts 汇总为 stateConditionRegistry。交互、外观、语气、强调、尺寸和环境条件均有现成快捷名，例如 hover、enabled、loading、outlined、danger、strong、small、darkTheme。
组件通过根入口 stateCondition(input) 局部定义分类，无须全局注册；直接使用条件对象，不读取 header 或裁剪字符串：

```ts
const whenCompact = stateCondition('&[data-density="compact"]')
const spacing = token('8px', {
  address: '.Panel',
  state: [
    [whenCompact, '4px'],
    ['hover', '2px'],
  ],
})
rules('.Panel', { gap: spacing })
rules(['.Panel', whenCompact], { 'align-items': 'center' })
```

共享定义减少重复选择器，局部定义保留组件协议；分类的具体视觉取值仍由消费组件决定。

## Token 提供状态反馈

```ts
const feedbackColor = token('red', {
  name: 'feedback-color',
  address: '.Feedback',
  state: { hover: 'pink', active: 'darkred' },
})
rules('.Feedback', [[key('color'), feedbackColor]])
```

普通为红色、悬停粉红、按下深红。消费处使用同一个 Token，状态规则在 address 指定的位置表达；多个状态同时成立时遵守主体状态的条件与顺序约定。

state 字符串只表示静态预置快捷名，如 hover、active、focus。快捷名映射只由 Style System 所属 Pieces 条件模块维护，由根表汇总；组件的临时 whenComponentState 通过 stateCondition 创建后直接作为 state 条件，无须也不应登记全局简写。未定义名称及原始 CSS 字符串在创建 Token 时立即报错；原始选择器或媒体条件一律通过对象 entry 输入。rules 字符串地址不查快捷表，'hover' 仍是标签选择器。

state 的书写优先级按层次区分，不禁止另一种合法输入：

| 层次         | 优先写法                                 | 原因                                     |
| ------------ | ---------------------------------------- | ---------------------------------------- |
| 组件         | 静态预置快捷名；没有快捷名时使用条件对象 | 快捷名稳定，业务读取直接                 |
| Style System | 引用由 stateCondition 定义的条件变量     | 条件集中定义并复用，修改定义不必逐处改写 |

rules 地址不查状态快捷名表，复用主体条件时仍传条件对象，例如 stateConditionRegistry.outlined、stateConditionRegistry.loading；不能直接传 'outlined' 或 'loading' 期待状态快捷名含义。具体写法见[样式文件写法](../../../docs/style/样式文件写法.md#状态与定义组合)。

whenHover、whenActive 及同义字符串只判断交互状态；whenEnabled、whenDisabled 分别判断可用与禁用状态，各条件独立匹配。焦点快捷名 focus 仍表示 focus-visible，whenFocus 对象表示原生 focus。

## State 独立复用

State 输入支持快捷名对象、Map、单个 [静态预置快捷名 | StateCondition, 取值] entry，以及这些形式的任意嵌套数组或 Iterable。容器按顺序展开，entry 保持配对；同 header 后值覆盖前值并保留首次位置。解析后已定义的 Token.state 统一为 Map，可直接参与组合；手动读取时使用 Map 迭代。新材料组合后返回 Token，不引入继承类型或用途成员表。

组合表达式中的 feedbackColor 只提供其坍缩结果，不复制来源状态；直接 token(feedbackColor, options) 则继承定义并合并追加 state。

## 修改与坍缩时序

也可以在明确的 hover、active 等条件下登记 modify。它使目标需要 CSS variable 身份，缺少名称则自动生成。onFirstScan 同样可以返回包含 modify 的规则，编译器在 Token 坍缩前完成相关修改的读取，不限定激活波数。

CSS 层叠仍由浏览器决定，不因统一 Token 模型而将祖先公式搬到后代重算。计算需要在哪个元素读取输入，就在相应 address 建立定义。
