# 怎样使用主体状态

本文按 [Token 设计](Token设计.md) 的目标接口说明用法，源码已完成迁移。状态边界见 [state 与条件选择](behaviors/states与条件选择.md)。

## Token 提供状态反馈

```ts
const feedbackColor = token('red', {
  name: 'feedback-color',
  address: '.Feedback',
  state: { hover: 'pink', active: 'darkred' },
})
rules('.Feedback', [[key('color'), feedbackColor]])
```

普通为红色、悬停粉红、按下深红。消费处使用同一个 Token，状态规则在 address 指定的位置表达；多个状态同时成立时遵守主体状态的条件与顺序约定。

内置 hover、active、focus 等名称可以用于 state。只有一次用途也可以直接写条件；多个材料确实需要共享自定义名称时，再通过 stateCondition 登记。Rules 字符串是普通 CSS 条件，不自动带有快捷状态的禁用抑制或中央顺序。

## State 独立复用

State 可以是独立的状态规则对象，也可直接写入 token()。新材料要复用反馈时，普通函数读取并组合相应 default、state 和配置，返回新 Token；不引入专门的继承类型或用途成员表。

组合表达式可以直接引用 feedbackColor。引用消费它的坍缩结果，不复制来源状态，也不因放进另一个 Token 就换成复制定义。

## 修改与坍缩时序

也可以在明确的 hover、active 等条件下登记 modify。它使目标需要 CSS variable 身份，缺少名称则自动生成。onFirstScan 同样可以返回包含 modify 的规则，编译器在 Token 坍缩前完成相关修改的读取，不限定激活波数。

CSS 层叠仍由浏览器决定，不因统一 Token 模型而将祖先公式搬到后代重算。计算需要在哪个元素读取输入，就在相应 address 建立定义。
