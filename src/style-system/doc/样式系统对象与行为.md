# Style System 使用入口

需要核对输入、结果与生命周期时，从[__spec.md](behaviors/__spec.md)按使用任务查找；初次编写业务样式可从下方例子开始。

Style System 用可复用材料组织样式：先决定要表达的效果，再选择组成部件，把同一份规则用于不同元素。第一次使用先读[从按钮需求组合样式](从按钮需求组合样式.md)：用现有Button完成排列、危险动作、反馈与区域定制。本文用于遇到新需求后比较部件和查API，不要求把每种部件都用一遍。

## 先让一个例子生效

以下 TypeScript 例子用于 `.style.ts`，从独立样式入口 `@edsolater/uikit/style-system` 导入。

```ts
import { key, rules } from '@edsolater/uikit/style-system'

rules('.Example', [[key('width'), '24px']])
```

页面提供 `<style id="css-root"></style>`，元素设置 `class="Example"`。应用入口导入样式后、渲染前统一挂载：

```ts
import { cssRoot } from '@edsolater/uikit/style-system'
import './example.style'

cssRoot.mount()
```

效果：Example 元素宽度为 24px。后文例子沿用这一接入方式，只替换样式定义；每段都给出自己的 import。完整的样式文件、JSX与挂载入口见[按钮教程](从按钮需求组合样式.md#可照用的三个文件)。

```text
在样式文件选择元素并声明宽度 → 应用导入该文件并挂载 → 元素按 24px 显示
```

## 先判断是否需要另一种部件

固定值可以直接写；现成Button已有的危险语气和交互优先通过Props使用。只有新增需求要求不同职责时，才引入下面的部件。

| 新增需求 | 选择与原因 | 尚不需要什么 |
| --- | --- | --- |
| 一次尺寸计算或混色 | Expression直接放在属性值中 | 没有共享覆盖与状态，就不创建Variable |
| 原始数据有自己的格式，换数据时格式不变 | Value保存数据和格式；withContent沿用格式 | 不是做CSS作用域主题，也不拥有状态 |
| 多处共享一个可按作用域覆盖、带状态的内容 | Variable；各处引用同一对象 | 不需要先创建Name再复用定义 |
| 先定转换和状态，多个基础分别生成内容 | 普通转换函数：填入基础的配方是样式骨骼 | 一次计算直接用Expression即可 |
| 变化本身要被独立命名、声明、在区域中覆盖 | Modification + adjust；来源与变化各自可选 | 只是同一转换接受不同基础，不必升级 |
| CSS作者也要在CSS中反复调用同一具名参数函数 | CSSFunction生成@function与调用 | 只在TypeScript组合一次值，用Expression更直接 |

例如，把某个基础色混黑一次用colorMix；多种材料都要沿用同一转换与自身状态时用普通转换函数；主题还要独立换“变化配方”、让根据地上的结果读取配方时才用Modification/adjust。后两者都能复用变化，但给调用方保留的控制点不同，不按“计算复杂程度”升级。

```text
只出现一次：直接值或Expression
格式需要随数据复用：Value
已有引用要按位置或状态变化：Variable
多个基础共享转换与状态：普通函数创建Variable
变化本身还要独立覆盖：Modification + adjust
需要CSS具名函数供CSS调用：CSSFunction
```

## 声明目标：Key

按[rule与rules的登记和撤销.md](behaviors/rule与rules的登记和撤销.md)的约定，Key可用于普通属性，也可约定重复贡献怎样合成。普通赋值只需key('width')；需要完整效果时选Mixin，不必逐条展开属性。

```ts
import { key, rules } from '@edsolater/uikit/style-system'

rules('.IconButton', [[key('width'), '32px']])
```

效果：IconButton宽32px。只是赋一个属性，不必先学习join。rules的二元声明目标使用Key或Variable对象，不能照抄为['width', '32px']。

只有需求明确为“两个来源分别贡献层级偏移，最终必须相加”时，才显式约定join：

```ts
import { key, rules } from '@edsolater/uikit/style-system'

const stack = key('z-index', {
  join: values => values.reduce((sum, item) => sum + Number(item.content), 0),
})
rules('.Stack', [[stack, 2], [stack, 3]])
```

Stack的层级是5。普通Key不会自动求和；没有相加需求时不用这段配置。

```text
只设宽度：Key配值 → 32px
确实有独立层级贡献：先约定求和 → 2与3组成5
```

## 条件与状态

Condition选择位置或环境，states用于主体反馈，二者如何解释见[states与条件选择.md](behaviors/states与条件选择.md)。本例直接用内置hover；多个材料需共用新名称时，再用stateCondition。

```ts
import { key, media, rules, variable } from '@edsolater/uikit/style-system'

const width = variable('8px', {
  name: 'doc-state-width', address: '.StateDemo', states: { hover: '16px' },
})
rules('.StateDemo', [[key('width'), width]])
rules([media('(min-width: 800px)'), '.StateDemo'], [[key('height'), '20px']])
```

效果：StateDemo正常宽8px，悬停时宽16px，禁用时不触发该内置hover反馈；视口至少800px时，高度为20px。内置 `hover`、`active` 等快捷状态可直接用于 states；`whenHover` 等现成 Condition 用于 Rules 地址。普通 Rules 中写 `'hover'` 是标签选择器，不是快捷状态。多个新材料确实要共享自定义状态名时再用stateCondition注册；普通hover无需注册。

```text
需要悬停反馈：用内置hover状态 → 正常8px、悬停16px → 视口宽度要求另用media条件
```

## 内容包装：Value

需要让新数据沿用原格式时，使用[Value与Expression.md](behaviors/Value与Expression.md)中的Value/withContent；只写4px不用额外包装。局部覆盖或状态需求则选择Variable。

```ts
import { key, rules, value } from '@edsolater/uikit/style-system'

const duration = value<number>(200, { toCSSString: ms => `${ms}ms` })
const slower = duration.withContent(400)
rules('.ValueOriginal', [[key('transition-duration'), duration]])
rules('.ValueNext', [[key('transition-duration'), slower]])
```

效果：ValueOriginal过渡时长0.2秒，ValueNext为0.4秒；原数据仍为200。`withContent` 创建新包装，沿用格式，适合“数据变了、表达方式相同”的情况。

```text
业务时长单位是毫秒 → 用Value附上ms → 新时长沿用格式 → CSS分别得到200ms和400ms
```

## 内容表达式

本例用add/multiply计算尺寸、colorMix混色、oklch调整颜色，解释[Value与Expression.md](behaviors/Value与Expression.md)的输入结果。一次组合直接使用表达式；变化还要独立命名、声明或覆盖时，再选择Modification。

```ts
import { add, colorMix, key, oklch, rules } from '@edsolater/uikit/style-system'

rules('.ExpressionDemo', [
  [key('width'), add('32px', '8px')],
  [key('color'), colorMix(['black', 0.5], 'white')],
  [key('background-color'), oklch({ lightness: 0.6, chroma: 0, hue: 0 })],
])
```

效果：内容宽32px加8px空间，总宽40px；文字是黑白各半的 Oklab 混色；背景是明度0.6、彩度0的灰色。对应 CSS 内容为 `calc(32px + 8px)`、`color-mix(in oklab, black 50%, white)`、`oklch(0.6 0 0)`。

```text
选择已有计算或混色工具 → 传入尺寸、比例或通道 → 把结果用于具体属性
```

只有现成工具无法表达内容格式时才需要 `createJSSContent`；自定义工具的协议见[内容工具公约](../pieces/contents/functions/SPEC.md)，不必为了使用普通表达式阅读它。

## 共享内容：Variable与Name

共享覆盖需求使用Variable，另建有差异的定义使用variableFrom。创建、具体引用与复用边界见[Variable的创建与复用.md](behaviors/Variable的创建与复用.md)，下面说明怎样选择。

```ts
import { declare, key, rules, variable } from '@edsolater/uikit/style-system'

const actionHeight = variable('32px', 'doc-action-height')
rules('.SharedAction', [[key('min-height'), actionHeight]])
rules(['.CompactPanel', '.SharedAction'], [declare(actionHeight, '24px')])
```

效果：SharedAction引用actionHeight，按[Variable的创建与复用.md](behaviors/Variable的创建与复用.md)取得32px；CompactPanel显式选择24px，属性仍引用同一对象。前者是默认消费，后者是实际区域选值，不需要另列默认依赖清单。没有共享或覆盖需求时直接写32px就够了。

规则骨骼用普通函数表达：接收具体基础后创建Variable。例如lineColor(base)返回引用该基础和lineStrength的线条实体；[完整例子](变量定义与消费.md#用普通函数保存转换规则)展示从表面创建线条及CSS求值边界。函数与variableFrom分别负责转换规则和已有定义复用。

Name与variableFrom不是普通创建的前置步骤。Name用于两处定义先约定同一CSS名字；variableFrom用于另建一份有自身差异的定义。例如大号操作沿用默认高度与hover规则，只把默认高度换成40px：

```ts
import { key, rules, variable, variableFrom, variableName } from '@edsolater/uikit/style-system'

const heightName = variableName('doc-named-height')
const normalHeight = variable('32px', { name: heightName, address: '.NormalHeight', states: { hover: '36px' } })
const largeHeight = variableFrom(normalHeight, '40px', { name: 'doc-large-height', address: '.LargeHeight' })
rules('.NormalHeight', [[key('min-height'), normalHeight]])
rules('.LargeHeight', [[key('min-height'), largeHeight]])
```

效果：常态最小高度32/40px；悬停时都沿用36px规则。原hover规则固定为36px，因此大号悬停会从40px变为36px；variableFrom不会把固定状态按新默认值自动放大。新名字让大号定义独立；不传新名字时variableFrom沿用原名，适合同名覆盖，不能把它当成独立角色。创建时继承不是以后自动同步母体配置。

```text
同一内容要在区域换值：共享Variable并declare
另一个定义要沿用规则但有自身差异：variableFrom，并明确是否用新名字
只是引用：直接用Variable即可，Name不是额外必经层
```

## 同条件的并列声明

新面板有表面、文字和边线三个目标，本例用同一rules并列declare解释[共享主题与组件颜色控制.md](behaviors/共享主题与组件颜色控制.md)。哪些颜色随另一个来源变化，再按[CSS作用域与层叠.md](behaviors/CSS作用域与层叠.md)组织。

```ts
import { boundary, color, declare, rules, variable } from '@edsolater/uikit/style-system'

const panelSurface = variable('white', 'doc-panel-surface')
const panelContent = variable('black', 'doc-panel-content')
const panelLine = variable('gray', 'doc-panel-line')
rules('.Panel', [
  color({ background: panelSurface, content: panelContent }),
  boundary({ border: ['1px', 'solid', panelLine] }),
])
rules(['.Panel', '&[data-danger]'], [
  declare(panelSurface, 'red'),
  declare(panelContent, 'white'),
  declare(panelLine, 'pink'),
])
```

效果：Panel默认白底黑字灰边，加data-danger后红底白字粉边。去掉其中一条危险声明，就只保留那个目标的原值；若颜色明确引用另一个Variable，则仍按显式依赖随动。现有Button已处理danger，无需复制这份面板规则。

```text
三个独立颜色要一起变：选择同一条件 → 并列三个declare
只改一个：只声明那个目标
需要随某个基础变化：让内容直接引用该基础Variable
```

## 局部定义与修改

本例解释[adjust与modify.md](behaviors/adjust与modify.md)：固定当地值用declare，沿基础累计变化用modify。这里用两个显式根据地展示一个完整数值例子，精确边界由行为篇负责。

```ts
import { add, declare, key, modify, rules, variable, variableFrom, type ExpressionModification } from '@edsolater/uikit/style-system'

const amount = variable(1, { name: 'doc-amount', address: '.DocButton', states: { hover: 10 } })
const panelAmount = variableFrom(amount, 20, { name: 'doc-panel-amount', address: '.DocPanel' })
const increase = (delta: number): ExpressionModification => ({
  type: 'expression', detail: current => add(current, delta),
})
rules('.DocButton', [[key('z-index'), amount]])
rules(['.DocButton', '&:hover'], [modify(amount, increase(3))])
rules(['.DocButton', '&:focus'], [modify(amount, increase(2))])
rules('.DocPanel', [[key('z-index'), panelAmount]])
rules(['.DocPanel', '&:focus'], [modify(panelAmount, increase(4))])
```

| 使用处 | 条件 | z-index |
| --- | --- | --- |
| DocButton | 常态 | 1 |
| DocButton | hover | 13：状态基础10再加3 |
| DocButton | hover与focus同时成立 | 15 |
| DocPanel | focus | 24：局部基础20再加4 |

这些普通选择条件演示相对变化；可复用的主体反馈通常直接写在 Variable 的 states。修改叠加、同一ID覆盖等边界见[adjust与modify.md](behaviors/adjust与modify.md)。

```text
创建变量时明确根据地 → 给不同条件配置增量 → 条件成立时沿该基础计算 → 其他作用域不受影响
```

## 独立变化与来源绑定

本例按[adjust与modify.md](behaviors/adjust与modify.md)，让两种来源复用一份透明度变化。仅做一次颜色运算直接用oklch即可；需要声明和覆盖变化本身时再用Modification，选adjust取得新结果，或modify改变已有局部基础。

```ts
import { adjust, color, declare, modification, rules, variable } from '@edsolater/uikit/style-system'

const halfOpacity = modification({
  name: '--doc-half-opacity', type: 'color', detail: { alpha: 0.5 },
})
const red = variable('red', 'doc-adjust-red')
const blue = variable('blue', 'doc-adjust-blue')
const redResult = adjust(red, halfOpacity)
const blueResult = adjust(blue, halfOpacity)
rules('.RedShade', [color({ content: redResult })])
rules('.BlueShade', [color({ content: blueResult })])
```

效果：两处分别保持红色、蓝色，透明度都为0.5；来源本身仍为不透明颜色。adjust返回新结果，不修改 red 或 blue。当前独立 Modification 支持颜色领域；数值增量使用上一节的 expression 修改材料。

```text
定义一份 50% 透明度变化 → 分别绑定红色与蓝色来源 → 使用两份结果 → 共享变化而保留各自来源
```

## 规则登记与句柄

临时效果保存自己的句柄，按[rule与rules的登记和撤销.md](behaviors/rule与rules的登记和撤销.md)更新或退出。下面展示单条替换与批量退出的写法。

```ts
import { compileCSS, key, rule, rules } from '@edsolater/uikit/style-system'

const single = rule('.Temporary', key('color'), 'red')
single.replace('blue')
const updated = compileCSS() // 包含 Temporary 的 color: blue
single.remove()
const removed = compileCSS() // 不再包含 Temporary

const batch = rules('.TemporaryBatch', [[key('width'), '12px'], [key('height'), '8px']])
batch.remove() // 两项一起撤销
```

效果：替换后文字声明为蓝色；撤销后本次登记不再出现在 CSS 中。句柄只管理自己的贡献，更新和删除后若需要页面立即改变，再由应用调用 mount。

```text
登记自己的样式并保存句柄 → 需要时替换或撤销 → 重新提交 → 其他登记继续存在
```

## 读取与提交样式

需要预览时用compileCSS，需要页面生效时用cssRoot.mount，完整副作用与失败边界见[Compile与挂载.md](behaviors/Compile与挂载.md)。下面沿用首次挂载方式演示12px宽度。

```ts
import { compileCSS, cssRoot, key, rules } from '@edsolater/uikit/style-system'

rules('.Mounted', [[key('width'), '12px']])
const cssText = compileCSS() // 包含 width: 12px；此时页面还没有新样式
cssRoot.mount() // 页面已有 style#css-root 时提交
```

效果：Mounted元素宽12px。原有宿主内容保留；新的生成或提交失败时保留上次成功结果。宿主缺失会报错，应用应在调用前提供它。

```text
准备样式宿主 → 登记样式 → 需要字符串时读取 → 需要页面生效时挂载
```

## CSS函数

需要在CSS里定义一个有名字、可接收不同参数的计算时使用CSSFunction，例如多个元素共享同一个尺寸算法。只组合一次尺寸时，直接用 multiply 更短；普通 TypeScript 函数返回表达式也不需要 CSSFunction。

定义、调用与返回内容的行为见[内容扩展与AST编辑.md](behaviors/内容扩展与AST编辑.md)、[Value与Expression.md](behaviors/Value与Expression.md)和[按需资源与同名替换.md](behaviors/按需资源与同名替换.md)。

```ts
import { cssFunction, key, rules } from '@edsolater/uikit/style-system'

const innerSize = cssFunction('--doc-inner-size(--size <length>, --inset <length>) returns <length>', [
  [[], 'result', 'calc(var(--size) - var(--inset) * 2)'],
])
rules('.FunctionDemo', [[key('width'), innerSize('100px', '8px')]])
```

CSS结果：定义 `@function --doc-inner-size(...)`，使用处为 `width: --doc-inner-size(100px, 8px)`；支持该CSS语法的浏览器得到84px。`@function` 仍属[有限可用能力](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@function)，不能把生成文本等同于所有浏览器都能执行。

```text
定义具名尺寸算法 → 用不同参数调用 → 将调用结果用作宽度 → 由支持该语法的浏览器计算
```

## 动画

把一组关键帧和动画参数一起复用时，使用 animationName 与 animationValue；前者定义动作，后者选择时长、节奏等播放配置。普通静态颜色或尺寸不需要动画材料。

本例解释[Value与Expression.md](behaviors/Value与Expression.md)与[按需资源与同名替换.md](behaviors/按需资源与同名替换.md)，不额外制定动效偏好策略。

```ts
import { animationName, animationValue, condition, key, rules } from '@edsolater/uikit/style-system'

const fade = animationName('doc-fade', [
  [[condition('from')], 'opacity', 0],
  [[condition('to')], 'opacity', 1],
])
rules('.Animated', [[key('animation'), animationValue({
  name: fade, duration: '1s', easing: 'linear', fillMode: 'forwards',
})]])
```

效果：元素在1秒内从透明变为不透明，结束保持不透明；线性播放时0.5秒处透明度为0.5。CSS包含对应 `@keyframes doc-fade`。实际播放依赖浏览器动画能力及应用是否另行设置减少动效规则；本例没有自动增加这类策略。[animation参考](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/animation)

```text
定义起止透明度 → 选择1秒线性播放与结束保持 → 把动画用于元素 → 元素逐渐显现
```

## 完整效果：Mixin

Mixin让调用处表达内容居中、加边界、可点击等目的，本表按[rule与rules的登记和撤销.md](behaviors/rule与rules的登记和撤销.md)解释具体输入结果。只设置一个属性时用Key即可；反馈组合参照[states与条件选择.md](behaviors/states与条件选择.md)。

```ts
import { boundary, clickable, color, contentLayout, elevation, innerText, rules, size } from '@edsolater/uikit/style-system'

rules('.LayoutDemo', [contentLayout({ mode: 'center', gap: '8px', padding: ['4px', '12px'] })])
rules('.TextDemo', [innerText({ fontSize: '16px', emphasis: 700, leading: 1.5 })])
rules('.SizeDemo', [size({ minHeight: '32px' })])
rules('.BoundaryDemo', [boundary({ border: ['1px', 'solid', 'red'], radius: '4px' })])
rules('.ColorDemo', [color({ background: 'white', content: 'black' })])
rules('.ElevationDemo', [elevation('0 2px 4px black')])
rules('.ClickDemo', [clickable({ address: '.ClickDemo' })])
```

| 效果API | 使用目的 | 本例可观察结果 |
| --- | --- | --- |
| contentLayout | 统一内容排列与间距 | inline-flex内容双向居中，间隔8px，内边距上下4px、左右12px；只配gap时不自动居中 |
| innerText | 统一文字层级与阅读节奏 | 字号16px、字重700、行高24px |
| size | 给控件设置尺寸约束 | 最小高度32px，不替调用者决定固定高度或宽度 |
| boundary | 区分轮廓与外形 | 1px红色实线边框、4px圆角 |
| color | 指定承载面与内容颜色 | 白背景、黑文字 |
| elevation | 表达浮起层级 | 水平偏移0、下移2px、模糊4px的黑色阴影 |
| clickable | 提供可点击的视觉反馈 | 正常指针为pointer；按下位移1px；禁用时指针为not-allowed并淡化；键盘焦点显示轮廓 |

clickable 的 address 指定反馈主体；省略时其内部 Variable 使用默认root根据地。clickable 是样式效果，不替组件绑定点击事件或实现键盘行为；交互能力由组件或Piv插件负责。透明度参数可选，省略时沿用通用禁用淡化。

```text
确定布局、文字或交互目的 → 为所需效果填写参数 → 在一份rules中组合 → 未选择的效果不附带改变其他属性
```

## 现成材料与角色

库中的Atom把常用尺度和视觉用途变成可复用材料，避免每个组件重新决定同一含义的值。组件用自己定义的Variable选择材料，分别控制承载面与文字等内容。

材料组合和区域选择参照[共享主题与组件颜色控制.md](behaviors/共享主题与组件颜色控制.md)、[CSS作用域与层叠.md](behaviors/CSS作用域与层叠.md)，以下数值仅解释这些材料用于本例的效果。

```ts
import {
  boundary, color, contentLayout, controlSize, fontWeight, multiply,
  innerText, rules, size, space, textSize, variable,
} from '@edsolater/uikit/style-system'

const materialSurface = variable('white', 'material-surface')
const materialContent = variable('black', 'material-content')
rules('.MaterialDemo', [
  color({ background: materialSurface, content: materialContent }),
  size({ minHeight: multiply(controlSize, 2 / 3) }),
  contentLayout({ gap: space }),
  innerText({ fontSize: textSize, emphasis: multiply(fontWeight, 7 / 4) }),
  boundary({ radius: '999px' }),
])
```

效果：本作用域白背景、黑内容，最小高度32px、间距8px、字号16px、字重700、胶囊圆角。局部角色赋值不会改其他组件的共享定义。

| 材料用途 | 代表材料 | 如何选择与使用 |
| --- | --- | --- |
| 间距与边界厚度 | space、boundaryWidth | 8px 与 1px 是不同物理用途的基准；其他取值相对基准计算 |
| 控件尺度 | controlSize | 48px 基准；现有 data-size 状态使用 2/3、4/3、5/3 比例 |
| 文字 | textSize、fontWeight | 16px 字号与 400 字重分别表达长度和字形粗细；字重不随字号缩放 |
| 外形 | radius | 4px 圆角基准；胶囊是组件外形，可直接使用 999px |
| 阴影 | shadow、shadowDistance、shadowColor | 场景由 card/popover/dialog/control 等 variant 表达；各层位移、模糊与颜色分别相对共同来源 |
| 用途色 | colorAction、colorBrand、colorGood、colorBad | 色相身份保持独立；surface/content/boundary 是应用部分，soft/strong 是同一对象状态 |
| 透明度与动效 | opacity、motionDuration、motionEasing | 基准透明度、时长、曲线各有物理职责；减少动效将时长归零，快慢由消费处相对计算 |

完整定义见[材料源码](../pieces/contents/atoms)。新材料不依赖旧 CSS，也不会仅因导入而挂载。组件用 `variableFrom(base, base, { name, address })` 保留对公共基准的引用，再将状态模板放到自己的地址；不要用 `.content` 复制初始值，切断运行时的基准联动。固定用途的比例可直接用 `multiply`，不必另造一个 Variable 或选择器。

```text
先选视觉用途与档位 → 将材料交给对应Mixin → 需要局部换色时声明组件角色 → 同一套语义继续用于其他组件
```
