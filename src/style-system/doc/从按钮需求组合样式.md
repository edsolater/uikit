# 从按钮需求组合样式

本文说明材料、Token 自身定义与属性消费怎样组合成页面样式。Button Props、页面布局与挂载方式沿用现有能力；Token 的默认与状态在定义处确定，属性声明由 rules 自动完成。

这里完成一排“保存／删除”按钮，再让审核页面有自己的视觉密度和配色。组件直接使用仓库现有 `Button`，不重新实现按钮：原生按钮语义、普通／危险语气、悬停反馈和禁用处理都已经存在。Style System 组合页面效果，独立定制通过新 Token 明确接入属性。

本文依据[rule与rules的登记和撤销.md](behaviors/rule与rules的登记和撤销.md)、[共享主题与组件颜色控制.md](behaviors/共享主题与组件颜色控制.md)和[states与条件选择.md](behaviors/states与条件选择.md)解释按钮需求与用法，不另行定义行为规范。

本文例子的样式 API 从 `@edsolater/uikit/style-system` 导入，Button 从 `@/components` 导入。下方三个文件和 HTML 宿主即可组织页面，不必先展开内部协议。

## 第一步：先把动作排在一起

需求是“保存和删除并排、按钮之间留出空隙”。先用现成 Button；它已经用布局、文字、尺寸、边界等 Mixin 组合好按钮本身。再给外面的 ActionRow 使用 `contentLayout`，只负责这排动作的排列。

这时不需要 Token：间隔固定为12px，没有共享身份、主题覆盖或状态要求。也不需要用 Key 逐条展开 flex 属性。下方样式文件的第一段就是全部新增布局。

效果：两颗按钮同排，间隔12px；Button 默认最小高度48px、内容居中。页面排列和按钮内部布局分别负责自己的范围。

```text
需要一排动作
    使用 Button 表达动作
    使用 contentLayout 表达容器排列
    固定间隔直接写 12px
没有要覆盖的共享值：不创建 Token
```

## 第二步：普通动作与危险动作

“删除”需要有破坏性语气。直接写 `<Button filled danger>`；“保存”写 `<Button filled>`。`filled` 决定填充外观，`danger` 决定动作语气，两者不是同一个选择。

Button 已经选择普通和危险的整套颜色材料，并把材料用于背景、内容及轮廓。不要再为这两个按钮创建另一套包装，也不要在页面手写危险色选择器来重做 `danger`。

效果：两个按钮尺寸和排列一致，删除使用危险配色；这里只改变组件 Props，不增加样式规则。下方的禁用删除仍使用 `danger`，因此禁用和语气可以同时成立。

```text
是执行动作：使用 Button
需要填充外观：加 filled
动作有破坏性：再加 danger
同一种按钮只是语气不同：复用组件已有材料选择
```

## 第三步：先复用已有悬停与禁用反馈

现在要求“两个按钮都能反馈悬停，禁用按钮不能执行动作”。这也已由 Button 提供：悬停／按下反馈跟随组件状态，禁用通过 `disabled` 传给原生 button，并显示禁用指针和淡化。

因此本步骤不新增状态注册、不写 `&:hover`、也不创建另一层规则对象。Button 内部已用 Token 的 `state` 保存共享反馈；页面继续使用同一个组件，就已经复用了它。鼠标停在禁用按钮上，不能把它恢复成可点击按钮。

效果：普通和危险按钮悬停时背景变化；禁用按钮透明度0.48、指针为not-allowed，点击不会触发 onClick。你若是在写一个尚无状态能力的新样式，才需要[参考入口的内置状态例子](样式系统对象与行为.md#条件与状态)。

```text
组件已经提供所需反馈：沿用 Button
禁用动作：传 disabled，不只降低透明度
只有新的样式值需要自己的反馈时：创建带 state 的 Token
```

## 共用主题来源，还是定义自己的局部样式

Button 自身引用 surfaceColor、contentColor 等共享材料。这些来源的实际 CSS 变化继续沿引用传递；Button 的外观、语气与交互在所属 Token 的 state 中完整定义。
需要设计共享主题时，在来源 Token 的 default、state、address 中表达主题，不在使用处重复为同一个 Token 赋值。

只改审核页按钮时，创建审核页自己的 Token，并明确把它接到选中的按钮属性。
新 Token 不会自动替换 Button 的内部引用；独立定义与属性消费是两件明确的事情。
也不需要分别声明背景色源、画布、强度等中间控制点。

## 第四步：审核页拥有自己的背景定义

需求增加：“审核页这排按钮最小高度改为 40px，普通按钮使用浅蓝背景，并有自己的悬停与按下反馈；危险按钮继续使用组件配色，其他页面不变。”

size 表达高度。reviewSurface 在审核页实际普通按钮的地址定义默认值和 state，rules 只消费它。
悬停、按下与禁用独立匹配；这里定义自己的背景反馈，不附加禁用排除。

## 三个文件怎样组织

`actions.style.ts`：定义紧邻消费，地址和取值只在 Token 定义处写一次。
rules 的对象与 entry 自动完成属性声明，不调用 declare，也不给 Button 导出的 Token 重新赋值。

```ts
import {
  contentLayout,
  rules,
  size,
  token,
} from '@edsolater/uikit/style-system'

rules('.ActionRow', contentLayout({ mode: 'center', gap: '12px' }))
rules(['.ReviewPanel', '.Button'], size({ minHeight: '40px' }))

const reviewSurface = token(
  {
    default: 'rgb(210, 230, 250)',
    hover: 'rgb(190, 215, 240)',
    active: 'rgb(170, 200, 230)',
  },
  { address: ['.ReviewPanel', '.Button:not([data-tone])'] },
)
rules(['.ReviewPanel', '.Button:not([data-tone])'], {
  'background-color': reviewSurface,
})
```

区域外不消费 reviewSurface，危险按钮也没有被选择；它们保留 Button 自己的定义。
这里改变最终背景属性，其余焦点、阴影、尺寸和原生禁用行为继续由 Button 负责。
如果内容颜色也需变化，再创建并消费对应定义，不隐式联动另一份 Token。

`Actions.tsx`：这里渲染 UIKit Button。组件自身静态导入它已有的样式。

```tsx
import { Button } from '@/components'
import './actions.style'

export function Actions() {
  return (
    <>
      <div class="ActionRow OutsideActions">
        <Button filled onClick={() => console.log('已保存')}>
          保存
        </Button>
        <Button filled danger>
          删除
        </Button>
      </div>
      <section class="ReviewPanel">
        <div class="ActionRow">
          <Button filled onClick={() => console.log('已保存')}>
            保存
          </Button>
          <Button filled danger>
            删除
          </Button>
          <Button
            filled
            danger
            disabled
            onClick={() => console.log('不应执行')}
          >
            不可删除
          </Button>
        </div>
      </section>
    </>
  )
}
```

`main.tsx`：先让静态样式登记，再挂载，最后渲染。HTML 中先提供 `<style id="css-root"></style><div id="app"></div>`。

```tsx
import '@/css/all-base.css'
import { render } from '@solidjs/web'
import { cssRoot } from '@edsolater/uikit/style-system'
import { Actions } from './Actions'

cssRoot.mount()
render(() => <Actions />, document.getElementById('app')!)
```

先只保留 `actions.style.ts` 的 ActionRow 规则，就能看到前三步；加上 ReviewPanel 的定义和属性消费，再比较区域内外。`compileCSS()` 可用于读取当前 CSS 文本；页面生效用 `cssRoot.mount()`。后续替换或撤销已登记规则后，再次 mount 提交结果。

## 新规则怎样复用，而不建立组

继续使用 Button 时，普通、危险和焦点已有组件配方，页面复用组件，独立定制通过自己的 Token 接入具体属性。新增线条用途时，可以写 lineColor(base) 这样的普通函数，返回引用基础材料的新 Token。需要组合 default、state 或其他配置时，函数读取需要的信息、组合后返回结果，不在 Token 内保存用途分支或加工历史。

把已有 Token 作为另一个 Token 的基础内容，只表达引用：

```ts
const componentSurface = token(globalSurface, {
  name: 'component-surface',
  address: '.Component',
})
```

此处 globalSurface 与普通表达式一样作为可坍缩内容消费，不自动复制它的状态或其他配置。新组件需要什么状态，直接提供或通过定义组合函数明确复用。

| 需求                           | 表达方式                   | 对已有引用的影响                         |
| ------------------------------ | -------------------------- | ---------------------------------------- |
| 根据基础材料计算另一用途       | 普通函数返回新 Token       | 新使用处选择结果，原对象不自动替换       |
| 组合已有默认与状态，再表达差异 | 函数读取配置后创建新 Token | 继承和覆盖由函数明确表达                 |
| 让已有 Button 在区域内换配色   | 新 Token 在区域属性中消费  | 只影响匹配位置，不改组件原 Token         |
| 条件下修改同一个目标           | modify                     | 目标需要 CSS variable 身份，缺名自动命名 |
| 多个独立颜色同条件一起换       | 并列属性 entry             | 各自消费明确内容，没有隐式成员配对       |

onFirstScan 可以引入带 modify 的规则，因此坍缩之前须先读完会影响相关 Token 的修改，不把处理限制在某个激活波次。组件消费者只关心目标与条件，无须自行生成 CSS 变量名称或维护附带声明列表。

完整模型见 [Token 设计](Token设计.md)，输入与生命周期见 [Token 的创建与复用](behaviors/Token的创建与复用.md)，定义组合和条件修改见 [Token 的定义组合与 modify](behaviors/Token的定义组合与modify.md)。
