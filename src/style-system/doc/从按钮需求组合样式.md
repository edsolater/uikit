# 从按钮需求组合样式

这里完成一排“保存／删除”按钮，再让审核页面有自己的视觉密度和配色。组件直接使用仓库现有 `Button`，不重新实现按钮：原生按钮语义、普通／危险语气、悬停反馈和禁用处理都已经存在。Style System 用于组合页面效果，以及操作组件明确公开的样式控制点。

本文依据[rule与rules的登记和撤销.md](behaviors/rule与rules的登记和撤销.md)、[共享主题与组件颜色控制.md](behaviors/共享主题与组件颜色控制.md)和[states与条件选择.md](behaviors/states与条件选择.md)解释按钮需求与用法，不另行定义行为规范。

本文例子在 UIKit 仓库内运行，定义 API 从 `@/style-system` 导入，Button 与公开控制点从 `@/components` 导入。包根 `@edsolater/uikit` 没有导出全部定义 API。你只需要本文中的三个文件和一个 HTML 宿主，不必先读对象契约。

## 第一步：先把动作排在一起

需求是“保存和删除并排、按钮之间留出空隙”。先用现成 Button；它已经用布局、文字、尺寸、边界等 Mixin 组合好按钮本身。再给外面的 ActionRow 使用 `contentLayout`，只负责这排动作的排列。

这时不需要 Variable：间隔固定为12px，没有共享身份、主题覆盖或状态要求。也不需要用 Key 逐条展开 flex 属性。下方样式文件的第一段就是全部新增布局。

效果：两颗按钮同排，间隔12px；Button 默认最小高度48px、内容居中。页面排列和按钮内部布局分别负责自己的范围。

```text
需要一排动作
    使用 Button 表达动作
    使用 contentLayout 表达容器排列
    固定间隔直接写 12px
没有要覆盖的共享值：不创建 Variable
```

## 第二步：普通动作与危险动作

“删除”需要有破坏性语气。直接写 `<Button filled danger>`；“保存”写 `<Button filled>`。`filled` 决定填充外观，`danger` 决定动作语气，两者不是同一个选择。

Button 已经选择普通和危险的整套颜色材料，并把材料用于背景、内容及轮廓。不要再为这两个按钮创建另一套包装，也不要在页面手写危险色选择器来重做 `danger`。

效果：两个按钮尺寸和排列一致，删除使用危险配色；这里只改变组件 Props，不增加样式规则。下方的禁用删除仍使用 `danger`，因此禁用和语气可以同时成立。

```text
是执行动作：使用 Button
需要填充外观：加 filled
动作有破坏性：再加 danger
同一种按钮只是语气不同：复用组件已有材料选择
```

## 第三步：先复用已有悬停与禁用反馈

现在要求“两个按钮都能反馈悬停，禁用按钮不能执行动作”。这也已由 Button 提供：悬停／按下反馈跟随组件状态，禁用通过 `disabled` 传给原生 button，并显示禁用指针和淡化。

因此本步骤不新增状态注册、不写 `&:hover`、也不创建另一层规则对象。Button 内部已用 Variable 的 `states` 保存共享反馈；页面继续使用同一个组件，就已经复用了它。鼠标停在禁用按钮上，不能把它恢复成可点击按钮。

效果：普通和危险按钮悬停时背景变化；禁用按钮透明度0.48、指针为not-allowed，点击不会触发 onClick。你若是在写一个尚无状态能力的新样式，才需要[参考入口的内置状态例子](样式系统对象与行为.md#条件与状态)。

```text
组件已经提供所需反馈：沿用 Button
禁用动作：传 disabled，不只降低透明度
只有新的样式值需要自己的反馈时：创建带 states 的 Variable
```

## 共用主题来源，还是只改这颗按钮

需要让实际引用主题的组件共用默认承载面、普通文字色时，使用globalSurfaceColor与globalContentColor。Button自己的画布引用并加工全局表面，普通内容引用全局内容；组件控制点仍然保留。

```ts
import { buttonSurfaceCanvas } from '@/components'
import { declare, globalSurfaceColor, globalContentColor, rules } from '@/style-system'

rules(':root', [
  declare(globalSurfaceColor, 'rgb(220, 230, 240)'),
  declare(globalContentColor, 'rgb(20, 30, 40)'),
])
rules(['.ReviewTheme', '.Button'], [
  declare(buttonSurfaceCanvas, 'rgb(180, 210, 190)'),
])
```

根主题让普通Button默认背景以浅蓝灰为画布、普通文字为深灰；ReviewTheme明确选择按钮画布，改用浅绿，区域外不变。Button仍按原配方混入动作色，并保留hover/active明度反馈。只改某个Button的画布或内容时，继续使用下一步的组件控制点。

这不是整颗按钮的单一染色开关。filled常态使用语气实底，因此可能不露出主题画布；强调实底上的文字仍用paperColor保证原有对比，不自动改成全局内容色。

```text
多个组件共用默认表面或普通文字：在root声明全局来源
某个组件需要不同加工或固定值：声明它公开的组件Variable
原有语气与交互反馈：继续由Button提供
```

## 第四步：只有审核页面需要更紧凑、换画布

需求增加：“审核页这排按钮最小高度改为40px，普通按钮以蓝色为来源、白色为画布；危险按钮继续保留危险语气。其他页面不变。”

用 `.ReviewPanel .Button` 选择本区域里的实际按钮，再用 `size` 调整尺寸、用 `declare` 给 Button 公开的 `buttonSurfaceCanvas` 提供白色。普通按钮另用 `:not([data-tone])` 选择，给 `buttonSurfaceSource` 提供蓝色。危险按钮没有被这条普通语气规则选中。

这里的角色是组件已经消费的同一个 Variable；在匹配到的按钮上声明它，组件原有的背景组合就读取新来源。只在祖先 `.ReviewPanel` 上声明不够：Button 在自身也有定义，本例因此明确选择区域内的按钮。`declare` 不修改共享对象，区域外按钮保持原样。

固定来源覆盖到这里已经满足需求。需要对默认、状态和变体结果统一应用变化时使用modify，无需先声明一次创建内容。

效果：区域内按钮最小高度40px，外部仍为48px；区域内普通按钮背景使用蓝与白的混合，危险按钮保留危险来源；悬停仍有反馈。样式未设置固定宽度，文字仍决定所需宽度。

```text
只改审核区域：选择 .ReviewPanel 内的 .Button
换现有背景画布：declare 公开画布角色
只换普通语气来源：再限制为没有 data-tone 的按钮
不匹配该区域：继续使用原 Button 定义
```

## 可照用的三个文件

`actions.style.ts`：定义在首次使用前，下面两段分别对应页面布局和区域定制。没有修改 Button 源码。

rules第一参数选择“给谁用”，第二参数列出“给它什么效果或声明”；contentLayout、size提供布局与尺寸效果，declare给组件已经公开的Variable赋当地值。路径数组['.ReviewPanel', '.Button']选择ReviewPanel内的后代Button，不是分别给两个元素套同一效果。

```ts
import { buttonSurfaceCanvas, buttonSurfaceSource } from '@/components'
import { contentLayout, declare, rules, size } from '@/style-system'

// 页面只增加动作排列；按钮本身沿用现有布局与交互。
rules('.ActionRow', [contentLayout({ mode: 'center', gap: '12px' })])

// 区域定制写到按钮自身，避免被按钮自己的基础定义遮住。
rules(['.ReviewPanel', '.Button'], [
  size({ minHeight: '40px' }),
  declare(buttonSurfaceCanvas, 'white'),
])
rules(['.ReviewPanel', '.Button:not([data-tone])'], [
  declare(buttonSurfaceSource, 'blue'),
])
```

`Actions.tsx`：这里确实渲染 UIKit Button。组件自身静态导入它已有的样式。

```tsx
import { Button } from '@/components'
import './actions.style'

export function Actions() {
  return <>
    <div class="ActionRow OutsideActions">
      <Button filled onClick={() => console.log('已保存')}>保存</Button>
      <Button filled danger>删除</Button>
    </div>
    <section class="ReviewPanel">
      <div class="ActionRow">
        <Button filled onClick={() => console.log('已保存')}>保存</Button>
        <Button filled danger>删除</Button>
        <Button filled danger disabled onClick={() => console.log('不应执行')}>不可删除</Button>
      </div>
    </section>
  </>
}
```

`main.tsx`：先让静态样式登记，再挂载，最后渲染。HTML 中先提供 `<style id="css-root"></style><div id="app"></div>`。

```tsx
import '@/css/all-base.css'
import { render } from '@solidjs/web'
import { cssRoot } from '@/style-system'
import { Actions } from './Actions'

cssRoot.mount()
render(() => <Actions />, document.getElementById('app')!)
```

先只保留 `actions.style.ts` 的 ActionRow 规则，就能看到前三步；加上 ReviewPanel 两条规则，再比较区域内外。`compileCSS()` 可用于读取当前 CSS 文本；页面生效用 `cssRoot.mount()`。后续替换或撤销已登记规则后，再次 mount 提交结果。

## 新规则怎样复用，而不建立组

继续使用Button时，普通/危险/焦点已有明确配方，页面只声明它公开的具体Variable。自己新增线条用途时，可以写lineColor(base)这样的普通函数，返回属于该基础的Variable；已有定义和状态要复用时用variableFrom(source, value, nameOrOptions)。这两种需求的完整例子在[Variable使用段](变量定义与消费.md#用普通函数保存转换规则)。

如果三个独立颜色要在同一条件协调变化，就在同一rules中并列declare。创建一个新Variable不会自动改变旧引用；给现有组件在区域内声明它消费的同一Variable，才改变匹配位置。下面的选择与上面ReviewPanel用法相同，不增加新的组对象或整组换色接口。

| 你的需求 | 选择 | 对已有引用的影响 |
| --- | --- | --- |
| 另一种内容由具体基础计算 | 普通函数接收基础，返回新Variable | 新设计主动引用新结果；原对象不自动替换 |
| 沿用已有默认和状态，再表达定义差异 | variableFrom(source, value, options) | 创建时复用；新名独立，默认沿用名字仍受CSS层叠 |
| 让已有Button在某区域换组件配色 | 在区域内按钮上declare其公开Variable | 匹配位置读取当地覆盖，区域外不变 |
| 多个独立颜色同条件一起换 | 并列declare各目标 | 只改列出的具体对象，没有隐式成员配对 |

```text
转换规则要重复使用：普通函数创建具体变量
定义和状态要延续：variableFrom
已有组件按位置换值：declare原控制对象
多个目标同步选值：在同一条件逐个声明
```

完成按钮后，再按[选型对照](样式系统对象与行为.md#先判断是否需要另一种部件)进入所需参考。不需要新增规则时，教程到此即可。
