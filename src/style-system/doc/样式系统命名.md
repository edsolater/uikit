# Style System 命名

内容模型统一使用 Token，目标语义见 [Token 设计](Token设计.md)。源码已完成迁移，本文说明目标命名，公开入口与源码已使用 Token。

命名先保持同一逻辑链的一致性，再考虑单个名字的局部可读性。来源和结果沿用 Color、Shadow、Opacity 等相同抓手；组件前缀在前，Source 或档位在后，CSS 名称保持相同顺序。

例如 brandColor、badColor → buttonColorSource → buttonSurfaceColor、buttonContentColor、buttonBoundaryColor。来源与各结果都在表达颜色，不另用 ThemeSource 改变这一层的含义。

公共颜色链同样保持 Color 抓手，例如 brandColor → brandColorTheme → brandColorEmphasis；Theme、Emphasis 表达该颜色的主题或强调定义，放在后面。动作与链接颜色分别叫 actionColor、linkColor，不在同一层反转词序。

| 对象            | 示例                                    | 含义                                 |
| --------------- | --------------------------------------- | ------------------------------------ |
| JSSKey          | $backgroundColor、$opacity              | 原生 CSS 声明目标                    |
| Token           | baseSpace、surfaceColor、motionDuration | 可组合的内容，可携带状态、名称与地址 |
| 普通函数        | lineColor(base)                         | 根据输入产生用途明确的 Token         |
| Mixin           | color、boundary、clickable              | 从配置产生完整效果                   |
| State Condition | hover、active、focusVisible             | 主体自身状态                         |

公共 Token 不使用 space、opacity、radius、shadow 这样的单词名称，分别使用 baseSpace、baseOpacity、baseRadius、baseShadow；档位继续追加后缀，如 baseShadowSmall、baseShadowLarge。base 表示基础材料，不改写原生 CSS 属性名或 Key 变量，例如 opacity、$opacity。

业务名称带组件前缀，例如 buttonOpacitySource、buttonOpacity。Source 表示该链条继续消费的来源，放在 Color、Shadow、Opacity 等抓手之后；不能只为了单个名字读起来顺口，改用另一套抓手。两个职责明确的节点分别命名，不为命名另造中间层。

surfaceColor 已说明材料的视觉作用，无需 global 前缀。业务名称不要求追加 Token 后缀。CSS 名称由显式配置或自动分配取得，不通过名称反向查找另一个对象的定义。

用途通过普通函数组织，不通过 Token 内置成员表选择。组件自己的 buttonSurfaceColor、buttonContentColor 等控制对象保留在组件样式；共享转换函数只表达输入到结果的规则。

需要状态就使用可选 state，无状态的直接内容仍然是 Token。具体表达式参数可以使用 value 等普通参数名；领域对象统一命名为 Token，CSS 输出术语继续使用 CSS variable、CSS value。

名字必须对应样式本身或所属业务职责。公共材料不因某个组件使用它就改用组件名称；组件自己的配置使用业务前缀，明确谁在选择材料。
