# 当前接口与扩展协议

本篇承接 Behavior 中迁出的当前调用形状、输入限制及编译扩展协议。它们是现有接口约定，不据此证明某种内部算法必须保留，也不替代用户对领域语义的裁决。重建等效领域引擎先读 [__spec.md](behaviors/__spec.md)；兼容当前调用方或编写扩展时再查这里。

本篇承接当前调用协议；示例省略 import，不代表实现已经符合全部 Behavior。接口支持范围由实际入口核对，不能因为两个 API 目的相近就混用参数。与最新 Behavior 冲突的内部处理属于实现差距，不提升为新的领域规则。

# 加工、注册与提交入口

`adjust(source, modification)` 保持两参，不提供命名或地址第三参；`modify(target, modification, options?: { id?: string | symbol })` 返回可交给 rules 的 Declaration。当前 adjust 接受可独立声明的 color Modification；modify 接受该颜色材料，也接受 `{ type: 'expression', detail: current => ... }`。ExpressionModification 不能因此作为当前 adjust 的合法参数。目标须为自定义属性材料，非法类型或缺必要材料明确失败；这不要求为任意强制类型转换另建防御层。

registration 明确提供 syntax:string、inherits:boolean，可选 initialValue:ValueInput。入口检查前两项类型，实际注册是否合法由浏览器判断；不从 Variable 创建内容推断 initialValue。

数组 Value 默认递归使用逗号分隔；`valueList` 明确使用逗号，`valueSequence` 明确使用空格。空项不占分隔位置，0 等合法值保留。`withContent` 更换数据并保留原包装的输出方式、依赖配置和 onActive 约定；动态 dependencies 根据新内容求取，显式列表沿用。

`compileCSS()` 读取当前全局登记，`compileRules(rules)` 读取显式材料而不登记全局，均返回 CSS 文本。`cssRoot.mount()` 提交到宿主准备的 `style#css-root`；目标不存在明确失败，不自动改为另一个宿主。页面保护要求由 [Compile与挂载.md](behaviors/Compile与挂载.md) 规定。


# Variable 输入、命名与可选配置


业务引用具体Variable，才能确定需要哪份定义。同名仅表示CSS标识相同，不能据此从另一JS对象借入状态或资源：

```ts
const a = variable({ default: 'red', hover: 'pink' }, { name: 'tone', address: '.A' })
const b = variable({ default: 'blue', active: 'navy' }, { name: 'tone', address: '.B' })
```

只消费a不激活b的生产函数、状态或onActive资源。消费两者时A不借入b的active，B不借入a的hover；同名CSS仍按浏览器层叠互相影响，独立JS对象不等于CSS隔离。

Variable.name是创建时绑定的VariableName对象，不支持事后替换。String(a.name)、a.name.toString()及模板拼接得到逻辑名`tone`；Name对象作为内容消费才输出`var(--tone)`，Variable声明地址为`--tone`。创建的字符串名称可带--前缀，按既有名称正规化处理。

普通字符串按原CSS文本消费，不自动变成引用：`'var(--tone)'`原样提供引用，String(a.name)仅提供文本`tone`。Name和字符串都不查找或激活同名Variable，也不建立对象依赖。

# 创建输入与继承的完整边界

公开创建形状是`variable(defaultContent, nameOrOptions)`或`variable({ default, ...states }, nameOrOptions)`，均返回Variable。基础内容和名称必填，不提供匿名创建或遗漏基础内容的重载。

```ts
const gap = variable('4px', 'gap')
const shorthand = variable({ default: '8px', hover: '16px', active: '12px' }, {
  name: 'shorthand-size', address: '.Shorthand', states: { hover: '20px' },
})
const empty = variable({ default: undefined }, 'empty')
```

shorthand的hover为20px，active仍为12px：options.states覆盖简写中的同名状态，其余保留。显式default:undefined是提供内容，不等于缺字段。内容可为普通值、具体Variable、Value、Expression、无参生产函数或内容协议对象；创建不执行生产函数，求值边界见[Value与Expression.md](behaviors/Value与Expression.md)。address接受现有Condition、路径字符串或路径数组。

variableFrom省略priority时为来源加一，显式0有效；registration、onActive及compileWaveIndex须显式提供，不随入口复用。规则复用不替代对这些可选行为的明确配置。


# 登记接口与同址聚合


多项样式使用`rules(condition, items)`，其中Declaration元组明确目标与内容，Mixin提供一组所选效果。元组目标使用Key或Variable，不接受裸字符串或普通声明对象；低层rule与Rules允许字符串目标。

Key表示原生属性，不要求预登记；如果使用别名，必须先明确它指向哪个属性：

```ts
const color = variable('red', 'public-color')
const handle = rules('.Probe', [[key('color'), color], [color, 'blue']])
key('align-items')
const alignment = rule('.Probe', 'alignItems', 'center')
try {
  const css = compileCSS()
  expect(css).toContain('color: var(--public-color);')
  expect(css).toContain('--public-color: blue;')
  expect(css).toContain('align-items: center;')
  expect(css).not.toContain('alignItems:')
} finally {
  handle.remove()
  alignment.remove()
}
```

上例中Variable同时作为内容引用和赋值目标；只登记属性时不必先创建Variable。key('align-items')明确登记其既有别名，避免alignItems被当成另一个CSS属性输出。同名别名登记不能悄悄改指另一属性。

Mixin的目的，是将一个完整效果写成一次选择，同时避免引入未选择的效果。例如jssContentLayout({ mode: 'center' })提供inline-flex和双向居中；jssContentLayout({ gap: '8px', padding: ['4px', '12px'] })只提供间距和内边距，不能顺带改变display或alignment。

# 一批登记整体生效

一批样式常常共同表达一个效果。如果中间失败却留下前半批，调用者就会得到残缺结果。因此嵌套组合保留输入顺序，空项与undefined内容不输出；无效条目或输入迭代中断时整批失败，既有登记保持。

```ts
const color = key('color')
const padding = key('padding')
const batch = rules('.Probe', [
  [color, 'red'], undefined,
  [[padding, '4px'], [color, 'blue']], [padding, undefined],
])
try {
  expect([...compileCSS().matchAll(/(color|padding):\s*([^;]+);/g)]
    .map(([, property, text]) => [property, text.trim()])).toEqual([
      ['color', 'red'], ['padding', '4px'], ['color', 'blue'],
    ])
} finally { batch.remove() }

const original = rule('.Probe', 'color', 'green')
try {
  function* interrupted(): IterableIterator<DeclarationItem> {
    yield [color, 'red']
    throw new Error('迭代中断')
  }
  expect(() => rules('.Probe', interrupted())).toThrow('迭代中断')
  expect(compileCSS().match(/color:\s*([^;]+);/g)).toHaveLength(1)
  expect(compileCSS()).toContain('color: green;')
} finally { original.remove() }
```

# 同址贡献如何选择和组合

多个来源可能同时为同一目标提供内容。这里解决两种不同意图：Variable需要选出适用值；带join的普通Key需要按约定组合贡献。两者都只处理同一完整地址，跨地址的CSS层叠另行决定。

同一完整CSS地址及目标中，较高priority的有效Variable贡献优先；同等级后写的有效贡献优先。undefined不能覆盖已有有效值。普通Key缺省priority为999，普通Variable为0；variableFrom省略时为来源加一，显式0仍为0。不同地址的最终结果由[CSS作用域与层叠.md](behaviors/CSS作用域与层叠.md)决定，不能用priority跨选择器压过浏览器规则。

可用同址值4(priority0)、7(priority2)、9(priority2)验证：先取9，撤销9后取7，加入undefined仍取7。从priority5来源复用且显式priority0的定义不能压过priority1；若误把0当成缺省6，这个结果就会反转。

普通Key的重复贡献按其join约定组合，不套用Variable只选一个值的规则：

join收到带content的Value视图，下面用item.content取得各项数值；2和3共同表达结果5，删除3的贡献后应回到2。

```ts
const stack = key('z-index', {
  join: values => values.reduce((sum, item) => sum + Number(item.content), 0),
})
const first = rule('.Stack', stack, 2)
const second = rule('.Stack', stack, 3)
try {
  expect(compileCSS()).toContain('z-index: 5;')
  second.remove()
  expect(compileCSS()).toContain('z-index: 2;')
} finally { first.remove(); second.remove() }
```

join只接收同完整目标/状态地址中获选等级组的贡献，输入Value按源序排列。单项直接使用，不调用join；没有显式join时默认逗号组合。组内唯一显式join接管默认规则，多个不同显式join冲突明确失败。结果保持组内最后贡献的外部顺序，其他地址与状态不混入。

回调看到原content及对象身份。保留输入Value时，输出读取它在原消费位置的编译结果，不额外执行生产函数；若把某项content换成依赖新位置的内容，新内容在结果消费处编译。两个原位置分别得到4和7时，组合不得因位置丢失读到另一值。join返回值继续按内容协议消费。

阴影和$boxShadow沿用默认逗号组合，重复项保序；none或CSS全局关键字不表示编译期清空此前贡献，组合是否有效交给浏览器判断。join冲突不交付半份CSS，也不替调用者删除源登记。

# 声明材料的输入边界

`declare(key, content)`构造Declaration，交给rules使用。`declare({ key, content }, replacement?)`也可读取自然材料，不要求品牌或特定构造器；这样已有材料可以直接参与声明，不必包装成指定类。

自然材料须实际提供content字段；显式undefined表示无有效内容，不能被换成另一个目标或默认值。可选declarations保留共同声明依赖，即使覆盖自身内容也不丢失。属性名输出须为字符串，不得把函数源码当属性名。adjust/modify目标须为自定义属性材料，非法材料明确失败；公开类型的拒绝不等于为所有强制转换输入新增运行时校验。


# 状态快捷名与交互约定


快捷名解决的是多个定义共用同一反馈条件的问题。内置快捷状态可直接使用；需要自定义共用名称时，用`stateCondition(name, condition)`登记。只使用一次的直接条件可以直接写入states，无需预登记。

```ts
stateCondition('probeReady', condition('&[data-ready]'))
const readySize = variable('4px', {
  name: 'ready-size', address: '.Ready', states: { probeReady: '8px' },
})
```

挂载后增删.Ready的data-ready，应在8px与4px间切换。其他Variable使用同一快捷名，仍取得自己的对应状态内容。

为避免同一个名称在不同定义中突然表示不同条件，空名称、default和重复名称明确报错，不静默覆盖。定义者保证直接条件约束同一主体且组合可交换；接口不分析或修正任意选择器。

快捷名在Variable创建时确定含义，后续登记不追溯改写既有定义。例如旧对象先将`&[data-old]`作为直接条件；随后将同字符串登记到`&[data-new]`再创建新对象。旧对象仍响应data-old，新对象响应data-new。自定义名称使用独有名字；接口无撤销登记能力，不虚构清理API。

普通Rules的字符串地址不查快捷表，`'hover'`仍是标签、`'&:hover'`仍是原生条件。名称解释只属于states相应输入。

# 同时成立时如何选择

一个主体可能同时focus、hover和active。结果不能依赖不同业务文件碰巧以什么顺序拼出states，因此快捷状态使用统一次序；直接条件继续保留自己的CSS含义。

内置快捷顺序为focus、focusWithin、focusVisible、hover、active、disabled；自定义快捷名按登记顺序。states配置字段书写次序不改变快捷顺序。直接条件在快捷状态之后按配置顺序参与，仍受自身CSS特异度和层叠约束，不能把中央次序推广成任意选择器都忽略权重。

focus快捷项与focusVisible均表示`:focus-visible`，直接whenFocus仍为原生`:focus`；鼠标取得焦点不保证显示焦点提示。

可用两个同时命中的自定义状态验证：先登记A，再登记B，states故意先写B再写A。主体同时具备A/B标记时应取B；删除B标记应恢复A，均删除恢复普通值。把配置书写顺序反过来，结果仍相同。仅比较生成文本不足以证明浏览器同时命中的结果。

# 禁用时排除交互反馈

禁用主体仍可能被鼠标悬停；快捷交互反馈应避免把它表现为可操作状态。whenHover和whenActive排除原生`:disabled`及`data-status~="disabled"`，whenDisabled识别两者。普通`&:hover`保留原生CSS语义，不自动加入禁用限制；状态标记不替元素实现DOM事件禁用。

# 用交互结果验证禁用边界

下面的测试片段分别观察原生禁用、状态标记和二者同时存在。先确认浏览器本来匹配了交互，再确认快捷反馈将其排除，避免把“浏览器根本没进入active”误判为禁用反馈正确：

```ts
for (const mode of ['native', 'status', 'both']) {
  const button = document.body.appendChild(document.createElement('button'))
  try {
    button.disabled = mode !== 'status'
    if (mode !== 'native') button.dataset.status = 'loading disabled'
    await userEvent.hover(button)
    expect(button.matches(':hover')).toBe(true)
    expect(button.matches(whenDisabled.header.replace('&', ''))).toBe(true)
    expect(button.matches(whenHover.header.replace('&', ''))).toBe(false)
    button.focus()
    await userEvent.keyboard('[Space>]')
    try {
      if (mode === 'status') expect(button.matches(':active')).toBe(true)
      expect(button.matches(whenActive.header.replace('&', ''))).toBe(false)
    } finally { await userEvent.keyboard('[/Space]') }
  } finally { button.remove() }
}
```

标记禁用案例先确认原生active确实匹配，再检查快捷反馈被排除；原生disabled按钮不要求浏览器产生active。真实Button还须验证原生disabled、点击拒绝及禁用外观，不能用选择器匹配代替组件结果。


# 内容扩展与 AST 编辑协议

本篇面向扩展作者。已有Value、表达式和Mixin能满足需求时，业务直接组合它们；需要新的内容格式或编译扩展时，才使用这里的协议。它保护两件事：改写准确作用于本次消费，共享内容和来源能安全退出。

# 改写本次消费并读取其结果

同一个内容可能被多个位置使用。扩展必须区分这次正在处理哪一处，避免改变A时连B一起改掉。onCompile(context, ast)返回void，返回值不替代内容；改写使用ast.setContent(context, content)。

例如同一内容分别用于A.width和B.width，按本次输入分别setContent为8px/12px，页面应各得8px/12px；将A设为undefined只退出A的贡献，B保持12px。嵌套内容取得自身input，不能误改外层对象。保留已经退出同步通知的context再次setContent明确失败。

context.node是可改写节点引用；conditionPath/key/content是角色开始时的输入快照，改node不反改快照。input标识本次被通知对象，role区分declaration-key/declaration-content；session是同次编译内稳定的不透明身份，不同编译不混用私有状态。Controller没有隐含当前位置。

内容可按需提供dependencies、onActive和toCSSString；合法依赖/资源容器不必自身有输出。resolver及getCompiledContent/getCompiledValue/getContentCompilation取得本次已编译结果及实际依赖，不为读取再次运行生产函数或getter，不因查询激活未访问输入。usesContent(node,input)只反映当前目标/内容实际访问，旧替代记录存在不等于仍在消费。替换后独占资源退出，共享需求保留。

Expression只组织依赖和CSS输出，类型不接受onActive/onCompile/compileWaveIndex/resourceIdentity。createJSSContent(output,dependencies?)返回Expression；CSSFunction作为独立定义主体，调用返回依赖主体及实参的Expression。类型边界不表示为任意强制转换输入增加运行时防御。

# 显式查询和编辑节点

扩展可能需要在既有声明旁增加内容，或查询某个地址是否已有声明。位置和来源分别表达：位置决定CSS顺序，来源决定谁退出时应撤销产物，移动位置不应改变归属。

扩展明确给出锚点、条件地址及来源owner。insert(position,[key,content],provenance)的before/after互斥是公开类型约束；identity/productTag/resourceAddress是可选标识。每次紧邻锚点，不暗设插入游标；连续向后插入保持顺序时，用上次返回节点作新锚点。move只改位置，不改值、条件与来源。

可先插width8px再插height12px，读取有序声明应width→height；将height移到width前应height→width。只核两个计算值不足以发现移动失效。

search({key,conditionPath,productTag,resourceAddress})返回有序匹配；未提供字段不限制，提供字段取交集。Key按属性名、条件按输出地址匹配；has与search是否为空一致。findDeclaration(query,accept)在指定地址可接受候选中选择有效声明：同完整地址遵循priority与源序，单层:root和:where(:root)识别同一根且保留原生特异度。查询不改队列和来源；nodes是快照，修改返回数组不直接改队列。

验证查询须同时准备同key不同条件、同条件不同key的对照；同时给key和conditionPath只能取得两者均匹配者，查询前后顺序与撤销计数保持。

# 来源决定撤销范围

共享产物仍有人需要时就应保留；最后一个来源退出后才撤销。暂时不输出也不等于永久删除，因此协议区分解除来源、退出输出和真正撤销：

- depend(product,{owner})登记显式来源；release(product,{owner})只解除该来源，其余来源仍需的产物保留，最后来源退出才撤销非源产物。
- onRemove(node,cleanup)登记真正撤销时的清理。remove(node)真正撤销并清理失去全部来源的后继。
- remove(node,{from:'output'})仅退出输出，保留来源与产物，不触发真正撤销清理。

同一产物有两个owner时，退出输出应使CSS不再包含该项、清理计数仍0；真正解除最后来源后清理计数才1。另一个有剩余owner的共享产物仍输出，不能因为暂不输出就销毁共享来源。

# 明确改变输入后读取新结果

输入被替换，或扩展明确要求旧结果失效后，后续读取必须采用当前内容。输入身份未变但编译前提改变时，通过compileRevision使旧结果及聚合结果失效；这不提供闭包自动观察。setContent仍只在对应同步通知内有效。

modify也是遵守该协议的内容。[修改输入替换后采用当前变化](behaviors/../../test/修改输入替换后采用当前变化.browser.test.ts)验证：

- 修改材料被替换后，默认、固定状态和变体采用新变化，区域外对照保持。
- 同一input显式增加compileRevision后使用当前变化，旧配方独占资源退出。
- 共享id候选、后续非交换步骤与撤销仍有效；不能因更新而重复累计或改变顺序。

仅前插一步只重连源序，不重新执行尚未显式失效的旧变化回调。这样显式更新能生效，单纯重新排列又不会意外读取闭包新值。最终验证的是[adjust与modify.md](behaviors/adjust与modify.md)的实际效果，不固定私有步骤名称、容器或辅助变量数。

# 等待只重试未完成工作

某项内容尚缺前提时可以等待，但等待不应重复执行已经成功的其他工作。defer(node,reason)暂缓未完成通知，保留已完成内容及合法队列操作。compileWaveIndex是最早允许执行时机，不保证固定波数完成；配置时机不能被绕过。

行为示意：前序成功通知把计数加1；等待内容见ready=false则defer。合法后续生成者置ready=true，重试后setContent为9px，页面宽9px，前序计数仍1。始终不置ready则明确报告等待原因，不能成功空输出或无界增长。旧等待原因不能遮盖重试后的新状态。

等待不延长过期context寿命，退出同步通知后不能继续用旧context改写。

清理案例时撤销源登记与所有DOM/style；失败构建不得交付半份结果，也不损坏[Compile与挂载.md](behaviors/Compile与挂载.md)。
