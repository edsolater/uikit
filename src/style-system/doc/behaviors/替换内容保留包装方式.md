# 目的

业务数据替换后继续沿用原表达方式和依赖配置，同时保留原包装的内容，调用者不必重复定义格式。

# 典型案例

行为伪代码，不能直接运行：创建`value<number>(200, { toCSSString: ms => String(ms) + 'ms' })`，再调用`duration.withContent(400)`取得新包装；两者分别用于两个元素transition-duration，构建挂载应得到0.2秒和0.4秒，原duration.content仍为200。

withContent返回独立Value，保留原输出规则、依赖配置和激活约定，只替换数据。依赖配置为按内容计算的函数时，新内容400参与该函数；配置为明确依赖列表时继续沿用列表。普通Value不取得Variable状态能力；没有自身生命周期的ExpressionValue在替换后仍只组织依赖与输出。

默认数组内容递归逗号输出，valueList/valueSequence分别提供逗号/空格组织；自定义输出方法可以用resolver读取已编译子内容，不能为格式化重新执行业务生产函数。通用消费边界见[延迟求值](动态样式只在使用时求值.md)。

清理：撤销两个消费及本例DOM/style；若共享资源，先撤销一个不误删另一个需要的资源。

# 反例

新数据仍输出200ms、原数据变成400、替换时丢失格式或依赖配置、外围Value开始复制来源状态，均违反目的。
