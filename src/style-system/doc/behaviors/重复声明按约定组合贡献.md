# 目的

同一目标的多个有效贡献按调用者约定组合，组合不会丢顺序、误读原消费位置或擅自创造清空规则。

# 典型案例

行为伪代码，不能直接运行；以下迁移现役Key.join公开约定。

```ts
const stack = key('z-index', {
  join: values => values.reduce((sum, item) => sum + Number(item.content), 0),
})
rules('.Stack', [[stack, 2], [stack, 3]])
```

构建挂载后Stack计算z-index为5。撤销第二项后单条直接得到2，不调用join。另以两个阴影贡献验证无显式join时按原顺序逗号组合，不能反转图层。

聚合只包括同完整目标/状态地址及[有效等级](同址声明保留有效优先关系.md)获选组的贡献；输入Value按声明顺序传给join。组内唯一显式join接管默认逗号组合，多个不同显式join规则冲突须明确失败，不能随遍历偶然挑一个。回调返回ValueInput，其合法内容继续按内容协议消费；合成结果保持该组最后贡献的外部顺序，其他地址与状态不混入。

位置读取案例：两个内容对象sourceA/sourceB分别在原位置生成4和7，join回调应能观察`values[0].content === sourceA`及`values[1].content === sourceB`，content保留原值和对象身份，不能预先换成编译值或克隆对象。join保留输入Value进行组合时，输出仍读取对应原位置的编译结果，不额外运行原生产函数；若join把某项content替换为依赖新位置的合法内容，新内容在结果消费位置编译。分别观察对象身份、4/7及替换后的值，不约束内部Value视图或记录结构。

`$boxShadow`沿用同样默认组合。已有逗号列表和重复项按顺序保留；加入none或CSS全局关键字不表示编译期清空先前贡献，最终混合是否有效由浏览器判断。

清理：撤销其中一项核对剩余单项，再撤销本例全部登记；join冲突导致编译/提交失败时，不交付半份CSS，也不破坏上次成功提交。冲突不意味着替调用者删除源登记，需撤销本例冲突输入及DOM/style。

# 反例

2与3得到3、单项也运行join、不同地址合并、冲突join被静默选择、保留原Value却在新位置重新求值、改content仍读旧结果，均违反目的。

# 推断依据

迁移原对象契约的Key.join与boxShadow段及原节点树输出段，保留外部扩展效果，不保留惰性视图实现为永久要求。[key.ts](../../key.ts)、[join.ts](../../compiler/style-nodes-to-content-nodes/join.ts)为当前查证入口。
