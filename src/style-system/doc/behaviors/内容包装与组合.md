业务数据不一定已经是CSS文本。Value把数据与输出方式放在一起，表达式再组合这些内容；这样替换数据时不用重写格式，组合时也不丢失单位、比例和引用。它们不取得Variable的状态能力。

# 更换数据，保留格式与原包装

例如业务用毫秒保存动画时长，希望200和400都按同一规则输出为CSS，同时保留原来的200：

```ts
const duration = value<number>(200, { toCSSString: ms => `${ms}ms` })
const slower = duration.withContent(400)
const css = compileRules([
  [['.Normal'], 'transition-duration', duration],
  [['.Slower'], 'transition-duration', slower],
])
expect(css).toContain('transition-duration: 200ms;')
expect(css).toContain('transition-duration: 400ms;')
expect(duration.content).toBe(200)
```

withContent生成独立Value，只更换数据，保留输出规则、依赖配置及onActive约定。动态dependencies函数取得新内容；显式列表继续沿用。原包装保持原数据，没有自身生命周期的ExpressionValue替换后仍仅组织依赖和输出。

数组Value默认递归逗号输出，valueList/valueSequence分别表示逗号/空格组织；空项不占分隔位置，0等合法值保留。自定义输出通过resolver读取已编译子项，不再次执行业务生产函数。

# 组合保留原有CSS含义

格式化后的内容还需要组成颜色、字体或计算表达式。组合工具的意义是保留每个组成部分的CSS含义，避免调用者每次手工拼接比例、分隔符和单位：

```ts
const css = compileRules([
  [['.Probe'], 'background-color', colorMix(['black', 0.5], 'white')],
  [['.Probe'], 'font', fontValue({
    style: 'italic', size: '16px', lineHeight: 1.5, family: 'system-ui',
  })],
  [['.Probe'], 'width', multiply('12px', 2)],
])
expect(css).toContain('background-color: color-mix(in oklab, black 50%, white);')
expect(css).toContain('font: italic 16px/1.5 system-ui;')
expect(css).toContain('width: calc(12px * 2);')
```

混色比例、字体斜杠、计算运算符与单位不能在通用编译中丢失。CSSFunction保存具名定义，调用返回依赖主体及实参的Expression。例如定义结果为`calc(var(--size) - var(--inset) * 2)`，调用100px/8px在支持相应CSS语法的浏览器应84px。

animationName(name, frames)保存关键帧，animationValue组合名称、时长及其他动画配置。from opacity0/to opacity1、1s线性且forwards的动画正常播放结束为1，中点为0.5；不凭空加入未配置的减少动效分支。函数和动画的按需输出及命名资源替换由[按需资源与同名替换](按需资源与同名替换.md)负责。

# 内容只在实际消费时求值

可复用定义可能很多，页面只使用其中一部分。生产函数因此在真正需要内容时执行，创建或登记未被使用的材料不应提前计算并产生副作用：

```ts
const produce = vi.fn(() => '12px')
const size = variable(produce, 'lazy-size')
expect(produce).not.toHaveBeenCalled()
const handle = rule('.Probe', 'width', size)
try {
  expect(produce).not.toHaveBeenCalled()
  expect(compileCSS()).toContain('--lazy-size: 12px;')
  expect(produce).toHaveBeenCalled()
} finally { handle.remove() }
```

仅创建或登记不执行默认生产函数，普通Value中的动态内容也遵循此边界。无参函数到构建消费时执行，返回值继续按内容协议解释；可调用内容对象遵守自身协议，不因可调用而误当普通生产函数，状态回调仍取得基础参数。

有效声明替代默认时，不为取得无用默认额外求值；显式undefined不回退。求值失败明确报错，不把函数源码拼为CSS，不吞掉异常。不为探测依赖额外调用源函数，把不同返回混在一次消费；这不规定全系统各类回调的永久精确调用次数。

# 共享可复用，真实递归明确失败

同一内容在两个位置出现是正常复用；内容最终又依赖自己才是递归。区分它们，既能支持组合，又能在输入无法完成时明确失败，而不是卡住或交付半份CSS：
```ts
const shared = value('red')
expect(compileRules([[['.Probe'], 'color', colorMix(shared, shared)]]))
  .toContain('color-mix(in oklab, red, red)')
const cycle = value<ValueInput>(undefined)
cycle.content = cycle
expect(() => compileRules([[['.Probe'], 'color', cycle]])).toThrow('循环引用')
const first = value<ValueInput>(undefined)
const second = value(first)
first.content = second
expect(() => compileRules([[['.Probe'], 'color', first]])).toThrow('循环引用')
const recursive: Rules = []
recursive.push([undefined, undefined, recursive])
expect(() => compileRules(recursive)).toThrow('递归引用')
```

合法有限的共享、状态及局部覆盖组合须能完成，不能把共享误报循环。实际内容/Rules递归、生产函数错误或无法完成的内容链明确失败，不无界增长或交付部分CSS；不据此承诺任意CSS自定义属性依赖环分析。不固定耗时、编译波数、内部节点及中间变量数量。失败不得破坏[上次成功提交](编译结果与页面提交.md)。
