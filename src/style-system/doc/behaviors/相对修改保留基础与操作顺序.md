# 目的

在已有适用基础上表达局部相对变化，保留步骤次序及撤销后的结果，不修改共享创建配置。

# 典型案例

行为伪代码，不能直接运行：显式声明基础4、hover基础10，再应用合法加3变化并挂载；普通应7，实际hover应13。另用先加后乘与先乘后加两种登记核对非交换顺序，撤销中间步骤核对剩余结果。

数学示意：基础4、hover基础10，后续应用加3变化，普通7、hover13。实际API为`modify(target, modification, options?)`，返回Declaration；数值及尺寸等Expression材料为`{type: 'expression', detail: current => add(current, 3)}`，不是可独立声明的Modification。颜色可使用独立颜色配方。两次不交换的操作必须按业务登记次序产生结果，不能因延迟消费或编译先后改变次序。共享id表示同一步骤的候选覆盖，按适用条件、CSS选择器层叠及源顺序选有效候选，这不是Variable.priority之间的比较；撤销候选后恢复剩余步骤。

父区域变化与子区域覆盖各按其主体条件生效；两个组件及相邻实例不共享错误的修改链。撤销中间步骤后，后续步骤基于剩余结果继续正确计算。当前使用契约要求modify有适用的显式基础声明；能否完全依靠自动默认建立起点仍待定，不能借本次自动声明承诺擅自扩展modify。

未独立declare的后代可以继承祖先已经选择的结果；同class本身不保证实例自动隔离。需要独立变化基础时在相应区域明确声明，不能把正常CSS继承误报为串链。

`declare(target)`读取该次构建适用默认，`declare(target, value)`明确给基础；普通`[target, 20]`只是CSS赋值，不自动成为相对修改基础。默认内容用于基础声明，不作为var()第二参数；操作不改共享创建内容。

晚到内容依然按实际声明位置参与步骤，而非按完成编译的时间排序，不要求预知修改数量或分配固定槽位。没有输出的候选不参与赋值；子元素当地配方覆盖在当地结果中生效，父条件仍由父宿主匹配。浏览器表达式有容量限制，无类型或syntax:'*'可能达到上限，已有类型长链案例不是无限容量承诺。

明确类型注册且inherits:false时，同一主体已声明基础4再加3应得到7，不能因基础丢失读错；注册的后代初值边界由[注册语义](变量注册保留显式类型与继承语义.md)负责。

清理：退出状态、撤销修改再核对基础；最后撤销声明及消费，移除案例DOM/style。共享id只撤销一个候选时保留其他候选。

# 反例

把加乘顺序改反、撤销中间步骤后断链、共享id按Variable.priority而非CSS层叠选择，或局部变化污染相邻独立基础，均违反目的。

# 推断依据

现役公开modify用途，用户明确要求保留。[浏览器修改测试](../../test/变量修改与条件组合.browser.test.ts)覆盖非交换顺序、共享id、局部主体和撤销；它不承诺无限表达式容量。modify无显式基础的自动起点待定，不借自动声明要求扩展其签名或起点。
