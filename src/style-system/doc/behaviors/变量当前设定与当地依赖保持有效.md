# 目的

业务能够通过全局或区域输入调整引用结果，同时保留显式控制和状态效果，不必枚举依赖组合或在每次输入变化后重复重建样式。

# 行为

使用变量时保留当前样式Address适用的原始定义，没有适用声明时采用创建默认；原始定义是尚未附上state、未被CSS引擎求成具体值的declare输入。只有它实际引用其他Variable，且任一被引用Variable在当前Address已有显式或连带自动声明时，才发布当地基础表达式，并按原始定义展开state。无依赖或输入未在当地声明时，不因纯消费重复当地基础，但目标自身state仍在使用Address发布。显式固定20后改变旧来源仍为20，基于当前基础乘2的状态为40，退出状态恢复20。更换表达式后响应新依赖，未实际引用的对象不激活；撤销只清理退出的关系，不影响其他消费者。

# 典型案例

以下为Vitest浏览器测试体片段，省略import。声明路径只使用明确的嵌套条件，不推断任意选择器的包含关系。

```ts
const base = variable(4, 'current-expression-base')
const result = variable(multiply(base, 2), 'current-expression-result')
const style = document.body.appendChild(document.createElement('style'))
style.textContent = compileRules([
  [['.Parent'], ...declare(result, 20)],
  [['.Parent', '.Child'], ...declare(base, 7)],
  [['.Parent', '.Child'], 'width', multiply(result, '1px')],
])
const parent = document.body.appendChild(document.createElement('div'))
parent.className = 'Parent'
const child = parent.appendChild(document.createElement('div'))
child.className = 'Child'
try {
  expect(getComputedStyle(child).width).toBe('20px')
  child.style.setProperty('--current-expression-base', '9')
  expect(getComputedStyle(child).width).toBe('20px')
} finally {
  parent.remove()
  style.remove()
}
```

Address指样式condition path，不是实际DOM。当地使用从当前位置逐级向上取得适用原始定义；根兜底不参与该查找。同址冲突继续遵循[有效优先关系](同址声明保留有效优先关系.md)。兄弟声明不能改变此处结果，state展开产物或浏览器求值结果不能再被当作原始输入重复展开。

若Parent的result换成`another × 3`，Child又声明another，则Child应以当前表达式读取当地another，base变化不再恢复旧公式。若another本身是`source × 2`，Child声明source会使another在当地连带声明，再触发result当地求值。已满足当地声明门槛并提交CSS后，修改当地CSS输入应立即影响结果，无需重新编译；浏览器动态验收见[当地输入响应](派生结果跟随当地输入变化.md)。单独修改内联CSS而未在该Address登记输入声明，不承诺触发编译时当地基础重声明。

例如`basicSize=1em`、`cardWidth=basicSize×20`，Card与Inner仅消费cardWidth且未当地声明basicSize时，两处均不重复发布basicSize或cardWidth基础。若Card声明basicSize，则在Card联动cardWidth；Inner继续继承，不因纯消费再复制一次。多输入定义只需任一输入在当地声明，其余输入可继承。

依赖来自当前表达式实际引用的Variable，参数传入但展开结果未引用的对象不激活；延迟内容、状态表达式实际保留的引用仍须处理。自身状态继续以当前显式基础生成，例如基础20的乘2状态应为40。定义替换或消费撤销后，旧关系退出，仍被其他消费者使用的关系保留。

当地发布表达式是达到目的的当前行为方式，不构成目的本身；等效方式变更仍须重新裁决对外约定。声明树、条件查找及AST职责的待实施方案由[实施计划](../../../../docs/plans/20261019_变量局部重声明与动态依赖.md)记录，具体实现归代码；本文不将内部步骤或声明次数当作行为要求。

# 反例

Child得到14或18，说明固定20被创建公式覆盖；替换为another后仍随base变化，说明旧关系未退出；当地声明门槛已满足后，多层依赖或运行时CSS输入变化仍读取旧结果，说明表达式被提前冻结。纯消费层层复制当地基础、根兜底被当作当地输入声明或未引用参数激活资源，也违反当前行为。

默认基础可用由[自动定义](使用变量自动取得必要定义.md)负责；当前设定保持不能使其他消费失去默认，也不能用默认取代当地有效设定。

# 推断依据

2026-10-19最新用户裁决要求按原始declare输入取得当前定义，仅在实际引用的任一输入于当前Address已有声明时联动基础；目标state独立发布，根兜底不参与定义查找。AST继续负责贡献覆盖、优先关系及生命周期。本篇不规定内部树字段或遍历实现。
