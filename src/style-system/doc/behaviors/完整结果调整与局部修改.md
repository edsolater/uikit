基础、状态和变体可能各有复杂规则。业务想让整套结果改变时，不应逐项找出这些规则再重写；adjust和modify负责将一份变化应用到全部结果。

# 先确定要保留来源，还是改变原目标

下面两种操作的加工范围相同，区别是业务要控制谁：

| 操作 | 返回与用途 |
| --- | --- |
| `adjust(source, modification)` | 保留来源，另取新Variable；独立命名，沿用来源根据地 |
| `modify(target, modification, options?: { id?: string \| symbol })` | 改变已有目标；返回Declaration，放入rules，仅改变匹配范围内结果 |

如果只想换基础、保留原规则，先选[variableFrom](变量创建与定义复用.md#从已有定义复用规则)。这里解决的要求更进一步：固定状态值、规则状态值和变体结果也要接受同一变化。

# 用一份配方改变完整颜色结果

假设Button有红色基础、蓝色hover、紫色active，另有绿色line用途。现在希望这套颜色全部变为半透明：

```ts
const surface = variable('red', {
  name: 'surface', address: '.Button',
  states: { hover: 'blue', active: 'purple' },
  variants: { line: 'green' },
})
const halfOpacity = modification({ type: 'color', detail: { alpha: 0.5 } })
```

颜色变化用Modification保存。固定通道表示替换，通道回调表示相对变化，未指定通道保留；这样“怎么变化”可以独立复用，而不绑定某个来源。上面的配方将每个所选结果的alpha设为0.5。

如果还要保留原surface供其他地方使用，创建独立结果：

```ts
const faded = adjust(surface, halfOpacity)
rules('.Button', [color({ background: faded })])
```

如果希望读取surface的相关位置直接使用修改结果，改用下面这一组规则，替代上面的调整用法：

```ts
rules('.Button', [
  modify(surface, halfOpacity),
  color({ background: surface }),
  boundary({ border: ['1px', 'solid', surface.variant('line')] }),
])
```

两组规则分别使用，不在这个比较案例中叠加。adjust不改变来源；modify改变匹配范围内原目标。两种用法各自的背景普通半透明红、hover半透明蓝、active半透明紫；变体普通半透明绿，继承hover时也半透明蓝。外部未匹配修改的范围保留未加工结果。

有意串联两者时，adjust保留的来源当前CSS引用也会读到相应修改，不能把它当作未修改来源的对照。比较新结果与原来源时，只登记独立调整用法，在同一根据地另一消费位置读取原来源。

# 状态和变体先选出结果，再加工一次

这个顺序保护的是“整套变化”的含义：普通时加工红色，hover时加工蓝色，而不是先把红色改一次、又对状态结果改一次。固定值和规则结果都必须加工，不能让固定状态绕开。变体仍可在使用处选择，选择后不能丢失加工；adjust保留variants供选择，结果还能作为variableFrom来源。

adjust保留来源和配方在同一根据地上的当前CSS引用，让主题和配方控制继续有效。例如挂载后将根根据地的来源CSS值由红改蓝，结果应由半透明红变半透明蓝，不能冻结成创建时快照。局部同名输入不使祖先公式重新绑定，见[CSS作用域与层叠](CSS作用域与层叠.md)。

# 在指定条件内累计修改

根据地保障目标存在，modify不要求业务先补`declare(target)`、重传默认内容或先登记某个局部依赖。目标配置不被修改，条件外继续原结果。

尺寸也可以直接表达相对变化，modify不要求JS先算出浏览器数值：

```ts
const size = variable('4px', { name: 'meter-size', address: '.Meter' })
rules('.Meter', [
  [key('width'), size],
  modify(size, { type: 'expression', detail: current => add(current, '3px') }),
  modify(size, { type: 'expression', detail: current => multiply(current, 2) }),
])
```

Meter宽14px。交换两次修改的书写顺序则为11px，所以系统必须保留业务顺序，不能按配方种类重排。表达式材料为`{ type: 'expression', detail: current => ... }`，current是当前CSS表达式。

如果两个条件表示同一步的不同选择，而不是累计两次，就使用共享id。不同id是不同步骤；共享id的候选按CSS条件、层叠与源序选择，不用Variable.priority代替。撤销一个候选或中间步骤后，其余步骤继续有效。这使条件进入、退出和规则撤销都有明确含义。

同一完整地址中，后写显式新值覆盖此前修改；先写新值再modify则加工新值。不同地址按CSS范围与层叠选择结果。嵌套主体不能在已加工结果上无意重复同一步。registration的inherits及initialValue仍有效；浏览器表达式有实际容量边界，不承诺无限修改链。

# 可选资源与验收边界

adjust保持两参，不增加命名/地址第三参；来源与配方可共享。加工结果保留来源已持有的registration及onActive资源需求，包括只消费结果的变体时；最后需求退出才释放。variableFrom的原样规则继承与资源显式配置边界见[定义复用](变量创建与定义复用.md#创建输入与继承的完整边界)。目标和配方须符合其领域材料，非法类型、非自定义属性目标或缺必要材料明确失败。

验收应同时观察普通、固定与规则状态、变体及变体状态，不能只看默认值；修改退出后其余步骤和共享资源应继续有效。根据地已有新声明时采用其基础，见[根据地与显式局部修改用例](../../test/根据地声明与显式局部修改.browser.test.ts)。

普通业务不需要操作编译失效。扩展作者替换修改材料或明确要求重新求值时，仍须保护上述结果；输入身份、失效与回调重执行的完整约定归[内容扩展与节点编辑](内容扩展与节点编辑.md#明确改变输入后读取新结果)。
