# 目的

同一份 Variable 定义可以提供不同尺寸、强度或颜色形式，业务不应为每种形式重写复杂的状态。variants 保存这些变体，使用者显式选择后取得普通 Variable，再按需要声明或派生。下文先用尺寸解释通用行为，再用 Button 组合颜色。

state 按条件生效，variant 由使用者显式选择另一种形式。两者都可以是规则或固定值，通常用规则表达相对变化。固定值适合明确指定的结果，例如固定宽度或填充按钮的文字始终采用纸色。

# 行为

每个 Variable 都有 `derive()`，包括没有变体的 Variable 和 `variant()` 返回的 Variable。derive 在创建时原样继承 states 与 variants 中的规则或固定值，显式同名配置覆盖来源配置，其余保留。规则作用于新基础，固定值继续保持原值；这是定义复用的自然结果，没有额外的父子联动。

`surface.variant('content')` 返回普通 Variable。选中的规则接收 surface 的默认表达式；固定值直接成为变体默认值。结果继承 surface 的状态定义，状态作用于变体自己的基础，名称追加变体后缀。选择消掉父层 variants，结果仍可 derive，但不会重新取得父层变体。未知变体抛出错误；本轮没有嵌套变体。

# 典型案例

## 尺寸也能选择变体

```ts
const length = variable('10px', {
  name: 'control-length',
  states: { hover: base => add(base, '3px') },
  variants: { wide: base => multiply(base, 2), fixed: '7px' },
})
const larger = length.derive('20px', 'larger-control-length')
const wide = larger.variant('wide')
const sizeHandle = rules('.WideControl', [[key('width'), wide]])
```

wide 默认宽度为 40px，hover 为 43px；`larger.variant('fixed')` 的默认宽度仍为 7px，hover 为 10px。继承保留原规则或固定值，无需为新基础重写状态。这个机制同样适用于下面的颜色用途。

## 背景需要内容和边线

先定义一个天空蓝按钮，再定义内容与边线用途。下面是现有 API，省略 import；`oklch` 保留未指定的通道，案例用明度变化展示用途，不宣称任意底色都满足文字对比度。

```ts
const surface = variable('skyblue', {
  name: 'surface-color',
  states: {
    hover: base => oklch(base, { lightness: l => add(l, -0.04) }),
    active: base => oklch(base, { lightness: l => add(l, -0.08) }),
  },
  variants: {
    content: base => oklch(base, { lightness: l => multiply(l, 0.5) }),
    line: base => oklch(base, { alpha: 0.44 }),
    fixedContent: 'white',
  },
})
const content = surface.variant('content')
const line = surface.variant('line')
const handle = rules('.Button', [
  color({ background: surface, content }),
  boundary({ border: ['1px', 'solid', line] }),
])
const css = compileCSS()
```

将 css 写入 style，给 button 设置 `class="Button"`，即可观察三种颜色。content 默认是对天空蓝减半明度；hover 在这个新基础上再减 0.04，active 则减 0.08。状态没有先作用于母体再被转换，也不会被应用两次。

例如把基础换成 `oklch(0.6 0.1 240)`，内容默认明度为 0.3，hover 为 0.26；如果先 hover 再转换，会错误地得到 0.28。消费属性保持变量引用，等效 CSS 可使用不同的表达式写法：

```css
.Button {
  background-color: var(--surface-color);
  color: var(--surface-color-content);
  border-color: var(--surface-color-line);
}
/* --surface-color-content 的默认值是 T(基础)，hover 时是 H(T(基础))。 */
```

## 换一个基础，继续复用定义

```ts
const danger = surface.derive('tomato', 'danger-surface-color')
const dangerContent = danger.variant('content')
const fixedContent = danger.variant('fixedContent')
const otherContent = dangerContent.derive('navy', 'other-content')
```

dangerContent 从 tomato 计算默认值，再沿用 hover/active 规则；fixedContent 默认仍为白色，其 hover/active 作用于白色。otherContent 默认变成 navy，仍保留同一套状态。规则和固定值都原样继承，无需业务手动枚举状态。

选择 content 后，`content.variant('line')` 会拒绝：line 属于 surface 的父层定义。应从 `surface.variant('line')` 取得它。content 派生出的对象同样不会找回这份父层变体。

## 一个输入控制 Button 的多个用途

如果需要区域改色，先提供一个真实的 Variable 输入，让用途规则保留对它的引用：

```ts
const tone = variable('skyblue', 'button-tone')
const uses = surface.derive(tone, 'button-uses')
const localContent = uses.variant('content')
const localLine = uses.variant('line')
// 接续前例时，先撤销旧规则，再登记新的输入。
handle.remove()
const handles = [
  rules('.Button', [
    color({ background: tone, content: localContent }),
    boundary({ border: ['1px', 'solid', localLine] }),
  ]),
  rules(['.Button', '&.Green'], declare(tone, 'seagreen')),
]
const updatedCSS = compileCSS()
```

将页面 style 更新为 updatedCSS，给目标 Button 增加 Green 类，一条 tone 声明就能改变背景及引用它的用途，兄弟按钮继续使用天空蓝。只改一个部件时，直接声明 localContent 或 localLine。共享全局颜色也是同一用法：将 tone 的默认值指向全局 Variable；全局、区域和组件各自通过明确的声明控制。

这里的联动来自表达式引用 tone。前一个 literal 示例直接转换 skyblue，之后声明 surface 为 green 不会改写那些 literal 表达式。Name 仍是 CSS 标识对象并支持字符串化，同名或派生血缘都不能替代真实引用。

## 实际业务与清理

[Button.style.ts](../../../components/kits/Button/Button.style.ts) 将 soft、strong、line 规则及固定 content 纸色放进 buttonColor，使用处直接写 buttonColor.variant(名称)，危险语气只声明 buttonColorInput；soft/strong 的透明度由同一个 buttonOpacity 派生，自动保留 disabled 定义。无需为危险语气重新写每个用途的转换，也无需重复列出 disabled 状态。

[编译测试](../../test/变体转换后状态使用独立基础.test.ts)验证规则、固定值、派生和消层；[浏览器测试](../../test/变体颜色与局部覆盖在浏览器中生效.browser.test.ts)验证实际 hover、共享来源与局部隔离。挂载示例后移除 style 和 DOM，并撤销 sizeHandle、handle 及 handles 中的登记句柄。

自动定义提供所需默认，业务不应将全部变体取出后分别补写默认声明。Button 已移除成员别名及6条冗余无值声明；保留的局部颜色输入、strong、画布和strength声明分别保证当前组件的公式重算、状态与modify基础。这些局部作用域选择不能由根默认补齐替代。

# 反例

| 目的落空的结果 | 验证方式 |
| --- | --- |
| 派生换了基础，变体规则还使用旧基础 | 派生 20 后，乘 2 得到 40，hover 加 3 得到 43。 |
| 固定 variant 或 state 被按新基础自动改写 | 固定变体仍为 7，固定 active 仍为 99；0 也有效。 |
| 状态在转换前执行或重复执行 | 浏览器内容明度应为 0.26，而非 0.28 或 0.22。 |
| 变体结果丢失 derive，或重新带回父层 variants | 结果可派生并继承状态，但不能取得父层其他用途。 |
| 只凭名称或血缘激活其他定义 | literal 变体不激活母体；纯 Name 不带入无关同名定义。 |
| 共享引用被提前冻结，或局部覆盖污染兄弟 | 全局与当地输入分别改变目标颜色，独立覆盖的内容和兄弟保持各自结果。 |

# 推断依据

用户明确要求 variant 返回 Variable、转换默认值、原样继承状态、消掉父层变体；所有 Variable 的 derive 都继承 state 和 variant，其中规则或固定值均保持原定义，不增加联动机制。options.variants 是落地采用的配置位置；变体通过普通派生创建，沿用 derive 的等级规则。重复获取不承诺对象相等，不做缓存；嵌套子变体留待未来需求。
