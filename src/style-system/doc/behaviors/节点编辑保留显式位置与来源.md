# 目的

扩展明确指定在哪插入、由谁需要以及何时撤销；移动和查询不能暗中改变来源，共享结果不因一个消费者退出而丢失。

# 典型案例

行为伪代码，不能直接运行：扩展用`insert(position, [key, content], provenance)`在显式锚点前后插入width8px/height12px；读取输出声明的有序序列应为width8→height12。将height移到width之前后，序列应为height12→width8，值、条件与来源不变；仅核两个计算值不能证明移动有效。

先登记同key但不同条件及同条件但不同key的对照项，search同时给key和conditionPath只返回两者均匹配的项；查询前后输出序列与撤销计数相同，has与search是否为空一致。给同一产物登记两个owner和onRemove计数：output-only后CSS中该产物退出，但清理计数仍0；真正撤销最后来源后清理计数变1。另一个仍有来源的共享产物在先撤销一个owner后仍输出。

公开位置输入before/after互斥，锚点、conditionPath与来源owner明确传入；这是现有类型契约，不补不存在的运行时互斥校验。插入位置与`[Key, content]`分别传入，identity/productTag/resourceAddress为可选标识。每次紧邻锚点，不暗设插入游标；连续向后插入并保持顺序时使用前次返回节点作新锚点。move仅变位置，不变条件和来源。

search({key, conditionPath, productTag, resourceAddress})返回有序匹配，未提供字段不限制，提供字段取交集；Key按属性名、条件按输出地址匹配。has沿用同一查询语义。查询不改变队列或来源，nodes返回快照而非可通过修改数组直接改变队列的活体容器。

`depend(product, {owner})`登记显式来源；`onRemove(node, cleanup)`登记撤销清理。`remove(node)`真正撤销并清理失去全部来源的后继；`remove(node, {from: 'output'})`只退出输出，保留来源和产物，不触发真正撤销清理。扩展必须能观察两种操作区别，不能只为结果暂不输出而销毁共享来源。

清理：先验证output-only未触发清理，再执行真正撤销；移除本例登记与DOM/style，其他来源贡献保留。

# 反例

查询取并集、移动改变来源、隐式游标导致顺序反转、输出退出触发销毁、单个owner退出误删共享产物，均违反目的。
