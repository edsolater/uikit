Variable让业务复用一整份定义：基础内容、状态反馈和不同用途可以一起保存。它先描述样式规则，真正使用时再落实到CSS，因而能作为组件样式的骨骼。业务需要换一个基础时，不必先了解并重写其中每个状态。

# 定义一份尺寸，再把它用到组件上

假设Control普通宽度为10px，hover时在基础上加3px，active时固定为12px：

```ts
const controlSize = variable('10px', {
  name: 'control-size',
  address: '.Control',
  states: { hover: base => add(base, '3px'), active: '12px' },
  variants: { wide: base => multiply(base, 2), fixed: '7px' },
})
rules('.Control', [[key('width'), controlSize]])
```

创建controlSize只保存定义；登记使用后，编译才保障.Control有相应声明。实际页面普通宽10px、hover宽13px、active宽12px。width读取同一个CSS变量，业务不必再给width分别写hover和active规则。variants先保存用途定义，后面需要时再选择。

address称为根据地，它回答“这份定义应该存在在哪里，状态属于谁”。省略address时根据地是根元素；要让每颗Control响应自身交互，就明确使用.Control。states只随根据地展开，不向每个直接或间接消费点复制；完整状态选择见[状态反馈与条件选择](状态反馈与条件选择.md)。

# 根据地已有值时保留，没有时才补

自动声明的目的是免去业务补基础的操作，同时尊重已经明确设置的值。

```ts
const panelGap = variable('8px', { name: 'panel-gap', address: '.Panel' })
rules(['.Panel', '.Item'], [[key('gap'), panelGap]])
```

Panel缺声明时在那里补8px，Item继承；Panel已有20px时保留20px。不能改在root或每个Item声明。另一个地址有同名声明，也不能阻止Panel补齐自己的定义。

存在声明和有可输出的值是两件事：显式undefined仍算已有声明，不能触发创建内容回填。根只是缺省地址，不是一套独立默认兜底；自动根声明使用低特异度`:where(:root)`，不压过显式根主题。

真实换值使用`declare(v, newValue)`。在根据地赋值，状态规则基于该处新基础；在其他地址赋值，只改变当地值，不把v的states带过去。普通使用不需要`declare(v)`或重传创建内容，无值declare仅是显式使用创建内容的逃生舱。局部赋值与公式继承见[CSS作用域与层叠](CSS作用域与层叠.md)。

多个消费者共享所需定义，撤销一个不误删另一个需要的内容；已有业务声明不被自动清理。扩展将根据地声明改名或移走后，旧状态产物撤回，后续消费仍保障原指定地址及其状态。

# 从已有定义复用规则

LargeControl想把宽度改为20px，同时保留Control的状态和用途定义。此时使用variableFrom：

```ts
const largerSize = variableFrom(controlSize, '20px', {
  name: 'large-control-size', address: '.LargeControl',
})
rules('.LargeControl', [[key('width'), largerSize]])
```

LargeControl普通宽20px、hover宽23px、active仍宽12px。hover是规则，会基于新基础计算；active是固定值，原样继承。这个区别让定义者自己选择相对变化或固定结果，复用过程不额外创造联动。

`variableFrom(source, value, nameOrOptions?)`返回独立Variable，后两项材料位置与variable一致。states和variants按名称原样继承规则或固定值；显式同名项覆盖，其余保留。例如仅配置`states: { hover: '30px' }`会替换hover，active和用途仍保留。

名称可省略沿用来源，也可提供字符串、VariableName或映射函数：

```ts
const smallerSize = variableFrom(controlSize, '6px', name => `small-${name}`)
```

address省略沿用来源，显式地址仅改变新定义。复用不会修改来源JS定义，也不会因来源之后的JS配置变动而自动更新已创建结果；若沿用CSS名称，两者仍会参与同名CSS层叠。

# 选择一种用途

LargeControl已经有完整定义。需要它的宽版尺寸时，在使用处选择wide；需要固定尺寸时选择fixed：

```ts
const wideSize = largerSize.variant('wide')
const fixedSize = largerSize.variant('fixed')
rules('.LargeControl', [
  [key('width'), wideSize],
  [key('height'), fixedSize],
])
```

这一组规则替代上节只设置width的规则。wide先把20px变成40px，继承的hover再加3px；fixed先取7px，hover再加3px。active是固定12px，两者都原样使用。

| 读取的Variable | 普通 | hover | active |
| --- | --- | --- | --- |
| largerSize | 20px | 23px | 12px |
| wideSize | 40px | 43px | 12px |
| fixedSize | 7px | 10px | 12px |

variant(name)返回普通Variable，根据地沿用来源，名称沿用后缀规则，状态作用于变体自己的基础。结果仍可作为variableFrom的来源，例如将wideSize换基础为50px后，hover为53px。

选择时消掉父层variants；再次复用结果不会恢复它们。未知名称明确失败，不承诺重复选择得到同一对象，当前不提供嵌套变体。

variableFrom解决“换基础、保留定义”，variant解决“选择一种用途”。如果要求所有固定值和规则结果共同变化，使用[adjust或modify](完整结果调整与局部修改.md)，不能只换基础后声称整份结果都已改变。

# 名称用于CSS，具体对象携带定义

业务引用具体Variable，才能确定需要哪份定义。同名仅表示CSS标识相同，不能据此从另一JS对象借入状态或资源：

```ts
const a = variable({ default: 'red', hover: 'pink' }, { name: 'tone', address: '.A' })
const b = variable({ default: 'blue', active: 'navy' }, { name: 'tone', address: '.B' })
```

只消费a不激活b的生产函数、状态或onActive资源。消费两者时A不借入b的active，B不借入a的hover；同名CSS仍按浏览器层叠互相影响，独立JS对象不等于CSS隔离。

Variable.name是创建时绑定的VariableName对象，不支持事后替换。String(a.name)、a.name.toString()及模板拼接得到逻辑名`tone`；Name对象作为内容消费才输出`var(--tone)`，Variable声明地址为`--tone`。创建的字符串名称可带--前缀，按既有名称正规化处理。

普通字符串按原CSS文本消费，不自动变成引用：`'var(--tone)'`原样提供引用，String(a.name)仅提供文本`tone`。Name和字符串都不查找或激活同名Variable，也不建立对象依赖。

# 创建输入与继承的完整边界

公开创建形状是`variable(defaultContent, nameOrOptions)`或`variable({ default, ...states }, nameOrOptions)`，均返回Variable。基础内容和名称必填，不提供匿名创建或遗漏基础内容的重载。

```ts
const gap = variable('4px', 'gap')
const shorthand = variable({ default: '8px', hover: '16px', active: '12px' }, {
  name: 'shorthand-size', address: '.Shorthand', states: { hover: '20px' },
})
const empty = variable({ default: undefined }, 'empty')
```

shorthand的hover为20px，active仍为12px：options.states覆盖简写中的同名状态，其余保留。显式default:undefined是提供内容，不等于缺字段。内容可为普通值、具体Variable、Value、Expression、无参生产函数或内容协议对象；创建不执行生产函数，求值边界见[内容包装与组合](内容包装与组合.md)。address接受现有Condition、路径字符串或路径数组。

variableFrom省略priority时为来源加一，显式0有效；registration、onActive及compileWaveIndex须显式提供，不随入口复用。规则复用不替代对这些可选行为的明确配置。
