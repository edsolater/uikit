# 目的

同一个 CSS 资源名在一次结果中只能对应一份完整定义。若后来定义接管该名字，旧定义的局部字段不能混入新定义，否则浏览器会得到从未声明过的组合。

# 典型案例

```ts
const oldBody: Rules = [
  [undefined, '--old', '100px'],
  [undefined, 'result', 'var(--old)'],
]
const nextBody: Rules = [[undefined, 'result', 'var(--old, 24px)']]
const baseline = compileCSS()
const first = cssFunction('--probe() returns <length>', oldBody)
const second = cssFunction('--probe() returns <length>', nextBody)
const oldCall = first()
const nextCall = second()
expect(compileCSS()).toBe(baseline)
const css = compileRules([
  [[condition('.First')], 'width', oldCall],
  [[condition('.Second')], 'width', nextCall],
])

expect(css.match(/@function --probe\(\) returns <length>/g)).toHaveLength(1)
expect(css).toContain('result: var(--old, 24px);')
expect(css).not.toContain('--old: 100px;')
```

属性注册同名时也要检查整份定义，不允许仅替换一个字段：

```ts
const old = variable(undefined, {
  name: 'replacement',
  registration: { syntax: '<length>', inherits: true, initialValue: '7px' },
})
const latest = variable(undefined, {
  name: 'replacement',
  registration: { syntax: '*', inherits: false },
})
const css = compileRules([
  [[condition('.Old')], 'width', old],
  [[condition('.New')], 'width', latest],
])
expect(css.match(/@property --replacement/g)).toHaveLength(1)
expect(css).toContain('syntax: "*";')
expect(css).toContain('inherits: false;')
expect(css).not.toContain('initial-value: 7px;')
```

## 注册的活跃消费与再次接管

行为伪代码，不能直接运行；迁移原节点树末段的现役注册资源约定。A/B为不同Variable对象但注册同一CSS地址：A描述符为length/继承/初值7px，B为通配类型/不继承/无初值。同次构建先消费A，再首次消费B，再增加一个A消费，结果须为完整B注册，第三个消费不能因重复遇到仍活跃的A而反盖成A。

同一对象的活跃消费者共享其当前资源贡献；不同对象首次消费可以接管同址注册。只有A本激活期的全部消费者都退出，随后重新激活A时，A才可再次完整接管。分别观察A→B→A仍为B、A全部退出再激活后为A，不能只测旧→新单向替换。这里保护可观察注册选择，不规定私有状态或存储方式，也不恢复按名字激活Variable。

清理：逐个撤销案例消费者；撤销一个共享消费者时保留其余需求，最后撤销全部本例规则与DOM/style。

# 反例

若输出两份同名定义，新定义中残留旧字段，或仍活跃的A再次消费反盖B、全部退出后重新激活A却不能接管，均违反目的。
