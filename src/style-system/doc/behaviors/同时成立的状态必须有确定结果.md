# 目的

一个主体可以同时满足多个状态，最终样式仍须稳定、可预期。快捷条件按中央顺序排列，不随配置字段书写顺序改变；直接条件随后按配置书写顺序排列，不要求登记。

# 典型案例

```ts
const first = variable(1, {
  name: 'priority-size', states: { active: 3, hover: 2 },
})
const second = variable(1, {
  name: 'priority-size', states: { hover: 2, active: 3 },
})
const compile = (size: typeof first) =>
  compileRules([[[condition('.Probe')], 'width', size]])

expect(compile(first)).toEqual(compile(second))
const direct = variable(1, {
  name: 'direct-size', states: { '&[data-tone="danger"]': 2 },
})
expect(compile(direct)).toContain('&[data-tone="danger"]')
```

浏览器测试还要让两个状态确实同时匹配，观察计算值：

```ts
stateCondition('behaviorPriorityA', condition('&[data-a]'))
stateCondition('behaviorPriorityB', condition('&[data-b]'))
const size = variable('10px', {
  name: 'priority-browser-size',
  states: { behaviorPriorityB: '30px', behaviorPriorityA: '20px' },
})
const style = document.head.appendChild(document.createElement('style'))
const element = document.body.appendChild(document.createElement('div'))
try {
  style.textContent = compileRules([[[condition('.Probe')], 'width', size]])
  element.className = 'Probe'
  element.dataset.a = ''
  element.dataset.b = ''
  expect(getComputedStyle(element).width).toBe('30px')
} finally {
  element.remove()
  style.remove()
}
```

# 反例

若快捷状态的配置书写顺序改变输出、直接条件因未登记被拒绝，或同时匹配 A 与 B 时未取后登记的 B 值，对应断言失败。
