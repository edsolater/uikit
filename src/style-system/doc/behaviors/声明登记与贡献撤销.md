样式登记让业务明确说明“在什么条件下，给哪个目标设置什么内容”。每次登记由自己的句柄管理，便于组件或功能退出时撤销自己的样式，不误删其他来源。

# 先登记，再观察、更新和撤销

`rule(condition, key, content)`登记一条规则并返回句柄。下面让Probe宽12px，再改为20px，最后退出这次登记：

```ts
const width = rule('.Probe', 'width', '12px')
try {
  expect(compileCSS()).toContain('width: 12px;')
  width.replace('20px')
  expect(compileCSS()).toContain('width: 20px;')
  width.remove()
  expect(compileCSS()).not.toContain('.Probe')
} finally { width.remove() }
```

compileCSS读取当前登记并返回CSS；挂载后Probe取得相应宽度。删除后下一次编译不再包含这次贡献，页面提交方式见[编译结果与页面提交](编译结果与页面提交.md)。重复remove没有额外影响；已删除句柄再replace明确失败。

每个句柄只管理自身，即使两次登记的地址、目标、内容完全相同，也必须能独立撤销：

```ts
const first = rule('.Probe', 'color', 'red')
const second = rule('.Probe', 'color', 'red')
try {
  first.replace('blue')
  expect([...compileCSS().matchAll(/color:\s*([^;]+);/g)]
    .map(([, text]) => text.trim())).toEqual(['blue', 'red'])
  first.remove()
  expect([...compileCSS().matchAll(/color:\s*([^;]+);/g)]
    .map(([, text]) => text.trim())).toEqual(['red'])
  expect(() => first.replace('green')).toThrow('已删除')
} finally { first.remove(); second.remove() }
```

这保护的是登记的归属，而不是给最终CSS文本去重。批量句柄同样只撤销自己的一整批；一个消费者退出时，其他消费者仍需的资源保留，最后需求退出才清理，见[按需资源与同名替换](按需资源与同名替换.md)。撤销后重新编译不得复活旧贡献。

# 将属性和完整效果一起登记

多项样式使用`rules(condition, items)`，其中Declaration元组明确目标与内容，Mixin提供一组所选效果。元组目标使用Key或Variable，不接受裸字符串或普通声明对象；低层rule与Rules允许字符串目标。

Key表示原生属性，不要求预登记；如果使用别名，必须先明确它指向哪个属性：

```ts
const color = variable('red', 'public-color')
const handle = rules('.Probe', [[key('color'), color], [color, 'blue']])
key('align-items')
const alignment = rule('.Probe', 'alignItems', 'center')
try {
  const css = compileCSS()
  expect(css).toContain('color: var(--public-color);')
  expect(css).toContain('--public-color: blue;')
  expect(css).toContain('align-items: center;')
  expect(css).not.toContain('alignItems:')
} finally {
  handle.remove()
  alignment.remove()
}
```

上例中Variable同时作为内容引用和赋值目标；只登记属性时不必先创建Variable。key('align-items')明确登记其既有别名，避免alignItems被当成另一个CSS属性输出。同名别名登记不能悄悄改指另一属性。

Mixin的目的，是将一个完整效果写成一次选择，同时避免引入未选择的效果。例如contentLayout({ mode: 'center' })提供inline-flex和双向居中；contentLayout({ gap: '8px', padding: ['4px', '12px'] })只提供间距和内边距，不能顺带改变display或alignment。

# 一批登记整体生效

一批样式常常共同表达一个效果。如果中间失败却留下前半批，调用者就会得到残缺结果。因此嵌套组合保留输入顺序，空项与undefined内容不输出；无效条目或输入迭代中断时整批失败，既有登记保持。

```ts
const color = key('color')
const padding = key('padding')
const batch = rules('.Probe', [
  [color, 'red'], undefined,
  [[padding, '4px'], [color, 'blue']], [padding, undefined],
])
try {
  expect([...compileCSS().matchAll(/(color|padding):\s*([^;]+);/g)]
    .map(([, property, text]) => [property, text.trim()])).toEqual([
      ['color', 'red'], ['padding', '4px'], ['color', 'blue'],
    ])
} finally { batch.remove() }

const original = rule('.Probe', 'color', 'green')
try {
  function* interrupted(): IterableIterator<DeclarationItem> {
    yield [color, 'red']
    throw new Error('迭代中断')
  }
  expect(() => rules('.Probe', interrupted())).toThrow('迭代中断')
  expect(compileCSS().match(/color:\s*([^;]+);/g)).toHaveLength(1)
  expect(compileCSS()).toContain('color: green;')
} finally { original.remove() }
```

# 同址贡献如何选择和组合

多个来源可能同时为同一目标提供内容。这里解决两种不同意图：Variable需要选出适用值；带join的普通Key需要按约定组合贡献。两者都只处理同一完整地址，跨地址的CSS层叠另行决定。

同一完整CSS地址及目标中，较高priority的有效Variable贡献优先；同等级后写的有效贡献优先。undefined不能覆盖已有有效值。普通Key缺省priority为999，普通Variable为0；variableFrom省略时为来源加一，显式0仍为0。不同地址的最终结果由[CSS作用域与层叠](CSS作用域与层叠.md)决定，不能用priority跨选择器压过浏览器规则。

可用同址值4(priority0)、7(priority2)、9(priority2)验证：先取9，撤销9后取7，加入undefined仍取7。从priority5来源复用且显式priority0的定义不能压过priority1；若误把0当成缺省6，这个结果就会反转。

普通Key的重复贡献按其join约定组合，不套用Variable只选一个值的规则：

join收到带content的Value视图，下面用item.content取得各项数值；2和3共同表达结果5，删除3的贡献后应回到2。

```ts
const stack = key('z-index', {
  join: values => values.reduce((sum, item) => sum + Number(item.content), 0),
})
const first = rule('.Stack', stack, 2)
const second = rule('.Stack', stack, 3)
try {
  expect(compileCSS()).toContain('z-index: 5;')
  second.remove()
  expect(compileCSS()).toContain('z-index: 2;')
} finally { first.remove(); second.remove() }
```

join只接收同完整目标/状态地址中获选等级组的贡献，输入Value按源序排列。单项直接使用，不调用join；没有显式join时默认逗号组合。组内唯一显式join接管默认规则，多个不同显式join冲突明确失败。结果保持组内最后贡献的外部顺序，其他地址与状态不混入。

回调看到原content及对象身份。保留输入Value时，输出读取它在原消费位置的编译结果，不额外执行生产函数；若把某项content换成依赖新位置的内容，新内容在结果消费处编译。两个原位置分别得到4和7时，组合不得因位置丢失读到另一值。join返回值继续按内容协议消费。

阴影和$boxShadow沿用默认逗号组合，重复项保序；none或CSS全局关键字不表示编译期清空此前贡献，组合是否有效交给浏览器判断。join冲突不交付半份CSS，也不替调用者删除源登记。

# 声明材料的输入边界

`declare(key, content)`构造Declaration，交给rules使用。`declare({ key, content }, replacement?)`也可读取自然材料，不要求品牌或特定构造器；这样已有材料可以直接参与声明，不必包装成指定类。

自然材料须实际提供content字段；显式undefined表示无有效内容，不能被换成另一个目标或默认值。可选declarations保留共同声明依赖，即使覆盖自身内容也不丢失。属性名输出须为字符串，不得把函数源码当属性名。adjust/modify目标须为自定义属性材料，非法材料明确失败；公开类型的拒绝不等于为所有强制转换输入新增运行时校验。
