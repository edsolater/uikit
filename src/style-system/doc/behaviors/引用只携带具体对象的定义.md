# 目的

引用谁就使用谁的定义；名称可用于命名和CSS引用，不暗中选择另一个JS对象。

# 典型案例

行为伪代码，不能直接运行：a默认red、hover为pink，b默认blue、active为navy，两者同名tone。另为a/b各配置onActive独有资源规则`--resource-a: 1`/`--resource-b: 1`。先仅在A作用域消费a并挂载：普通红、hover粉，只有资源a。再在独立B作用域消费b：普通蓝、active藏青；A按压不凭空取得b的active，B悬停不凭空取得a的hover。两个作用域分别声明自身基础，避免将同名CSS继承误当JS定义关联。另起独立构建，只消费Name或字符串，a/b资源均不应出现。

输入示意：`const a = variable({ default: 'red', hover: 'pink' }, 'tone'); const b = variable({ default: 'blue', active: 'navy' }, 'tone')`；onActive资源规则按上述伪代码分别配置。只消费a时，b的默认生产函数、状态、按需资源不被激活。两者都消费时，各自保持自己的依赖和状态；不能因同名把b的状态注入a。重复CSS地址仍按CSS层叠，不能承诺两个同名地址在浏览器中互不影响。

**现役公开名称契约**：`String(a.name)`、`a.name.toString()`和模板拼接得到不带`--`的逻辑名`tone`；CSS声明地址仍是`--tone`，内容引用是`var(--tone)`。Name在创建时绑定。单独消费`a.name`或纯字符串`'var(--tone)'`只提供CSS引用，不能查找、激活同名Variable，也不能建立具体对象依赖。

创建名称的字符串输入可以带--前缀，沿既有名称正规化处理；创建后不替换绑定的Name。按名称关联及激活定义的旧职责已退出，不因核心重写恢复。

清理：撤销上述消费后重编译，a/b独有资源均退出；移除案例元素、案例style，保留其他登记。

# 反例

创建顺序改变引用归属、Name触发未引用对象资源，或另一同名对象借入状态，都违反目的。CSS同址层叠导致的共享地址效果不等于JS对象关联。

# 推断依据

用户裁决保留Name对象、移除按名关联及激活；字符串化格式为现役公开契约。[具体身份测试](../../test/具体变量身份与定义派生.test.ts)提供核对案例。实际输入改变后的计算由[当地输入响应](派生结果跟随当地输入变化.md)负责。
