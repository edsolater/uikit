# 目的

一组样式材料替换另一组时，只应改变双方共同拥有的角色。未匹配角色继续保持原值，额外来源不被激活；同一目标出现矛盾来源时，不能静默选一个覆盖。

# 典型案例

```ts
const target = variableCluster({
  default: variable('black', { name: 'target-color' }),
  soft: variable('gray', { name: 'target-soft-color' }),
  line: variable('white', { name: 'target-line-color' }),
})
const unused = variable('orange', { name: 'source-extra-color' })
const unusedActive = vi.fn()
unused.onActive = unusedActive
const source = variableCluster({
  default: variable('blue', { name: 'source-color' }),
  line: variable('navy', { name: 'source-line-color' }),
  extra: unused,
})
const css = compileRules([[[condition('.Probe')], target, source]])
expect(css).toContain('--target-color: var(--source-color, blue);')
expect(css).toContain('--target-line-color: var(--source-line-color, navy);')
expect(css).not.toContain('--target-soft-color:')
expect(css).not.toContain('--source-extra-color:')
expect(unusedActive).not.toHaveBeenCalled()

const sharedName = 'conflicting-target-color'
const conflictingTarget = variableCluster({
  default: variable('black', { name: sharedName }),
  soft: variable('gray', { name: sharedName }),
})
const conflictingSource = variableCluster({
  default: variable('blue', { name: 'first-source-color' }),
  soft: variable('pink', { name: 'second-source-color' }),
})
expect(() => compileRules([[[condition('.Probe')], conflictingTarget, conflictingSource]]))
  .toThrow('同名目标存在对象或来源冲突')
```

同名目标的冲突不是“后写覆盖”：目标的 `default` 和 `soft` 使用不同 Variable 对象却共用 CSS 名字时，整条声明报错。

# 反例

若未匹配成员被覆盖、来源额外成员被激活，或共同成员漏掉，CSS 断言失败；若同名目标冲突被静默吞掉，冲突测试失败。
