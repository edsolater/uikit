# 目的

复用同一份内容应得到稳定结果，不能被误判为错误；真正回到自身的依赖必须及时终止。编译失败时不能把循环之前得到的部分 CSS 当作成功结果交付。

# 典型案例

```ts
const shared = value('red')
expect(compileRules([
  [[condition('.Probe')], 'color', colorMix(shared, shared)],
])).toContain('color-mix(in oklab, red, red)')

const cycle = value(undefined)
cycle.content = cycle
expect(() => compileRules([[[condition('.Probe')], 'color', cycle]]))
  .toThrow('循环引用')

const first = value(undefined)
const second = value(first)
first.content = second
expect(() => compileRules([[[condition('.Probe')], 'color', first]]))
  .toThrow('循环引用')

const recursive: Rules = []
recursive.push([undefined, undefined, recursive])
expect(() => compileRules(recursive)).toThrow('递归引用')
```

## 有限输入的完成边界

生产函数错误或真正的内容/规则循环明确报告，不能交付半份结果或无界增长；合法有限的共享、状态、局部覆盖组合应完成，不能将共享误判成循环。不规定耗时秒数、编译波数、内部节点或中间CSS变量数量。

当前核心调整已暂停，中间版本有局部依赖/优先级链失败；曾出现长时间编译和状态产物增长，但没有据此证明所有嵌套状态无限循环。27秒等观测不是永久性能阈值，也不能把当前缺陷改写为使用限制。

# 反例

若共享同一对象被误报为循环，第一个断言失败；若直接、间接或 Rules 结构递归无限遍历、返回部分 CSS 或不抛错，后续断言失败。
