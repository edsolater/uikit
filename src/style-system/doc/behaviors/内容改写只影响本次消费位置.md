# 目的

内容扩展能明确修改当前消费并安全复用同一内容，不能把一个位置的改写或过期上下文写到另一个位置。

# 典型案例

行为伪代码，不能直接运行：同一内容对象分别用于A.width与B.width，onCompile(context, ast)按本次输入调用`ast.setContent(context, '8px')`或`'12px'`；构建挂载后A为8px、B为12px。嵌套对象接收自身input，不能误改外层另一内容。将A设为显式undefined后A该贡献退出，B仍12px；保留已退出同步通知的context再调用setContent应明确失败。

公开onCompile返回void，返回值不作为替代内容；需要改内容使用Controller。context包含可改写node引用，以及角色开始时的conditionPath/key/content输入快照；改变node不反改快照。input为当前被通知对象，role区分声明目标/声明内容；session在同次编译内是不透明稳定身份，不同编译不混用私有状态。Controller不暗含“当前位置”。

内容对象可按需提供dependencies、onActive资源及toCSSString输出；没有输出能力的合法容器仍可提供依赖/资源，不强制为自身输出声明。resolver取得已编译子内容；`getCompiledContent`/`getCompiledValue`/`getContentCompilation`读取当前消费已留下的结果及实际依赖，不为查询再次执行源函数或getter。未访问的输入保持原含义，不凭查询激活新定义。

公开Expression只组织自身依赖和CSS输出，类型不允许onActive/onCompile/compileWaveIndex/resourceIdentity；createJSSContent(output, dependencies?)返回这样的Expression。CSSFunction则是独立定义主体，调用返回依赖主体与实参的Expression，不把资源定义放进调用表达式。类型排除不等于对任意强制类型转换输入新增运行时防御。

清理：撤销A后重新构建B仍正确；最后撤销B与本例DOM/style，过期上下文不能再写当前消费。

# 反例

A改写影响B、把onCompile返回值当结果、快照随node变化、失效上下文继续写入、查询已编译结果又运行生产函数，均违反目的。
