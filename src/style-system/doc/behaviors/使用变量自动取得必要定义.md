# 目的

业务直接使用Variable就能获得有效样式，不必理解内部依赖或安排手工声明顺序，避免因为缺少定义而使样式缺值。

使用点增多不应把一次局部变化放大成反复搜索所有样式；已经成立的依赖关系应继续可用，处理范围随实际受影响的需求推进。

# 行为

每次使用具体Variable都检查`:root`当前声明：已有同CSS名称时保留它，没有时补创建默认基础及其实际依赖的必要定义。根兜底不展开state，也不作为区域当前定义参与查找。调用者无需补依赖清单；存在适用显式声明时保留当地覆盖，兄弟或更窄条件中的声明不能让未被覆盖的消费失去默认。撤销覆盖后恢复适用基础，消费全部退出后按资源生命周期清理。

声明、实际引用或消费者变化后，只更新相应需求；新出现的受体也能接到已存在的输入声明。无关消费者不重复分析，没有新的受体或变更待处理时结束本次激活。这个要求约束工作范围，不要求某种索引、缓存或树的实现。

# 典型案例

行为伪代码，不能直接运行：创建Ordinary与Compact两个兄弟元素，登记下方输入后构建挂载，读取各自计算gap。再撤销Compact覆盖并重挂载，两处均应4px；更窄条件不匹配时也不能使Ordinary失去4px。

```ts
const gap = variable('4px', 'gap')
rules('.Ordinary', [[key('gap'), gap]])
rules('.Compact', [declare(gap, '2px'), [key('gap'), gap]])
```

Ordinary应为4px，Compact应为2px。Compact、其他兄弟或更窄条件中存在声明，不能让Ordinary失去默认。适用的祖先或当前位置显式声明应保持有效，自动补充不能将其顶回默认。撤销Compact覆盖后，其消费恢复适用基础；其他消费不受牵连。

`declare(gap)`明确采用该对象的默认；`declare(gap, '2px')`提供当地基础，均不修改共享JS创建配置。消费应取得其适用的默认或显式基础；所有消费退出后按[资源生命周期](未使用的资源不进入样式结果.md)清理。

默认也可以是引用其他Variable的表达式；实际依赖同样须取得必要定义。默认基础可用与[当前设定保持](变量当前设定与当地依赖保持有效.md)分别保护两个结果，不能互相替代。

例如`:root`已有`--gap: 6px`时，即使被消费的Variable创建默认为4px，也不另补4px覆盖它。这里按CSS名称识别已有声明，不要求由同一个Variable对象登记。根兜底只提供基础；两个组件的悬停状态仍在各自使用Address发布，不因根悬停而一起改变。

根发布是达到目的的当前行为方式，不构成目的本身；等效方式变更仍须重新裁决对外约定。AST的贡献覆盖、去重与Variable按根清单补默认的职责见[实施计划](../../../../docs/plans/20261019_变量局部重声明与动态依赖.md)，具体算法归代码；本文不限定精确声明次数。

无关位置或条件的同对象声明曾抑制普通使用处的默认，这是已修复的实现缺口，不是使用要求。根默认保障、同名已有根声明保留及当地覆盖的验证分别见自动声明与浏览器测试。

清理：撤销两个消费及覆盖，移除案例元素和案例style；其他规则保留。

# 反例

普通消费因兄弟或更窄条件声明而失去默认，或自动默认顶掉适用显式基础，均违反目的。局部值不得污染外层的独立要求见[作用域隔离](局部样式覆盖不污染其他主体.md)。

# 推断依据

来源为用户明确要求被使用自动declare、删除手工补依赖，以及2026-10-19最新裁决：AST提供根声明清单，按CSS名称保留已有基础，缺失才补默认；根兜底不展开state、不进入当前定义记录。此裁决更新此前全部交由AST判断默认是否存在的方案。验证见[自动声明测试](../../test/变量使用自动补根声明并保持引用简短.test.ts)、[依赖声明测试](../../test/变量依赖与声明行为.test.ts)及[根默认浏览器测试](../../test/根默认声明与局部派生状态在浏览器中生效.browser.test.ts)。

工作范围来自同日用户对性能的补充要求：按受影响的对象逐波激活，没有受体就结束。验证见[激活工作量测试](../../test/变量依赖激活不反复扫描全部样式.test.ts)，时间测量及环境归实施记录，不把单机毫秒数冻结为API契约。
