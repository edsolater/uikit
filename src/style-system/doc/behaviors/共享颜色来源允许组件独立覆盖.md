# 目的

组件明确引用或加工有实际用途的共享颜色来源，同时保留自己的局部控制点。

# 典型案例

行为伪代码，不能直接运行：挂载共享来源、普通/危险Button及默认/filled分类输入；先改变区域全局表面，再只覆盖一个组件表面，读取实际背景/文字并按下表核对来源关系，邻近实例作为对照。

例如全局表面为白色，组件表面默认引用它；某区域把全局表面设为红色，该区域组件使用红色基础，外部仍白色。再在子区域直接覆盖组件表面为蓝色，仅该组件层采用蓝色基础，不反向修改全局或邻近组件。组件状态按自身已定义规则处理新基础。

lineColor是普通函数，返回引用具体基础及lineStrength的Variable；两个基础各自产生结果，共享强度变化影响实际读取它的位置，当地强度覆盖只影响当地。多种颜色用rules中的并列declare协调，不提供新的整组API。

公开边界已退出baseOn及绑定参数、baseRecipes祖先重绑、VariableCluster/clusterFrom/resolveVariable/clusterDeclarations；不以改名的组对象或兼容包装恢复。这里只协调独立目标，具体引用关系仍由各结果内容明确表达。

Button的普通/危险与filled交集须同时正确：危险filled采用危险来源及filled含义，不能因补默认使其变回普通filled；区域覆盖仍保持其业务效果。明确退出buttonSurfaceCanvas独立控制点，但不要求所有Button颜色随单一全局值一起改变；危险强调文字等不应机械改为全局表面色。

| Button输入 | 应观察的配色关系 |
| --- | --- |
| 普通、默认外观 | 普通强调来源与全局表面按既有默认配方组合 |
| 危险、默认外观 | 危险强调来源与全局表面组合，不能借用普通强调来源 |
| 普通＋filled | 普通强调表面及对应可读文字 |
| 危险＋filled | 危险强调表面及对应可读文字；两条件同时成立，不能被普通filled覆盖 |

这些案例只保护共享来源与组件选择；状态基础、同时命中与禁用分别见[自身状态](样式状态只由变量自身承担.md)、[确定次序](同时成立的状态必须有确定结果.md)、[禁用交互](禁用主体不接受交互反馈.md)。全局表面变化只改变实际读取该来源的层，不为使filled也必然变色而改已有配方。

这些Button案例不把其具体混色比例或实现配方升级为全系统契约。试探中的Expression身份分支及“所有显式表面覆盖都跳过状态加工”也不是通用Variable承诺。

清理：逐项撤销组件覆盖、区域全局覆盖并重挂载核对恢复；最后移除案例Button、登记和案例style。

# 反例

组件直接复制全局常量而失去共享来源联动、局部组件覆盖反向污染全局或邻居、危险filled被普通来源接管，均不满足案例。
