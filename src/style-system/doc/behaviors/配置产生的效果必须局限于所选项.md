# 目的

业务选择一项布局效果时，只应得到该配置要求的结果。未选择居中模式，就不能顺带改变显示方式和对齐；不同配置之间的效果边界须清楚。

# 典型案例

```ts
const centered = rules('.Center', [contentLayout({ mode: 'center' })])
const spaced = rules('.Space', [
  contentLayout({ gap: '8px', padding: ['4px', '12px'] }),
])
try {
  const css = compileCSS()
  const centerBlock = css.match(/\.Center\s*\{([^}]*)\}/)?.[1]
  const spaceBlock = css.match(/\.Space\s*\{([^}]*)\}/)?.[1]
  expect(centerBlock).toContain('display: inline-flex;')
  expect(centerBlock).toContain('align-items: center;')
  expect(centerBlock).toContain('justify-content: center;')
  expect(spaceBlock).toContain('gap: 8px;')
  expect(spaceBlock).toContain('padding: 4px 12px;')
  expect(spaceBlock).not.toMatch(/display:|align-items:|justify-content:/)
} finally {
  centered.remove()
  spaced.remove()
}
```

`.Space` 没有选择 center 模式，因此不应自行输出 display 或 alignment；这使两个配置路径能够互相反证。

# 反例

若 center 缺少任一居中声明、gap 被忽略，或 `.Space` 被无条件设置布局模式，对应断言失败。
