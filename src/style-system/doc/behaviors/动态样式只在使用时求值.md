# 目的

样式定义可以保存尚未产生的内容。没有实际消费时，不应为了构造定义而执行它；消费时再得到内容，使定义阶段不必提前决定最终 CSS。

# 典型案例

```ts
const makeSource = vi.fn(() => '12px')
const size = variable(makeSource, { name: 'lazy-size' })
expect(makeSource).not.toHaveBeenCalled()

const handle = rule('.Probe', 'width', size)
try {
  expect(makeSource).not.toHaveBeenCalled()
  expect(compileCSS()).toContain('width: var(--lazy-size, 12px);')
  expect(makeSource).toHaveBeenCalledOnce()
} finally {
  handle.remove()
}

const serialize = vi.fn(() => '4px')
const content = value(createJSSContent(serialize))
expect(serialize).not.toHaveBeenCalled()
const padding = rule('.Padding', 'padding', content)
try {
  expect(serialize).not.toHaveBeenCalled()
  expect(compileCSS()).toContain('padding: 4px;')
  expect(serialize).toHaveBeenCalledOnce()
} finally {
  padding.remove()
}
```

Variable 的 source 与普通 Value 内容都用当前 API 演示延迟求值；目的不限定将来采用哪种内容生成方式。

# 反例

若只定义或登记就执行动态内容，或消费时没有取得它产生的值，对应断言失败。
