# 目的

业务样式必须明确写出“改哪个目标、给它什么内容”。即使声明入口或名称写法改变，编译也不能猜错目标、把配置对象当作声明，或要求调用者读取 Variable 的内部结构。

# 典型案例

```ts
const color = variable('red', { name: 'public-color' })
const handle = rules('.Probe', [[key('color'), color], [color, 'blue']])
key('align-items')
const alignment = rule('.Probe', 'alignItems', 'center')
try {
  const css = compileCSS()
  expect(css).toContain('color: var(--public-color, red);')
  expect(css).toContain('--public-color: blue;')
  expect(css).toContain('align-items: center;')
  expect(css).not.toContain('alignItems:')
} finally {
  handle.remove()
  alignment.remove()
}
```

这里用当前声明 API 表达目标与内容；将来入口写法可以变化，仍须得到同样明确的 CSS 目标。

# 反例

若变量目标被转成普通字符串、属性别名写到错误名称，或内容被当作另一条声明，输出结果会与案例不符。
