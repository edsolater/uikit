# 目的

业务样式明确表达改哪个目标、给它什么内容。更换核心须保留已公开的入口和名称含义，不能猜错目标、把配置对象当作声明，或要求调用者读取Variable内部结构。

# 典型案例

```ts
const color = variable('red', { name: 'public-color' })
const handle = rules('.Probe', [[key('color'), color], [color, 'blue']])
key('align-items')
const alignment = rule('.Probe', 'alignItems', 'center')
try {
  const css = compileCSS()
  expect(css).toContain('color: var(--public-color);')
  expect(css).toContain('--public-color: blue;')
  expect(css).toContain('align-items: center;')
  expect(css).not.toContain('alignItems:')
} finally {
  handle.remove()
  alignment.remove()
}
```

这里用当前声明API表达目标与内容，核心替换须保留该公开写法；API演进需用户另行裁决。

## 自然材料的内容字段

Declaration使用公开Key或对象自然材料；`declare({key, content}, replacement?)`读取这些材料，返回Declaration，自然材料须实际提供content，缺字段不能当作显式undefined。显式undefined不产生有效值，但不应被偷偷替换为另一目标或默认。可选declarations保存共同声明材料，其行为见[独立变化](独立变化可被多个来源复用.md)。不要求材料具有品牌或由特定构造器产生。

rules的公开声明输入为声明元组和Mixin组合；二元声明目标为公开Key/Variable对象，裸字符串目标和普通声明对象不在该公开类型内。这不等于撤销低层rule/Rules已经合法的字符串目标入口，类型拒绝也不表示对强制转换输入新增运行时校验。

Key可以直接表达原生CSS属性名，不要求预登记；已有别名解析保持明确映射，同名登记不能静默改指另一属性。属性名输出须为字符串，不把函数源码写为目标。Adjust/Modify目标材料的key须为CSS自定义属性，可带states和registration；不合法领域材料按现有入口明确失败，不能猜成另一操作。

# 反例

若变量目标被转成普通字符串、属性别名写到错误名称，或内容被当作另一条声明，输出结果会与案例不符。
