# 目的

调用者明确选择一个Variable的默认内容和名称，创建输入不因对象外形相似而被猜成另一种含义。核心替换保持既有公开API。

# 典型案例

以下是行为伪代码，不能直接运行；迁移的是现役公开契约。

```ts
const gap = variable('4px', 'gap')
const size = variable({ default: '8px', hover: '16px', active: '12px' }, {
  name: 'size', states: { hover: '20px' },
})
const empty = variable({ default: undefined }, 'empty')
```

登记gap与size到两个元素的width，构建挂载。gap为4px；size普通8px、hover20px、active12px，第二参数仅覆盖同条件，未覆盖状态保留。empty是已明确提供的undefined内容，不能因为无输出擅自换成另一默认。

公开形状为`variable(defaultContent, nameOrOptions)`及`variable({ default, ...states }, nameOrOptions)`，返回Variable。名称配置接受字符串或VariableName；默认输入ValueInput可为普通值、具体Variable、Value、Expression、无参生产函数及内容协议对象。简写以实际存在default字段为边界，不将缺字段视为显式undefined。默认和名称在公开类型中为必填，不提供匿名创建或遗漏默认的重载；绕过类型缺失名称不能产生合法匿名Variable。本条不增设独立运行时validator，也不承诺任意非法输入都在同一时点报同一错误。

派生的独立入口、名称映射和配置合并由[定义复用](延伸样式保留来源且允许覆盖.md)负责；内容执行由[延迟消费](动态样式只在使用时求值.md)负责，不在创建时执行默认生产函数。

清理：撤销案例登记，移除案例元素和挂载节点；后续构建不保留本例独有定义。

# 反例

缺失必填输入却猜出匿名定义、把合法内容对象误识别为options、忽略显式undefined、丢掉未覆盖active，或更换核心后改成另一套必填参数，都违反目的。
