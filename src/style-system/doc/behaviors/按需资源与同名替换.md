本文按 Token 模型描述资源行为，源码已完成 Token 迁移。

一份样式内容可能依赖属性注册、函数、关键帧或其他规则。使用者应当取得一份可用内容，而不是自己追踪并补齐其资源；退出时，也不能删除其他使用者仍需要的资源。

# 使用带入需求，最后需求退出才释放

```ts
const size = token('var(--probe-size)', {
  onFirstScan: () => [[[':root'], '--probe-size', '10px']],
})
const first = rule('.A', 'width', size)
const second = rule('.B', 'width', size)
```

只创建 size 不输出资源。编译实际使用后，A、B 的宽度引用可取得 10px。撤销 first，B 和资源仍在；撤销 second，独占资源才退出。纯 CSS 引用字符串不查找同名 Token，不暗中激活其 JS 定义。

内容从 A 换为 B 时，下一次构建取得 B 的值、state 与资源；A 的独占需求退出，共享需求保留。不能用上次生成结果代替当前需求，或因旧产物仍存在而把它误当作当前消费。

资源归属来自实际内容引用与定义明确持有的配置，不追踪创建历史。普通函数产生的新 Token 与直接创建的 Token 使用同一规则；函数决定如何组合 registration、onFirstScan 和 compileWaveIndex，消费方只处理结果及其实际需求，不重放加工。统一结构见 [Token的创建与复用.md](Token的创建与复用.md)。

onFirstScan 可以提供包含 modify 的规则。激活展开不限波次；所有影响相关 Token 的修改读取完毕后，才能确定最终 _kind 并坍缩。单个 Token 的读取顺序不能令新增修改丢失，也不能把“存在附加资源”误写成“所有内容在第一波直接输出”。

# 同名资源完整接管，不混成第三份定义

CSS 属性注册和具名函数以 CSS 名称识别。新的有效定义接管同名资源时，整份替换，不能把旧字段补进新定义。例如旧注册具有 initial-value:7px，新注册没有该字段，则接管后不能残留 7px。

仍活跃的旧定义增加一个消费者，不等于重新进入并接管资源。A 激活、B 激活接管、A 再增加消费，仍由 B 提供；A 全部退出后重新激活，才可能重新接管。这里约束接管事件，不按最后遍历到哪个消费者决定资源版本。

# 属性注册遵循浏览器含义

registration 表达 CSS 对类型、继承和初始值的约束，不是另一套创建默认值。提供 registration 使 Token 需要 CSS variable 身份，缺名自动生成。initialValue 不从 Token 的 default 推断；省略就不输出该描述符。

例如注册 inherits:false、初始值 1，父声明 4；没有自身声明的子元素取 1，不是 4。子元素明确声明 7 后取 7，撤销后回到 1。完整加工也必须尊重这个边界，不能为了让结果传播擅自改成继承。
