本篇面向扩展作者。已有Value、表达式和Mixin能满足需求时，业务直接组合它们；需要新的内容格式或编译扩展时，才使用这里的协议。它保护两件事：改写准确作用于本次消费，共享内容和来源能安全退出。

# 改写本次消费并读取其结果

同一个内容可能被多个位置使用。扩展必须区分这次正在处理哪一处，避免改变A时连B一起改掉。onCompile(context, ast)返回void，返回值不替代内容；改写使用ast.setContent(context, content)。

例如同一内容分别用于A.width和B.width，按本次输入分别setContent为8px/12px，页面应各得8px/12px；将A设为undefined只退出A的贡献，B保持12px。嵌套内容取得自身input，不能误改外层对象。保留已经退出同步通知的context再次setContent明确失败。

context.node是可改写节点引用；conditionPath/key/content是角色开始时的输入快照，改node不反改快照。input标识本次被通知对象，role区分declaration-key/declaration-content；session是同次编译内稳定的不透明身份，不同编译不混用私有状态。Controller没有隐含当前位置。

内容可按需提供dependencies、onActive和toCSSString；合法依赖/资源容器不必自身有输出。resolver及getCompiledContent/getCompiledValue/getContentCompilation取得本次已编译结果及实际依赖，不为读取再次运行生产函数或getter，不因查询激活未访问输入。usesContent(node,input)只反映当前目标/内容实际访问，旧替代记录存在不等于仍在消费。替换后独占资源退出，共享需求保留。

Expression只组织依赖和CSS输出，类型不接受onActive/onCompile/compileWaveIndex/resourceIdentity。createJSSContent(output,dependencies?)返回Expression；CSSFunction作为独立定义主体，调用返回依赖主体及实参的Expression。类型边界不表示为任意强制转换输入增加运行时防御。

# 显式查询和编辑节点

扩展可能需要在既有声明旁增加内容，或查询某个地址是否已有声明。位置和来源分别表达：位置决定CSS顺序，来源决定谁退出时应撤销产物，移动位置不应改变归属。

扩展明确给出锚点、条件地址及来源owner。insert(position,[key,content],provenance)的before/after互斥是公开类型约束；identity/productTag/resourceAddress是可选标识。每次紧邻锚点，不暗设插入游标；连续向后插入保持顺序时，用上次返回节点作新锚点。move只改位置，不改值、条件与来源。

可先插width8px再插height12px，读取有序声明应width→height；将height移到width前应height→width。只核两个计算值不足以发现移动失效。

search({key,conditionPath,productTag,resourceAddress})返回有序匹配；未提供字段不限制，提供字段取交集。Key按属性名、条件按输出地址匹配；has与search是否为空一致。findDeclaration(query,accept)在指定地址可接受候选中选择有效声明：同完整地址遵循priority与源序，单层:root和:where(:root)识别同一根且保留原生特异度。查询不改队列和来源；nodes是快照，修改返回数组不直接改队列。

验证查询须同时准备同key不同条件、同条件不同key的对照；同时给key和conditionPath只能取得两者均匹配者，查询前后顺序与撤销计数保持。

# 来源决定撤销范围

共享产物仍有人需要时就应保留；最后一个来源退出后才撤销。暂时不输出也不等于永久删除，因此协议区分解除来源、退出输出和真正撤销：

- depend(product,{owner})登记显式来源；release(product,{owner})只解除该来源，其余来源仍需的产物保留，最后来源退出才撤销非源产物。
- onRemove(node,cleanup)登记真正撤销时的清理。remove(node)真正撤销并清理失去全部来源的后继。
- remove(node,{from:'output'})仅退出输出，保留来源与产物，不触发真正撤销清理。

同一产物有两个owner时，退出输出应使CSS不再包含该项、清理计数仍0；真正解除最后来源后清理计数才1。另一个有剩余owner的共享产物仍输出，不能因为暂不输出就销毁共享来源。

# 明确改变输入后读取新结果

输入被替换，或扩展明确要求旧结果失效后，后续读取必须采用当前内容。输入身份未变但编译前提改变时，通过compileRevision使旧结果及聚合结果失效；这不提供闭包自动观察。setContent仍只在对应同步通知内有效。

modify也是遵守该协议的内容。[修改输入替换后采用当前变化](../../test/修改输入替换后采用当前变化.browser.test.ts)验证：

- 修改材料被替换后，默认、固定状态和变体采用新变化，区域外对照保持。
- 同一input显式增加compileRevision后使用当前变化，旧配方独占资源退出。
- 共享id候选、后续非交换步骤与撤销仍有效；不能因更新而重复累计或改变顺序。

仅前插一步只重连源序，不重新执行尚未显式失效的旧变化回调。这样显式更新能生效，单纯重新排列又不会意外读取闭包新值。最终验证的是[完整结果加工](完整结果调整与局部修改.md)的实际效果，不固定私有步骤名称、容器或辅助变量数。

# 等待只重试未完成工作

某项内容尚缺前提时可以等待，但等待不应重复执行已经成功的其他工作。defer(node,reason)暂缓未完成通知，保留已完成内容及合法队列操作。compileWaveIndex是最早允许执行时机，不保证固定波数完成；配置时机不能被绕过。

行为示意：前序成功通知把计数加1；等待内容见ready=false则defer。合法后续生成者置ready=true，重试后setContent为9px，页面宽9px，前序计数仍1。始终不置ready则明确报告等待原因，不能成功空输出或无界增长。旧等待原因不能遮盖重试后的新状态。

等待不延长过期context寿命，退出同步通知后不能继续用旧context改写。

清理案例时撤销源登记与所有DOM/style；失败构建不得交付半份结果，也不损坏[上次成功提交](编译结果与页面提交.md)。
