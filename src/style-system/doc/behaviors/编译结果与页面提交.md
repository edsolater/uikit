读取样式结果和改变页面是两件事。业务应能安全查看生成的CSS，再明确提交；一次失败也不能破坏宿主原有样式或上次成功结果。

# 从登记到页面效果

rule/rules先登记源样式。compileCSS读取当前登记并返回CSS文本，适合查看或校验结果；cssRoot.mount才将当前结果提交到页面的style#css-root。

```ts
const handle = rule('.Probe', 'width', '12px')
const css = compileCSS() // 取得文本，此时不会写入页面。
cssRoot.mount() // 宿主已准备好时提交，Probe取得12px宽度。
handle.replace('20px')
cssRoot.mount() // 明确重新提交，页面采用更新后的登记。
handle.remove()
cssRoot.mount() // 再次提交时移除这次贡献。
```

此片段假定页面已存在style#css-root，且Probe是本例元素。句柄更新只改变登记；普通JS配置变动不等于页面已经更新。CSS已经提交后，其引用值、选择器与媒体条件仍按浏览器原有规则响应。

compileRules直接消费显式Rules并返回CSS，不把它们登记进全局；compileCSS也不写DOM。重复编译不改源规则，句柄替换或撤销后，下一次编译反映当前贡献。

# 完整提交并保留宿主

宿主可能已经有页面基础样式，新的生成结果只能更新自己负责的部分。cssRoot.mount因此保留宿主已有内容；找不到挂载目标明确失败，编译或提交失败保留上次成功CSS及CSSOM，不得先清空页面再留下部分结果。

下面是提交失败的验收片段，先建立成功结果，再确认缺少宿主和内容递归不会破坏它：

```ts
const style = document.head.appendChild(document.createElement('style'))
style.id = 'css-root'
style.textContent = '.existing { color: red; }'
const good = rule('.Probe', 'width', '12px')
let bad: ReturnType<typeof rule> | undefined
try {
  expect(compileCSS()).toContain('width: 12px;')
  expect(style.textContent).toBe('.existing { color: red; }')
  cssRoot.mount()
  const committed = style.textContent
  expect(style.sheet!.cssRules[0].cssText).toContain('.existing')
  expect(committed).toContain('width: 12px;')
  style.remove()
  expect(() => cssRoot.mount()).toThrow('缺少样式挂载节点')
  document.head.append(style)
  const recursive: Rules = []
  recursive.push([undefined, undefined, recursive])
  bad = rule('.Probe', 'color', value('red', { onActive: () => recursive }))
  const committedRules = Array.from(style.sheet!.cssRules)
  expect(() => cssRoot.mount()).toThrow('递归引用')
  expect(style.textContent).toBe(committed)
  expect(Array.from(style.sheet!.cssRules)).toEqual(committedRules)
} finally {
  bad?.remove()
  good.remove()
  style.remove()
}
```

只读CSS文本不能证明挂载保护；须同时检查宿主原有规则、成功新结果以及失败后的DOM/CSSOM。清理测试登记后重新挂载应只留下当前需求，不能复活已撤销样式。
