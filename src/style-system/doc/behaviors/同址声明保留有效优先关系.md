# 目的

同一完整CSS地址上的有效贡献具有确定选择，显式等级和书写顺序不因内部编译改变。

# 典型案例

行为伪代码，不能直接运行：同地址依次登记值4(priority0)、7(priority2)、9(priority2)，消费结果应9；撤销9后应7。再加入undefined不能顶掉7。另从priority5的来源派生显式priority0，与同址priority1贡献竞争，须priority1获胜；若将0误当缺省6，结果便会相反。跨地址案例读取浏览器计算值。

相同完整CSS地址与目标中，较高priority的有效Variable贡献优先；同等级后面的有效贡献优先。显式0有效，undefined不应覆盖一个有效值。普通Key已有的同址聚合规则继续有效，不能以Variable竞争规则破坏其合法重复声明。不同选择器地址的最终结果仍须在浏览器中核对，不能只比较数字priority。

普通Key省略priority时为999，普通Variable为0，derive省略时为来源加一。可用同址同名的普通Key贡献与priority1的Variable贡献观察默认Key获选，不能将普通Key缺省误当0；显式派生0的反转案例见本篇前述步骤。不同地址仍按CSS层叠，不用999跨选择器强行改写浏览器结果。

状态与直接声明的既有有效覆盖结果须保留，不固定联动产物内部数值降级方式。声明目标与内容是否合法见[声明明确](样式声明必须明确目标与内容.md)。

清理：逐项撤销高等级和后写贡献核对剩余值；撤销全部本案例登记和DOM/style，保留其他来源。

# 反例

选中更低priority、将显式0当缺省、undefined压掉有效值，或为Variable选择规则破坏Key合法聚合，均违反目的。

# 推断依据

此为现役公开优先级契约，非每一条均来自用户直接命名的要求。[依赖与声明测试](../../test/变量依赖与声明行为.test.ts)核对高等级、同级后写、显式0及撤销恢复。不同地址仍由[浏览器层叠](浏览器层叠不能被编译改写.md)负责。
