样式登记、取得 CSS 和提交页面是不同动作。业务应能先查看结果，再明确改变页面；失败不能损坏宿主已有样式或上次成功结果。

# 先取得完整结果，再提交

```ts
const width = rule('.Probe', 'width', '12px')
const css = compileCSS()
cssRoot.mount()
width.replace('20px')
cssRoot.mount()
width.remove()
cssRoot.mount()
```

假定宿主已经提供挂载节点，第一次取得文本不改变页面；第一次提交后宽 12px，替换并重新提交后宽 20px，撤销并提交后退出这次贡献。句柄修改不等于已经更新页面。compileRules 只消费显式 Rules，不顺带将它们登记进全局。

重复读取不能改变源规则；提交后的 CSS 引用和条件继续由浏览器响应，不因读取与提交分开而变成静态快照。

# 失败保留此前完整状态

若宿主已有基础规则，提交只更新系统负责的部分。缺挂载目标、内容求值失败或无法完成构建时明确失败，不先清空成功内容，不留下部分 CSS，也不删除宿主规则。

伪代码验收：`宿主已有红色规则 → 成功提交宽12px → 加入递归内容再提交失败`；失败后原红色规则、成功的 12px 和原 CSSOM 均保持。移除错误来源后可以继续构建，不能复活已撤销贡献。

只比较新 CSS 文本不能证明提交安全；必须同时观察实际页面、宿主规则和失败后保留的最后一次成功提交结果。内部是否采用缓存、几轮解析或哪种替换算法不在此规定。
