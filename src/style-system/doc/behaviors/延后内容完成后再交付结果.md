# 目的

依赖尚未准备好时保留已完成工作并继续推进，只有合法内容完成后交付结果；真正无法推进时给出原因。

# 典型案例

行为伪代码，不能直接运行：令ready=false、前序成功通知计数=0。消费链先成功执行前序内容并计数加1；等待内容首次执行见ready=false，调用defer(node, '等待来源')。后登记的合法生成者执行时将ready=true；重试等待内容后setContent为9px。构建挂载读取width必须9px，前序成功通知计数仍1，不能在依赖未完成时提交半份CSS。另起独立案例始终不让ready变true，构建须报告等待来源原因而非成功空输出。带compileWaveIndex的独立内容不得早于其配置的最早时机执行。

最早时机不得被绕过。暂缓只重试未完成通知，不因等待重新调用前序已经成功的通知，也不撤销此前合法setContent或队列操作。无法继续时保留可报告原因；尝试前旧原因不遮盖新的状态。队列无法推进时明确报告原因，而非静默丢掉该声明。setContent仍仅在对应同步通知内有效，边界见[位置改写](内容改写只影响本次消费位置.md)。

输入身份未变但编译前提改变时，现有compileRevision使过期内容及聚合结果失效，下一次取得新输入对应结果；此处保存失效效果，不固定内部记录容器。compileWaveIndex是最早允许时机，不保证某固定波数内所有内容均完成。共享合法有限输入须完成，永久内部上限与循环边界见[共享与循环](共享内容可复用且循环必须终止.md)。

清理：撤销等待来源及消费后重新构建，不残留半完成产物；移除案例DOM/style。失败构建不破坏上次成功提交，见[提交保护](样式提交保留已有且失败可回退.md)。

# 反例

忽略最早时机、等待丢失已完成内容、重复前序副作用、未完成先提交、无进展却静默成功或无界增长，均违反目的。

# 推断依据

迁移原节点树关于compileWaveIndex/defer/失效与重试的现役扩展约定；[内容编译入口](../../compiler/style-nodes-to-content-nodes/node-compilation.ts)为查证线索，不将编译波或内部限制数值固定为对外永久行为。
