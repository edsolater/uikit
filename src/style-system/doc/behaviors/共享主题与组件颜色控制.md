# 共享主题与组件颜色控制

本文按 Token 模型解释控制关系，源码已完成 Token 迁移，示例不是当前组件实现证明。

共同主题与组件例外必须同时成立：仍引用共同来源的组件随之变化，明确设置自己的部分保留例外。控制依赖实际引用，不依赖 global 名称或内置颜色变体机制。

## 组件明确材料与计算位置

```ts
const whenReviewTheme = stateCondition('&[data-theme="review"]')
const surfaceColor = token('skyblue', {
  name: 'surface-color',
  address: ':root',
  state: [[whenReviewTheme, 'green']],
})
const buttonSurfaceColor = token(oklch(surfaceColor, { alpha: 0.8 }), {
  name: 'button-surface-color',
  address: '.Button',
  state: { hover: (base) => oklch(base, { alpha: 0.9 }) },
})
const buttonBoundaryColor = token(oklch(surfaceColor, { alpha: 0.4 }), {
  name: 'button-boundary-color',
  address: '.Button',
})
const buttonContentColor = token('black', {
  name: 'button-content-color',
  address: '.Button',
})
rules('.Button', [
  paint({ background: buttonSurfaceColor, content: buttonContentColor }),
  boundary({ border: ['1px', 'solid', buttonBoundaryColor] }),
])
```

普通背景是 skyblue 的 0.8 透明度，线条是同色的 0.4，内容固定黑色；只有背景定义了 hover，因此背景在 hover 时透明度为 0.9，线条和文字保持各自定义。

给根元素设置 data-theme="review" 后，surfaceColor 的 state 选择 green，背景与线条因引用它而跟随变绿，固定黑色内容不变。CSS 已提交后由浏览器响应，不靠重新编译假装保留动态关系。Token 的默认值与状态声明由架构按 address 建立，调用方不需要再补 declare。

Token 对外是普通可坍缩内容。计算表达式内部引用它的结果，不复制来源 state，也不自动把固定值改成动态规则；直接 token(source) 则继承定义配置。显式 address 固定公式位置，未指定时，需要 CSS variable 的定义随各 AST 消费地址发布。相同颜色配方也可由普通函数返回，Token 内部不保存用途列表。

## 局部例外由自身状态或新定义表达

属于同一组件的条件差异写入该 Token 的 state，例如先定义 `const whenReviewRegion = stateCondition('.ReviewTheme &')`，再为 buttonSurfaceColor 配置 `[whenReviewRegion, 'green']` 条目。这种状态只约束 ReviewTheme 内的实际按钮，不给原 Token 增加外部定义入口。

区域需要自己完整的颜色与状态时，创建该地址的新 Token，再明确接入背景属性：

```ts
const reviewSurfaceColor = token('green', {
  address: ['.ReviewTheme', '.Button'],
  state: { hover: (base) => oklch(base, { alpha: 0.9 }) },
})
rules(['.ReviewTheme', '.Button'], { 'background-color': reviewSurfaceColor })
```

区域背景普通为 green，hover 时透明度为 0.9；区域外仍消费原来的 buttonSurfaceColor。reviewSurfaceColor 不改写原 Token，也不自动替换其他属性的引用，线条和内容仍采用各自原定义。地址与计算位置的边界见 [CSS作用域与层叠.md](CSS作用域与层叠.md)。

需要复用一份定义时，普通函数组合其内容与状态，返回该地址的新 Token；组合的继承、覆盖与固定值选择体现在函数中，不靠用途名称或对象创建历史推断。

多个独立颜色需要在同一条件变化时，在各自 state 中表达该条件；区域独立定义则由同一 rules 并列消费到对应 CSS 属性。颜色之间是否联动由显式 Token 引用决定，改背景不等于自动改文字和线条。

## 手动重声明是危险入口

declare(buttonSurfaceColor, 'green') 及含义相同的 Token 目标 entry 仍然可用，但属于 dangerous 操作；不推荐使用是君子协定，不做类型或运行时拦截。它们保留原生 CSS 层叠语义：只影响声明位置及适用继承者，不修改 JS 定义、不搬运来源 state，也不重算祖先公式。这些低层事实不使手动重声明成为正常组件配置方式。

## 业务 API 与实现边界

组件拥有自己的分类条件、布局和外观选择；通用层提供 Token、表达式、state 和 modify 等能力，不预设某个 Button 的颜色策略。

真实组件公开哪些颜色控制点、哪些分类改变哪些材料，由 [按钮教程](../从按钮需求组合样式.md) 和 [Button 规格](../../../components/kits/Button/Button.spec.md) 负责。领域验收同时观察主题变化、组件例外、hover/active/disabled 和区域外对照，不能只验证一个条件下的颜色结果。
