全局主题解决“多处一起改”，组件控制解决“这一处需要例外”。两种需求必须同时成立：共同来源变化时，仍引用它的组件跟随；组件明确设置自己的值后，其他区域不受影响。

# 先按想改变的部分选择控制点

Button的背景由动作色与画布混合，文字又有自己的来源。因此“把按钮改成绿色”需要先明确是改画布、改动作色，还是改最终文字：

| 需求 | 控制点 | 影响 |
| --- | --- | --- |
| 应用共同承载面换色 | globalSurfaceColor | 引用它的组件画布跟随，按钮最终背景仍经过配方混色 |
| 应用普通文字换色 | globalContentColor | 引用它的普通内容跟随，强调实底文字仍可用对比来源 |
| 只换某区域Button的画布 | buttonSurfaceCanvas | 改这些按钮的混色画布，不反改全局来源 |
| 只换某区域Button的动作色 | buttonSurfaceSource | 改这些按钮参与表面混色的来源 |
| 明确指定某区域Button的文字 | buttonContentColor | 改匹配按钮的内容色，不要求同时改背景 |

Button还保留自己的混色强度和最终表面控制点。这里先走一遍共同主题、区域例外和动作色例外，避免把不同意图混成一个总开关。

# 给整个应用设置共同来源

```ts
rules(':root', [
  declare(globalSurfaceColor, 'rgb(220, 230, 240)'),
  declare(globalContentColor, 'rgb(20, 30, 40)'),
])
```

普通Button以浅蓝灰为画布、以深灰为普通文字来源。最终背景仍混入按钮自己的动作色；globalSurfaceColor不是直接替换每种外观的background-color。hover/active继续反馈，禁用继续排除交互。

# 给一个区域保留自己的画布和文字

ReviewTheme区域需要浅绿画布和另一种普通文字色。继续登记明确的新值，而不修改全局JS定义：

```ts
rules(['.ReviewTheme', '.Button'], [
  declare(buttonSurfaceCanvas, 'rgb(180, 210, 190)'),
])
rules(['.ReviewTheme', '.Button:not([data-tone])'], [
  declare(buttonContentColor, 'rgb(60, 70, 80)'),
])
```

区域内普通按钮取得自己的画布和文字，区域外继续引用共同主题。之后再改根主题时，区域外跟随；区域内已明确覆盖的部分保持自己的值。其他仍引用主题的部分继续按引用关系变化。

# 只换普通按钮的动作色

如果ReviewPanel希望普通按钮以蓝色作为动作色，危险按钮仍保持危险语气，就选择实际按钮并明确排除data-tone：

```ts
rules(['.ReviewPanel', '.Button:not([data-tone])'], [
  declare(buttonSurfaceSource, 'blue'),
])
```

这一步改变普通按钮参与表面混色的来源，不重设全局画布，也不选中危险按钮。filled常态使用语气实底，可能不露出主题画布；强调实底文字保留其对比来源，不自动改成globalContentColor。修改未引用某个控制点的外观时，不能期待该控制点直接改变它。

选择实际按钮，是因为组件已有自己的声明；仅在祖先上声明同名组件变量，不保证压过组件自身的值。多个独立目标要同时换值，就在同一rules并列declare，不必建立额外的组概念。

# 保留引用关系，明确变化边界

全局来源在公式实际求值位置改变时，相关结果由CSS正常更新；不得把组件当前控制点退化为创建快照，也不承诺对子元素同名输入自动搬运祖先公式。需要本地公式时明示address，复用状态和用途用variableFrom；全部结果共同变化用adjust或modify。

控制点承担的是具体用途：来源、画布、强度和内容各有含义。它们让全局和组件控制能组合，也让调用者知道改动不会无条件染遍整颗按钮。

实际浏览器需同时观察主题默认、区域主题及组件覆盖：切换根表面/内容色，普通Button更新；区域与组件的显式覆盖保持，区域外不被污染。再进入hover、active、disabled，反馈及禁用表现继续成立；危险filled保持其原语气。CSS已经提交后只改CSS值即可响应，不能以重新编译掩盖引用丢失。
