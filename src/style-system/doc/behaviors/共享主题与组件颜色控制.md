共同主题与组件例外必须同时成立：仍引用共同来源的组件随之变化，明确设置自己的部分保留例外。控制依赖实际引用，不依赖“global”名称或额外的颜色组机制。

# 主题作为来源，组件明确自己的计算位置

下面用透明度变化简化真实 Button 的配方，以便直接推导控制关系：

```ts
const surfaceColor = variable('skyblue', 'surface-color')
const buttonColor = variable(oklch(surfaceColor, { alpha: 0.8 }), {
  name: 'button-color', address: '.Button',
  states: { hover: base => oklch(base, { alpha: 0.9 }) },
  variants: {
    line: base => oklch(base, { alpha: 0.4 }),
    content: 'black',
  },
})
rules('.Button', [
  color({ background: buttonColor, content: buttonColor.variant('content') }),
  boundary({ border: ['1px', 'solid', buttonColor.variant('boundary')] }),
])
```

普通背景是 skyblue 的 0.8 透明度，line 是同色的 0.4，content 是固定黑色。hover 规则作用于各用途自己的基础，因此此示例 hover 将它们都设为 0.9 透明度；这不是自动对比文字算法。需要不同反馈，应显式定义，而不能让用途名字暗带行为。

把根上的 surfaceColor 改为 green，Button 根据地公式仍引用它，所以背景与 line 跟随变绿；固定黑色内容不变。CSS 已提交后修改根 CSS 值即可响应，不靠重新编译假装保留动态关系。

初始化主题也可明确登记新值：`rules(':root', [declare(surfaceColor, 'green')])`。这是业务赋值，不是为了补齐自动声明而重传创建值。

这里 buttonColor 明确引用 surfaceColor 表达运行时控制。单纯 variableFrom 的定义复用不自动创造这个引用，也不把固定值改成动态规则。业务可以复用复杂反馈，也可以明确不同计算公式，两者不是互相替代。

# 区域例外仍须落在真正的计算位置

```ts
rules(['.ReviewTheme', '.Button'], [declare(buttonColor, 'green')])
```

这在区域地址显式赋 green，外部 Button 保留主题引用。完整地址是 ['.ReviewTheme', '.Button']，与 buttonColor 的根据地 '.Button' 不同，因此不在此复制 buttonColor 的 states。line 与 content 也是独立 Variable；修改 buttonColor 的声明不等于修改它们各自的定义。

若改为在原根据地执行 `rules('.Button', [declare(buttonColor, 'green')])`，已有 hover 规则才基于这个新基础得到 alpha 为 0.9 的 green。不能将“后代不重算祖先公式”误用为“根据地新值不参与自身 states”，也不能把选择器匹配的元素相同当作声明地址相同。

若 ReviewTheme 需要自己的一整套颜色与交互定义，显式复用定义并指定新根据地：

```ts
const reviewColor = variableFrom(buttonColor, 'green', {
  name: 'review-button-color', address: ['.ReviewTheme', '.Button'],
})
rules(['.ReviewTheme', '.Button'], [
  color({ background: reviewColor, content: reviewColor.variant('content') }),
  boundary({ border: ['1px', 'solid', reviewColor.variant('line')] }),
])
```

区域背景普通为 green、hover 为 alpha 0.9 的 green；line 普通为 alpha 0.4 的 green，content 普通仍为 black。各 variant 的 hover 按继承规则处理，区域外不变。这是 variableFrom 换基础、variant 选择和 address 归属的正常组合，不需要其他 API 识别定义的创建过程。

只在祖先 ReviewTheme 改一个输入，也不能承诺压过 Button 自己的声明或重算祖先公式。按 [CSS作用域与层叠.md](CSS作用域与层叠.md) 先找实际控制点，再选择显式新值、根据地公式或完整加工。

多个独立控制点同时赋值时，在同一规则并列 declare 即可，不新增组、cluster 或按名称切换整套定义的机制。variant 保存在定义里供使用处选择，不要求先逐个导出为平行变量。

# 真实组件怎样承接这些规则

真实 Button 的背景可能混合动作色、画布与强度，文字另有对比来源。全局画布改变不意味着每种实底外观都直接变成该色；只有引用对应控制点的部分才跟随。

[按钮教程](../从按钮需求组合样式.md) 与 [Button 规格](../../../components/kits/Button/Button.spec.md) 负责现有组件的具体入口。领域验收同时观察主题变化、组件例外、hover/active/disabled 和区域外对照；若需要手工补基础声明或在每个消费点复制公式才能通过，不能当作需求已经满足。
