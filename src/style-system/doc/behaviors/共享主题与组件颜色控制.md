# 共享主题与组件颜色控制

本文按 Token 模型解释控制关系，源码已完成 Token 迁移，示例不是当前组件实现证明。

共同主题与组件例外必须同时成立：仍引用共同来源的组件随之变化，明确设置自己的部分保留例外。控制依赖实际引用，不依赖 global 名称或内置颜色变体机制。

## 组件明确材料与计算位置

```ts
const surfaceColor = token('skyblue', 'surface-color')
const buttonColor = token(oklch(surfaceColor, { alpha: 0.8 }), {
  name: 'button-color',
  address: '.Button',
  state: { hover: (base) => oklch(base, { alpha: 0.9 }) },
})
const buttonLine = token(oklch(surfaceColor, { alpha: 0.4 }), {
  name: 'button-line',
  address: '.Button',
})
const buttonContent = token('black', {
  name: 'button-content',
  address: '.Button',
})
rules('.Button', [
  color({ background: buttonColor, content: buttonContent }),
  boundary({ border: ['1px', 'solid', buttonLine] }),
])
```

普通背景是 skyblue 的 0.8 透明度，线条是同色的 0.4，内容固定黑色；只有背景定义了 hover，因此背景在 hover 时透明度为 0.9，线条和文字保持各自定义。

把全局 surfaceColor 的 CSS 值改为 green，背景与线条因引用它而跟随变绿，固定黑色内容不变。CSS 已提交后由浏览器响应，不靠重新编译假装保留动态关系。

Token 对外是普通可坍缩内容。将它放进另一个 Token 或表达式表示引用，不复制来源 state，也不自动把固定值改成动态规则。相同颜色配方若要复用，通过普通函数返回所需 Token；Token 内部不保存用途列表。

## 局部例外落在实际控制点

```ts
rules(['.ReviewTheme', '.Button'], [declare(buttonColor, 'green')])
```

这只在指定区域显式赋 green，区域外仍读取主题。局部赋值不改写 JS 定义，不因此把主体的整套 state 搬到新地址，也不重算祖先公式。地址与计算位置的边界见 [CSS作用域与层叠.md](CSS作用域与层叠.md)。

区域需要自己完整的颜色与状态定义时，普通函数组合并创建该地址的 Token，再由区域规则使用。组合的继承、覆盖与固定值选择必须体现在函数中，不靠用途名称或对象创建历史推断。

多个独立控制点需要同时赋值时，在同一规则并列 declare 即可。控制点之间是否联动由显式 Token 引用决定；改背景并不等于自动改文字和线条。

## 业务 API 与实现边界

组件拥有自己的分类条件、布局和外观选择；通用层提供 Token、表达式、state 和 modify 等能力，不预设某个 Button 的颜色策略。

真实组件公开哪些颜色控制点、哪些分类改变哪些材料，由 [按钮教程](../从按钮需求组合样式.md) 和 [Button 规格](../../../components/kits/Button/Button.spec.md) 负责。领域验收同时观察主题变化、组件例外、hover/active/disabled 和区域外对照，不能只验证一个条件下的颜色结果。
