# 目的

在创建时复用默认内容与状态，派生只改变自己负责的部分，不反向修改来源。

# 典型案例

行为伪代码，不能直接运行：分别登记source、wider、fixed的width消费，挂载到三个元素并读取普通与实际hover的计算宽度。改变source的JS配置后重新构建，已创建派生体仍保留创建时取得的规则。copied沿用名称，不拿它与source的同址层叠证明独立地址效果。

```ts
const source = variable({ default: '4px', hover: base => multiply(base, 2) }, 'size')
const copied = source.derive()
const wider = source.derive('7px', name => `wide-${name}`)
const fixed = source.derive(source.content, { name: 'fixed-size', states: { hover: '12px' }, priority: 0 })
```

独立消费时，source普通4px、悬停8px；wider普通7px、悬停14px；fixed普通4px、悬停12px。派生不反向修改source。随后修改source的JS配置不会自动同步到已创建派生体；继承不是动态配置观察，也不是按名字重新寻找来源。

**现役公开配置契约**：名称默认沿用，独立CSS地址须显式新名。默认priority为来源priority加一，显式0保留；普通Variable默认priority为0。状态按条件合并，当前配置覆盖同条件，未覆盖条件保留。registration、onActive、compileWaveIndex不隐式继承，需明确提供。

derive不是父对象引用：`source.derive('7px', 'independent')`的独立默认没有引用source时，不因派生血缘激活父资源；若默认显式写成`source.derive(multiply(source, 2), 'dependent')`，则保留真实来源的动态关系。

公开入口为`source.derive()`及`source.derive(content, nameOrOptions)`，返回派生Variable；第二参数可为字符串、VariableName、名称映射`(name: VariableName) => string | VariableName`或options。仅改配置用`source.derive(source.content, options)`；单参对象是内容，不猜成配置，不新增variable({derive: source})入口。

清理：撤销三处消费，移除案例元素及案例style；独立默认与父引用资源案例分别撤销自己的消费，确认未引用父资源不因血缘留下。

# 反例

将显式0当缺省、丢失未覆盖状态、修改来源、以名称换绑，或因派生血缘激活没有被引用的父资源，均违反目的。

# 推断依据

用户明确extend改名derive且保留定义/状态复用，创建时继承，动态调控以后再做。priority、名称默认和配置不隐式继承为现役公开契约，不冒充用户逐字要求。[身份与派生测试](../../test/具体变量身份与定义派生.test.ts)提供核对线索；历史通过不代表暂停中版本已完成验收。
