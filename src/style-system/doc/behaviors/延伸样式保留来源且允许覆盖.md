# 目的

Cluster 可以按同名成员创建沿用来源状态的 Variable，再只改自己负责的部分。未覆盖的状态由 Cluster 明确配置为来源引用，编译该状态内容时读取来源的同状态内容；明确写出的 `0` 等值不能被当成缺省，延伸也不能改动共享来源。

# 典型案例

```ts
const source = variable(1, {
  name: 'source-ratio', states: { hover: 0.75, disabled: 0.5 },
})
const next = clusterFrom(variableCluster({ default: source, soft: variable(0.3, { name: 'source-soft-ratio' }) }), {
  default: { name: 'next-ratio', states: { disabled: 0 } },
  soft: { name: 'next-soft-ratio' },
})
const css = compileRules([[[condition('.Probe')], 'opacity', next]])
expect(css).toContain('opacity: var(--next-ratio, var(--source-ratio, 1));')
expect(css).toContain('--next-ratio: 0;')
expect(css).toContain('--source-ratio: 0.75;')
expect(css).toContain('--next-ratio: var(--source-ratio, 1);')

const sourceCSS = compileRules([[[condition('.Source')], 'opacity', source]])
expect(sourceCSS).toContain('--source-ratio: 0.5;')
expect(sourceCSS).not.toContain('--next-ratio:')
```

# 反例

若 `0` 被当成缺失而退回 `0.5`、hover 地址没有取来源的 `0.75`、新对象消费引用旧名字，或来源 disabled 值与名字被改写，断言失败。普通 `variable(source, options)` 不自动获得 source 的 hover、disabled 状态。
