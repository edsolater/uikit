# 目的

组合结果读取实际引用的输入，并随消费位置的来源变化计算，不能继承过期的祖先结果。

# 典型案例

行为伪代码，不能直接运行：创建Parent及A/B子区域，各放Read元素；登记下方基础与opacity消费后挂载，读取三个Read的计算opacity。更改并撤销A输入覆盖，按下述数值核对，不只检查CSS文本。

```ts
const base = variable(4, 'base')
const amount = variable(2, 'amount')
const result = variable(multiply(base, amount), 'result')
```

普通消费result得到8；A区域将base声明为7时得到14；B区域只把amount声明为3时得到12。A/B互不污染。若子区域改变输入，不能继续继承祖先已算好的8而忽略当地输入；浏览器仍应读取当地来源。局部来源自身有状态时，结果随当前状态变化，不要求使用者枚举输入状态的所有交集。

默认、状态、嵌套内容、延迟生产函数实际展开后引用的Variable都适用。函数忽略某输入而不返回其引用时，不能仅因传过参数激活该对象。共享引用、重复访问及替换后重新展开都不得换绑或保留已退出依赖。

父子例的完整CSS语义可以如下表达（允许其他等效输出）：

```css
.Parent { --base: 4; --amount: 2; --result: calc(var(--base) * var(--amount)); }
.Parent .A { --base: 7; --result: calc(var(--base) * var(--amount)); }
.Parent .B { --amount: 3; --result: calc(var(--base) * var(--amount)); }
.Read { opacity: calc(var(--result) / 20); }
```

Parent内普通Read为0.4，A内Read为0.7，B内Read为0.6；只让A/B继承父位置已计算的result而继续得到0.4不可接受。若撤销A的base覆盖，A恢复0.4，B仍0.6。

来源动态改为另一个对象时，新依赖须完整生效；旧资源退出案例见[按需资源](未使用的资源不进入样式结果.md)。对象引用归属见[具体身份](引用只携带具体对象的定义.md)，本篇不按函数形状或名称另建依赖资格。

清理：先撤销A覆盖确认A恢复、B不变；最后撤销其余登记并移除案例DOM/style。

# 反例

A/B中仍得到父位置的0.4、函数未引用输入却激活它、局部状态变化后结果仍固定，均违反目的。

# 推断依据

用户裁决：实际内容中的具体Variable引用建立依赖，是否为函数与依赖资格无关；动态局部和状态用途保留。[依赖声明测试](../../test/变量依赖与声明行为.test.ts)与[延迟消费测试](../../test/动态值只在编译消费时求值.test.ts)提供核对线索。
