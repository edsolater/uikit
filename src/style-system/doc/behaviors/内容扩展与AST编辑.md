扩展能力让新内容参与同一个样式领域，而不迫使普通业务理解编译过程。扩展必须遵守消费隔离、显式位置、贡献归属和失败安全；这些结果责任与采用何种 AST、回调或遍历算法无关。

# 共享内容不等于共享每次消费的改写

同一个内容分别用于 A.width 和 B.width，扩展按本次条件改成 8px 和 12px，则页面应分别取得 8px、12px。撤回 A 的内容，B 仍为 12px。读取编译结果不能额外运行源生产函数，也不能激活没有真正访问的内容。

伪代码：`改写(当前消费, 新内容)`，而不是 `修改所有引用这个对象的消费`。嵌套内容的当前输入是自己，不能误改外层对象。替换后旧独占依赖退出，共享依赖保留。

# 位置决定 CSS 顺序，来源决定撤销责任

扩展新增一条声明时，需能明确它在什么条件、哪个目标和什么位置生效，以及由谁持有。移动只改变位置，不改变内容和来源；来源撤销后，其独占产物一起退出。

例如 width 后插 height，顺序为 width→height；把 height 移到 width 前，应为 height→width。只验证两项数值都存在不足以判断移动生效，因为原生简写、层叠等组合会受源序影响。

同一产物由两个来源持有，撤销一个仍保留；最后来源退出才真正清理。暂时停止输出和永久撤销不能混同，否则重新使用或共享来源会失去所需内容。

# 查询反映实际地址，不制造隐式控制关系

Variable 的自动声明行为要求 AST 能按 VariableName 对应的 CSS 名称与 address 查询 declaration。同时给出名称与地址时，只返回两者均匹配的声明；不是查询任意同名位置，也不是搜索最近祖先来重新选择根据地。查询不改变顺序、输出或归属，提供查询能力不意味着需要独立 declare tree。

# 更新和等待保持一致结果

显式替换输入或要求旧结果失效后，后续读取采用新内容，并撤回旧独占依赖；普通闭包变化不自动成为更新通知。

某项内容暂缺前提时，可以等前提满足再完成；不能因此重复已完成的其他业务工作。无法完成时明确失败，不能无限等待、成功空输出或交付半份 CSS。构建失败仍保护 [Compile与挂载.md](Compile与挂载.md)。
