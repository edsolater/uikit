本文按 Token 模型描述扩展边界，源码已完成 Token 迁移。

扩展能力让新内容参与同一个样式领域，而不迫使普通业务理解编译过程。扩展必须遵守消费隔离、显式位置、贡献归属和失败安全；这些结果责任与采用何种 AST、回调或遍历算法无关。

# 对象生命周期与独立消费

同一对象在一次编译中只接收一次 onFirstScan 和一次 onCompile，不因出现在 A.width 与 B.width 两个位置就重复调用。确需分别得到 8px 与 12px 时，以两个独立的引用或内容对象表达位置差异，共享来源仍可相同。撤回 A 的独立消费不改变 B。读取编译结果不能额外运行源生产函数，也不能激活没有真正访问的内容。

onCompile 返回 void，可以在生命周期内调用 AST 操作。独立引用对象操作自己的消费，不误改外层对象或其他独立消费；同一对象共享的结果不能伪装成多个独立生命周期。替换后旧独占依赖退出，共享依赖保留。

# 位置决定 CSS 顺序，来源决定撤销责任

扩展新增一条声明时，需能明确它在什么条件、哪个目标和什么位置生效，以及由谁持有。移动只改变位置，不改变内容和来源；来源撤销后，其独占产物一起退出。

例如 width 后插 height，顺序为 width→height；把 height 移到 width 前，应为 height→width。只验证两项数值都存在不足以判断移动生效，因为原生简写、层叠等组合会受源序影响。

同一产物由两个来源持有，撤销一个仍保留；最后来源退出才真正清理。暂时停止输出和永久撤销不能混同，否则重新使用或共享来源会失去所需内容。

# 查询反映实际地址，不制造隐式控制关系

Token 坍缩需要 CSS variable 时，声明和查询依据其名称及 address。同时给出名称与地址时，只返回两者均匹配的声明；不是查询任意同名位置，也不是搜索最近祖先来重新选择定义位置。查询不改变顺序、输出或归属，提供查询能力不意味着 Token 需要 definitionKey、declarations 或独立声明树。

onFirstScan 等扩展可以继续登记 modify。坍缩前必须读取完所有影响相关 Token 的修改，随后按内部 _kind 生成 CSS；不限制激活波次，不允许先输出后才发现目标本应具有 CSS variable 身份。

# 更新和等待保持一致结果

显式替换输入或要求旧结果失效后，后续读取采用新内容，并撤回旧独占依赖；普通闭包变化不自动成为更新通知。

某项内容暂缺前提时，可以等前提满足再完成；不能因此重复已完成的其他业务工作。无法完成时明确失败，不能无限等待、成功空输出或交付半份 CSS。构建失败仍保护 [Compile与挂载.md](Compile与挂载.md)。

context、session、setContent、search、owner、compileRevision、defer 和编译波等扩展协议见 [当前接口与扩展协议](../当前接口与扩展协议.md)。这些协议不应恢复两种内容对象模型，也不要求业务复制当前内部结构。
