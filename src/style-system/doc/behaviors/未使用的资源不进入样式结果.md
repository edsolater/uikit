# 目的

最终 CSS 应只包含当前样式实际需要的资源。仅创建定义、未被消费或已撤销的样式，不应留下变量根值、函数、动画帧或其他派生依赖。

# 典型案例

```ts
const onActive = vi.fn((): Rules => [
  [[condition(':root')], '--probe-size', '10px'],
])
const size = value('var(--probe-size)', { onActive })
expect(onActive).not.toHaveBeenCalled()

const handle = rule('.Probe', 'width', size)
try {
  const before = compileCSS()
  expect(before).toContain('width: var(--probe-size);')
  expect(before).toContain('--probe-size: 10px;')
  expect(onActive).toHaveBeenCalledOnce()

  handle.remove()
  expect(compileCSS()).toBe('')
} finally {
  handle.remove()
}
```

按需根规则、属性注册、函数和关键帧也遵守同一个使用边界。下面的 API 组合只是目前可运行的观察方式：

```ts
const baseline = compileCSS()
const color = variable('red', {
  name: 'resource-color',
  registration: { syntax: '<color>', inherits: true, initialValue: 'black' },
  onActive: () => [[[condition(':where(:root)')], color, 'blue']],
})
const frames: Rules = [
  [[condition('from')], 'opacity', 0],
  [[condition('to')], 'opacity', 1],
]
const motion = animationValue({
  name: animationName('resource-motion', frames), duration: '1s',
})
const length = cssFunction(
  '--resource() returns <length>', [[undefined, 'result', '2px']],
)()
expect(compileCSS()).toBe(baseline)

const css = compileRules([
  [[condition('.Probe')], 'color', color],
  [[condition('.Probe')], 'animation', motion],
  [[condition('.Probe')], 'width', length],
])
expect(css).toContain('--resource-color: blue;')
expect(css).toContain('@property --resource-color')
expect(css).toContain('@keyframes resource-motion')
expect(css).toContain('@function --resource() returns <length>')
expect(compileCSS()).toBe(baseline)
```

## 共享、替换与重新构建

只创建未消费定义时，不输出其默认、状态、注册、函数、动画或onActive资源，也不执行未使用生产函数。实际消费时提供所需资源；onActive返回的真实规则和稍后展开内容仍能引入合法依赖。普通资源描述文本不能误作Variable消费。

共享资源有两个消费者时，移除一个仍保留另一个所需结果；移除最后一个后释放不再需要的定义。替换引用对象、修改局部来源、撤销规则、重新编译时，旧依赖及其独有资源退出，新依赖完整生效。

资源回调的永久精确执行次数、内部节点或中间CSS变量数量不在承诺内。相同名字的资源定义完整替换语义见[资源定义一致性](同名样式定义必须完整一致.md)，不能据此恢复Variable按名关联。

动态切换例：同一延迟内容原来返回A（默认4、悬停6、独有资源a），下次构建改为返回B（默认10、悬停12、独有资源b），提交后须普通10、悬停12；无其他需求时a及A独有状态退出，b完整生效。不能为了探测依赖额外再次调用源函数并将不同返回混在同一消费；此约束不规定全系统固定调用次数。

# 反例

若定义时就激活、使用后没有依赖、或删除源 Rule 后残留派生资源，断言失败。`onActive` 的调用次数只是案例证据，是否留下资源由 CSS 结果判断。
