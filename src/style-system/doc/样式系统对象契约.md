# Style System 对象契约

本文保存对象的精确协议、声明与状态边界，供实现和扩展时查证。编写业务样式先读[使用入口](样式系统对象与行为.md)；代码文件职责与运行链见 [architecture.md](../architecture.md)。

Pieces 是可复用碎片的统称，不是 Rules 的父节点。Rule 包含 Condition 和 Declaration；Declaration 将声明目标与 JSSContent 配对。JSSKey 可直接配对内容，Variable、Modification 等对象持有 `key/content` 自然材料，declare 据此建立对应声明。`pieces/contents/` 对应内容这一侧，包含现成 Atom、内容组合操作和内容构造方法。

## 对象分别负责什么

| 对象 | 职责 |
| --- | --- |
| JSSKey | 表达一个 CSS 属性或描述符的声明目标，可自带同址重复声明的聚合规则 |
| Value | 包装内容、按需依赖与 CSS 输出；withContent 以原配置包装新内容，不选择或传播状态 |
| Variable | 拥有内容身份、创建配置、引用、局部定义和状态基础，投影 Declare、Adjust Target、Modify Target 所需的自然材料；见 [变量定义与消费.md](变量定义与消费.md) |
| VariableName | 保留CSS名称对象；字符串化输出逻辑名，内容引用只输出var()，不激活定义 |
| Atom | Value 与 Variable 在组合时作为一块使用的称呼；不是独立类型，底层仍是 JSSContent |
| JSS 内容组织工具 | 位于 functions，用已有输入组织混色、计算等 Expression；边界见 [SPEC.md](../pieces/contents/functions/SPEC.md) |
| Expression | 只承担自身依赖与输出，不提供消费位置通知、AST 操作或资源定义 |
| CSSFunction | 与 Variable 平级的定义主体，按需提供函数体；调用返回依赖主体和实参的 Expression |
| Atom Creator | 由配置构造可作为一块内容使用的 JSSContent，例如阴影或动画 |
| JSSContent | 内容对象共同遵守的可选编译、生命周期与输出约定 |
| Modification | 保存变化自身的 type/detail，内置转译颜色配方，持有 Declare、Adjust、Modify 所需材料；来源绑定和条件应用由使用方组织 |
| State Condition | 表达同一主体的状态条件及优先级 |
| Condition | 表达有序 CSS 地址，包括选择器和 At Rule |
| Declaration | 一对声明目标与内容，由 Key 配对或 declare 读取自然材料建立 |
| Mixin | 将完整效果配置转换成声明组合 |
| Rule | 保存普通 CSS 条件、声明目标及内容，不解释状态名称 |
| CSSRoot | 保存源规则，统一编译并提交 CSS |

```text
Condition + Declaration(声明目标, JSSContent) → Rules
Rules → JSSStyleNode[] → JSSContentNode[] → CSS 字符串
```

## 创建与延伸

普通variable创建需要默认内容与名称。derive()沿用来源默认和状态；derive(value, nameOrOptions)替换默认并合并当前states。仅配置差异用derive(source.content, options)，不使用undefined占位。默认priority为来源加一，显式0保留；名称默认沿用，独立定义须明确新名。registration、onActive、compileWaveIndex不自动继承。具体用法由[Variable](变量定义与消费.md#derive的定义与状态复用)唯一维护。

Name不管理定义注册。具体Variable引用携带自己的定义、默认/状态资源；纯Name只提供CSS引用。对象依赖由实际编译内容中的Variable引用建立，不按名称换绑或借入状态。局部来源变化在当地物化派生声明，消费者退出沿AST来源释放产物。重复CSS名称仍受CSS地址聚合与浏览器层叠影响。

默认函数无参延迟求值，状态回调接收本次声明基础；局部declare、modify和adjust不改创建内容。缺失同对象声明时可以补根基础，有显式声明时由使用者明确各位置基础；registration.initialValue独立于defaultValue。按需onActive返回普通Rules并保留原资源生命周期。

## 独立变化与来源绑定

```ts
const source = variable(oklch({ lightness: 0.5, chroma: 0.1, hue: 240 }), 'source')
const change = modification({
  name: '--change',
  type: 'color',
  detail: { lightness: 0.3, chroma: current => add(current, 0.3) },
})
const merged = adjust(source, change)

rules('.item', [declare(merged), color({ content: merged })])
```

`Modification<Detail, Type>` 自身就是通用变化定义，可声明和引用，不需要包装为 Variable。type 选择描述转译，name 是完整 CSS 名称；两者职责独立。通用主体及声明生命周期在前，Color 的参数、材料形状和转译在后；当前内置策略是 Color，没有运行时安装或注册入口。单个配置中的 `name` 使用完整 CSS 自定义属性名（例如 `--change`），省略时生成匿名名称；`type` 选择内容领域，`detail` 保存变化：固定通道设为给定值，回调在配方编译时收到 l/c/h/alpha 表达式，未指定通道保持来源。上例的变化声明为 `--change: 0.3 calc(c + 0.3) h / alpha`。内置转译只负责配方内容，不建立独立 Adapter 层；颜色之外的 Size 参数与表达尚未定义。

```mermaid
flowchart LR
  subgraph Definitions[独立定义]
    S[Source：Variable]
    M[Modification：变化配方]
  end
  S -->|Adjust Target 协议| A[Adjust 绑定]
  M -->|Adjust 协议| A
  A --> R[mergedResult：引用双方的 Variable]
  R -->|Declare 协议| D[共同声明 Source、Modification、mergedResult]
  D --> C[浏览器沿 CSS 引用计算结果]
```

`adjust(source, change)` 返回 mergedResult。结果使用 `oklch(from var(--source) var(--change))` 组合双方，`declare(merged)` 一并声明三者。当前或祖先作用域已经声明的来源与配方优先，自动声明只补缺项；当子元素局部覆盖来源或配方时，结果在消费地址重新组合，使用该处的 CSS 值。多个 Source 可共享同一 Modification。

`modify(target, change)` 按 type 选择具体应用，返回条件修改 Declaration。颜色材料通过独立配方引用参与组合；数字及其他 CSS 表达式变化使用 `modify(target, { type: 'expression', detail: current => add(current, 2) })`。这种回调材料直接描述对前序表达式的变化，不是独立可声明的 Modification。Modification 持有变化方材料，Variable 持有目标侧材料；具体组合、顺序和条件由外部 Modify 使用端组织。

协议是操作所需的数据形状；`AdjustProtocol<Type>` 描述可声明的配方，`adjust` 入口另限制当前支持的 type，绑定主体不继承颜色定义。Declare 描述 `key/content`，Adjust、Modify 的目标 key 须为 CSS 自定义属性，还可携带 states（已解析状态条件到内容的 Map）与 registration（CSS @property 配置），颜色变化材料包含 `type: 'color'`、配方 key 与 content。

Declare 还允许可选的 `declarations?: DeclareProtocol[]` 保存共同声明的依赖材料。Adjust 结果用它保留来源与配方，即使 `declare(merged, replacement)` 显式覆盖结果内容，依赖关系仍会共同声明；普通材料无需提供这个字段。

使用端通过 FNKit 的 DataShape 和 `matchShape` 识别材料并执行操作；信息体不必知道协议，不需要协议登记、品牌或外部操作方法。

控制器修改变化参数、更新通知及自动重编译属于后续能力，当前没有对应操作方法。

例如 `declare({ key: key('--surface'), content: 'red' })` 直接声明普通信息体的材料；它不需要 Variable 身份。`content` 可以是可编译内容或消费时执行的生产函数，显式 `undefined` 表示不输出；缺少 content 字段不等同于显式 undefined。

## 并列声明独立颜色

多个颜色在同一条件一起变化时，在rules中并列declare对应具体Variable。每个声明有自己的目标、内容及状态，不定义组对象、成员代理或隐式配对。只覆盖一个Variable就只改变该目标；其他派生颜色是否随动取决于它们是否显式引用了该对象。使用例见[按钮教程](从按钮需求组合样式.md)。

## 声明与作用域

```ts
rules(button, [
  [$alignSelf, 'center'],
  declare(surfaceColor, surfaceColorDefault),
  color({ background: surfaceColor }),
])
```

rules 的公开输入是声明序列及 Mixin 组合；普通声明对象和裸字符串目标不在公开类型中。JSSKey 对象直接携带属性名，不依赖名称预注册。Mixin 自己解释配置对象，Compiler 只读取生成的声明。

声明不修改共享 Variable 的 JS 对象。等级属于声明键：Variable 为 `specifiedPriority ?? (derive ? derive.priority + 1 : 0)`，普通 Key 为999；联动配方减1，状态不再减级。同名同完整地址先选高等级有效输出，同级保持书写顺序；Variable 后写覆盖，普通 Key 保留 join／默认逗号聚合。跨地址的覆盖、继承及层叠由 CSS 作用域决定。undefined 内容跳过；迭代失败或输入无效时不登记部分结果。

同一目标与状态地址的同名 Key 重复声明时，Compiler 按声明顺序为获选等级形成一组 Value。每项 Value 的 `content` 保留原值与对象身份，`toCSSString` 惰性读取该节点已编译的内容。默认把这组 Value 作为逗号数组输出；Key 的 `join` 可以改为数值等其他组合，并返回普通内容继续 `onCompile` 和输出。结果位于获选贡献的最后位置，其他地址和状态各自处理。获选组唯一显式 `join` 接管默认规则；多个不同显式规则报冲突。单条声明直接输出。

`join` 保留输入 Value 对象时，该项继续读取原声明位置的编译结果；改写 Value 的 `content` 引入新内容时，新内容在结果节点编译。

```mermaid
flowchart LR
  R[Rule 声明序列] --> C[Compiler]
  C -->|同址同名的重复声明| V[有序 Value 数组]
  V --> K[默认逗号组合或 Key join]
  K --> A[组合后的内容]
  A -->|继续编译并调用 toCSSString| O[同组最后声明位置的输出]
  C -->|单条声明| P[原值输出]
  O --> B[浏览器 CSS 层叠]
  P --> B
```

`$boxShadow` 不提供专属 `join`，使用相同的默认逗号组合；已有逗号列表与重复项按原顺序保留。它不检查 `none` 或 CSS 全局关键字；混合后的声明是否有效由浏览器判断。编译期不据此创造清空历史贡献的语义。

rule 返回的句柄可以替换或删除自己的源条目；rules 返回批量删除句柄。句柄不直接提交 DOM，应用通过 cssRoot.mount() 统一提交。

## 状态与内容输出

状态只产生 Variable 自身的 Custom Property 声明，外部混色、计算或 Value 包装不获得状态分支。一个表达式组合多个有状态 Variable，消费属性仍输出一次。

Variable 创建时展开 `states` 中匹配到的快捷名称，其他输入直接作为条件，保存条件到内容的映射；业务保证这些条件约束自身，不要求登记。公开 Rules 中的字符串统一是普通条件，例如 `'&:hover'`，含义不随快捷名称登记变化。普通内容与状态配方都直接引用来源 Variable，组件只选择分类材料和贡献。

每次声明只展开材料的各项有效状态，不自动枚举交集。状态选择器的附加权重统一归零，确保中央顺序不被选择器特异性反转；显式嵌套条件保留。状态只属于具体定义，不按名称借入；derive保留创建时状态规则。具体边界见 [主体状态条件.md](主体状态条件.md)。

焦点轮廓由 focusOutline 的 focus 状态（匹配 `:focus-visible`）与通用 clickable Mixin 组成；配色由组件通过clickable的focusColor明确提供，独立颜色各自声明。line 表示轮廓颜色用途，焦点仍是 State Condition，因此普通背景和内容色不会为了轮廓反馈而改变自身颜色。

内容完成编译后仍可保持对象形态，到最终输出阶段才通过 `toCSSString` 得到文本。循环引用终止编译；共享但无环的内容可以重复消费。`onActive` 提供的依赖只参与本次编译，不写回源账本。函数定义的局部 Variable 与 result 保持在同一份定义中，避免同名函数的后定义覆盖前定义。
