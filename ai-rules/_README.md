# 规则目录

## 用途

这个目录存放写给 AI 的仓库规则。

`_README.md` 是目录入口。模型先读这份文件时，应能快速知道每份规则的主题、用途和深入阅读入口。

## 顶层文件

以下划线开头的文件是目录级入口或写作规范：

- `_README.md`：目录总览，说明每份规则文件的主题。
- `_how-to-write-rule.md`：规则写法规范，说明 `ai-rules` 里的文档应该如何保持可读、稳定、低噪音。

普通主题规则文件不使用前置下划线。

## 规则索引

- `component.md`：定义 SolidJS 组件、组件内本地能力、外部函数之间的边界。重点是组件只接收 `props`，本地创建能力使用 `create*`，只有使用已有上下文时才使用 `use*`。
- `condition.md`：定义条件语句写法。重点是可读性优先、显式枚举少量模式、不可达分支可作为阅读结构收尾，但不能作为防御性兜底。
- `css.md`：定义 CSS 写法和基础样式抽取规则。重点是现代 CSS、嵌套结构、流式响应式、基础层与业务层分工，以及组件样式归属。
- `class-name.md`：定义 class name 与特殊 class 绑定规则。重点是完整语义单元、上下文继承、状态类 `--state`、typed value binding 和基础后缀兼容绑定。
- `file-name.md`：定义文件名怎么起。重点是文件名必须可想象，不重复目录上下文，不用过度抽象词偷懒。
- `function.md`：定义函数抽取规则。重点是什么逻辑适合抽成函数、函数和文件的边界、hook 本质仍是函数抽取、style 可以抽成局部函数但不等于新建文件。
- `solid-state.md`：定义 Solid 动态状态写法。重点是业务代码统一使用 `createState()`，通过 `$()` 读取，只通过 setter 写入，并明确默认是 signal，只有显式 `{ mode: 'store' }` 才创建 store。
- `types.md`：定义 TypeScript 类型规则。重点是类型归属、`types.ts` 使用边界、`import type`、联合类型和 overload 的使用边界。
- `_how-to-write-rule.md`：定义规则文档自身怎么写。重点是标题稳定、边界明确、示例克制、表达顺畅。

## 目录基线

这个仓库当前按 SolidJS 前端项目处理。

默认只考虑最新浏览器规则，不为旧浏览器、旧渲染心智、旧 JS 运行时或旧 CSS 规范保留降级写法。

如果后续新增规则文件，先判断是不是已有主题下的补充。

- 只是补充组件写法，改 `component.md`。
- 只是补充 `if`、`else if`、`else` 条件表达规则，改 `condition.md`。
- 只是补充样式写法，改 `css.md`。
- 只是补充 class 命名或绑定，改 `class-name.md`。
- 只是补充函数抽取规则，改 `function.md`。
- 只是补充类型归属、联合类型或 overload 规则，改 `types.md`。
- 确实是新主题，再新增文件。

规则文件数量越少，AI 越不容易在相近文档之间选错入口。
